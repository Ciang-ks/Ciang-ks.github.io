    第 12 讲 · 二叉堆与优先队列¶

    阅读起点：第 11 讲：树高与孩子；第 2 讲：数组。

    首读范围：先用 heapq 和最小堆；线性建堆证明第二遍读。

    操作系统要调度进程：每个进程有优先级，每次挑最高优先级的来跑，同时随时可能有新进程加入。

    无序数组取最大要扫描 \(\mathcal{O}(n)\)；平衡树也能做优先队列。若只需频繁取极值，不需范围、前驱等完整顺序功能，可用结构更简单的堆。两者有同阶更新界，实际速度取决于实现。

    堆的取舍就在这里：它只保证"父节点不小于（或不大于）子节点"这个局部约束，于是根总是极值，而维护成本只有 \(\mathcal{O}(\log n)\)。

    用数组表示完全二叉树¶

    完全二叉树是逐层从左向右填满，最后一层可以不满但中间不能留洞。例如7个位置按层编号：根0，下一层1、2，再下一层3、4、5、6。这样数组前n个槽正好存全部节点。

    节点 i 的左孩子下标 \(2i+1\)、右孩子 \(2i+2\)，但只有下标<n时孩子才存在；根没有父节点，其余节点父下标为 (i-1)//2。第 h 层最多\(2^h\)个位置，填到高度h需要约\(2^h\)个节点，故完全树高度 \(\mathcal{O}(\log n)\)。

    本讲用最小堆：每个父值不大于其孩子值。根到任意节点的一条路径上，值只能不变或增大，所以根不大于所有元素。左右兄弟没有排序要求，整个数组也不一定升序；图里的 [2,5,3,8,7,6,4] 就是最小堆。

    数组省去节点指针；它的优势是结构紧凑，而不是保证所有实践场景都快于平衡树。

    先用标准库体验优先队列¶

    先准备数值 5、2、7，再加入 1，观察能否按从小到大取出。Python 的 heapq 接收一个普通列表：heapify 将已有列表调整成堆，heappush 插入，heappop 返回并删除最小值；只想查看最小值则读 heap[0]。

    import heapq
heap = [5, 2, 7]
heapq.heapify(heap)              # 原地调整成最小堆
heapq.heappush(heap, 1)          # 加入一个元素
print(heap[0])                  # 1：看最小值，不删除
print(heapq.heappop(heap))      # 1：取出并删除最小值
print(heapq.heappop(heap))      # 2

    heapq 操作的是普通列表，但会维护堆关系，不能再随意改某个位置的值。看堆顶与弹出都要求堆非空。下面再手写修复过程，解释这些操作为什么只需沿一条路径移动。

    两个局部修复¶

    插入时把新元素放到数组末尾，然后让它向上冒；删除最小值时把最后一个元素挪到根，然后让它向下沉。两条修复路径最多为树高，所以修复过程最坏 \(\mathcal{O}(\log n)\)。底层 Python 列表还可能扩缩容；把第 2 讲的数组成本计入后，这里插入、弹出的整体操作按摊销 \(\mathcal{O}(\log (n+1))\) 分析。

    class MinHeap:
    def __init__(self):
        self.data = []

    def _sift_up(self, i):
        while i > 0:
            p = (i - 1) // 2
            if self.data[i] < self.data[p]:
                self.data[i], self.data[p] = self.data[p], self.data[i]
                i = p
            else:
                break

    def _sift_down(self, i):
        n = len(self.data)
        while True:
            smallest = i
            for child in (2 * i + 1, 2 * i + 2):
                if child < n and self.data[child] < self.data[smallest]:
                    smallest = child
            if smallest == i:
                break
            self.data[i], self.data[smallest] = self.data[smallest], self.data[i]
            i = smallest

    def insert(self, x):
        self.data.append(x)
        self._sift_up(len(self.data) - 1)

    def extract_min(self):
        if not self.data:
            raise IndexError('heap is empty')
        top = self.data[0]
        last = self.data.pop()
        if self.data:
            self.data[0] = last
            self._sift_down(0)
        return top

    为什么这两段是对的？_sift_up 里除"新元素与其父"之外的所有父子关系都没被改动；每次交换修好一个违反点并把新的违反点向上移一层。_sift_down 同理，只是每次和较小的那个孩子交换，从而不影响另一棵子树。

    先用图中数组手推：插入1，放在下标7，与父下标3的8换，再与下标1的5换，再与根2换，变成 [1,2,3,5,7,6,4,8]。弹出最小值1，用末尾8顶根；8与较小孩子2换，再与较小孩子5换，得到 [2,5,3,8,7,6,4]。

    若下沉时随便挑孩子，比如根8的左右孩子为5、3，却先与5换，根5仍比另一孩子3大，堆性质就没有修好。“挑较小孩子”是正确性要求。

    建堆：一个 \(\mathcal{O}(n)\) 的漂亮结论¶

    把整个数组当成完全二叉树，从最后一个非叶节点开始，依次向前对每个节点做一次下沉：

    这里另写一份接收列表 A 的独立 sift_down，供建堆与堆排序复用；它不依赖前面 MinHeap 对象中的 self.data。参数中的 \(*\) 规定 largest 只能按名字传入，例如 largest=True，不能把 True 当第四个位置参数。默认 False 表示修最小堆，True 表示修最大堆。

    def sift_down(A, i, end, *, largest=False):
    # 活动堆为 A[0:end]；默认最小堆，largest=True 时为最大堆。
    while 2 * i + 1 < end:
        child = 2 * i + 1
        right = child + 1
        if right < end and ((A[right] > A[child]) if largest else (A[right] < A[child])):
            child = right
        if not ((A[child] > A[i]) if largest else (A[child] < A[i])):
            break
        A[i], A[child] = A[child], A[i]
        i = child

def build_heap(A):
    for i in range(len(A) // 2 - 1, -1, -1):
        sift_down(A, i, len(A))
    return A

    从后往前的原因是：修复节点 i 时，它的孩子下标更大，孩子所带的子树已经修好。叶子没有孩子，本来就是堆。

    你可能会想："有 n/2 次下沉，每次最多 log n 层，那不是 \(\mathcal{O}(n \log n)\) 吗？"——这个界太松了。

    下沉代价取决于这个节点还能往下走几层。对 15 个节点：8 个叶子不用下沉，4 个最多 1 层，2 个最多 2 层，1 个最多 3 层，总层数至多 \(4+2\times 2+1\times 3=11\)，远小于“15 个都走 3 层”。

    一般地，能下沉至少 k 层的节点最多 \(\lfloor n/2^k\rfloor\) 个。把每层移动各计一次，总层数不超过 \(n/2+n/4+n/8+\cdots <n\)，每层比较与交换为常数次，所以总计 \(\mathcal{O}(n)\)。逐个插入的最坏总成本则为 \(\mathcal{O}(n \log n)\)。

    堆排序¶

    建最大堆，然后反复把堆顶（最大值）与末尾交换、再对缩小的堆做一次下沉：

    def heapsort(A):
    n = len(A)
    for i in range(n // 2 - 1, -1, -1):     # 建最大堆，O(n)
        sift_down(A, i, n, largest=True)
    for end in range(n - 1, 0, -1):         # 反复取最大值放到末尾
        A[0], A[end] = A[end], A[0]
        sift_down(A, 0, end, largest=True)
    return A

    \(\mathcal{O}(n \log n)\)，最坏情况也是（不像快速排序会退化），而且额外空间 \(\mathcal{O}(1)\)。它不稳定：交换根与末尾时，相等元素的原始顺序可能改变。选择排序算法时还要考虑稳定性、额外空间与具体实现。

    两个经典用法¶

    多路归并的输入是 k 个各自升序的序列，输出把全部元素合在一起的升序序列，保留重复值。例如 [[1,4],[2,3],[]] 应返回 [1,2,3,4]。第 7 讲合并两路只要比较两个头部；现在有 k 个头部，每次线性扫描它们会多花 \(\mathcal{O}(k)\)。用最小堆保存每一路尚未输出的第一个元素，就能迅速选出下一个值，并只从它所属的那一路补入后继。

    import heapq
def merge_k_sorted(lists):
    heap = []
    for i, lst in enumerate(lists):
        if len(lst) > 0:
            heap.append((lst[0], i, 0))  # 值、序列编号、序列内下标
    heapq.heapify(heap)
    out = []
    while heap:
        val, i, j = heapq.heappop(heap)
        out.append(val)
        if j + 1 < len(lists[i]):
            heapq.heappush(heap, (lists[i][j + 1], i, j + 1))
    return out

    多路归并的堆项 (值,序列编号,序列内下标) 既记录候选值，也记录“弹出后该从哪里补一个”。Python 按元组从左往右比较，先比值；值相等再比编号。堆中每个非空序列恰有一个候选，最小候选就是全体尚未输出元素的最小值。总元素数 N、序列数 k，时间 \(\mathcal{O}(k+N \log (k+1))\)，堆空间 \(\mathcal{O}(k)\)，输出 \(\mathcal{O}(N)\)。

    求流式中位数：数值陆续到来，add_num(x) 接收一个数，find_median() 返回目前所有数的中位数。奇数个时取升序中间那个；偶数个时取中间两数的平均，例如先加入 2，查询得 2；再加入 1，查询得 1.5。约定至少加入一个数后才查询。

    每次把全部数重新排序会重复很多工作。我们只需要知道较小一半的最大值和较大一半的最小值，因此用两个堆分别保存这两半。下面用取负数的最小堆模拟最大堆；例如原值 2、5 变成 -2、-5，弹出最小的 -5 就相当于取出原来的最大值 5。

    class MedianFinder:
    def __init__(self):
        self.small, self.large = [], []      # small 存负数当大顶堆

    def add_num(self, num):
        heapq.heappush(self.small, -num)
        heapq.heappush(self.large, -heapq.heappop(self.small))
        if len(self.large) > len(self.small):
            heapq.heappush(self.small, -heapq.heappop(self.large))

    def find_median(self):
        if len(self.small) > len(self.large):
            return -self.small[0]
        return (-self.small[0] + self.large[0]) / 2

    双堆先维持两项保证：small 保存较小一半，large 保存较大一半；small 的个数等于 large 或多1。Python小顶堆取负数后，原来的最大值反而对应最小负数，所以 -small[0] 是较小一半的最大值。

    插入2、1、5后，两组真实值依次为“小半 [2]、大半空”，“小半 [1]、大半 [2]”，“小半 [1,2]、大半 [5]”（此处只列成员，不是堆数组的内部排列），中位数依次2、1.5、2。代码先把新值放小半，再把小半最大值移往大半，最后按数量必要时移回；第一步可能打乱分组，第二步修顺序，第三步修数量。每次常数次堆操作 \(\mathcal{O}(\log n)\)，查询看堆顶 \(\mathcal{O}(1)\)。

    这份写法的三步要一起理解，它们共同保证"small 的所有元素不大于 large 的所有元素"。

    该不该用堆¶

    需求 常用方案（不声称每种规模都最优）
    静态数组求第 k 大（只要一个值） 快速选择，期望 \(\mathcal{O}(n)\)
    静态数组求前 k 大 小顶堆，\(\mathcal{O}(n \log (k+1))\)
    动态数据求 Top-K 小顶堆，\(\mathcal{O}(\log k)\) 每次
    动态数据求中位数 双堆，\(\mathcal{O}(\log n)\) 每次
    k 路归并 堆，\(\mathcal{O}(N \log k)\)

    判断依据是是否反复“加入并取当前极值”。动态范围查询可能更适合平衡树；静态多路归并也适合堆，不能仅按数据会不会变决定。

    从讲义走到代码¶

    事件模拟不断加入新事件、每次取最早发生的一项，适合优先队列。

    先用 heapq 加入 5、2、7，再连续弹出，检查得到 2、5、7。自己写 _sift_down 时，每步都比较两个孩子，选更小者交换。

    再做 Kth Largest Element in a Stream：每次加入一个数后，返回目前第 k 大的值，重复值也占名次。例如 k=3、初始 [4,5,8,2]，堆中应保留 4、5、8；加入 3 返回 4，再加入 10 返回 5。堆顶是当前第 3 大，因为比它小的候选都已淘汰。

    练习¶

    1. 用无序数组实现优先队列，insert 和 extract_min 各是多少？有序数组呢？堆凭什么把两者都做到 \(\mathcal{O}(\log n)\)？

    无序数组：insert \(\mathcal{O}(1)\)、extract_min \(\Theta (n)\)；有序数组反过来。堆的诀窍是只维护部分顺序——局部约束就足以让极值浮到根上，维护成本降到 \(\mathcal{O}(\log n)\)。

    2. 用 15 个节点验证从底向上建堆的工作量，并说明为什么不能把每个节点都计为 log n。

    8 个叶子无需下沉，4 个节点最多 1 层，2 个最多 2 层，根最多 3 层。正文把这一观察推广成 \(n/2+n/4+\cdots <n\)。完全二叉树的相同深度节点未必高度都相同，不能把“节点高度”与“所在层”直接等同。

    3.（学完第 18 讲再做） Dijkstra 需要优先队列的哪些操作？它需要 decrease_key 吗？标准二叉堆不支持怎么办？

    需要 extract_min 和"把某个键的距离改小"。本讲的基础堆接口与 heapq 没有提供按节点定位的 decrease_key；若额外维护“节点→堆下标”，也能在 \(\mathcal{O}(\log n)\) 内减小一个键，绕过办法是惰性删除：直接把新的 (距离, 节点) 压进堆，弹出时如果该记录已过期就跳过。代价是堆里可能有重复记录，复杂度仍是 \(\mathcal{O}((V+E) \log V)\)。这正是第 18 讲 Dijkstra 代码里那行 if d > dist[u]: continue 的来历。

    4. 实现 KthLargest：数据流中反复查询第 k 大。

    要求k不小于1，且查询时累计已见元素至少k个。维护至多k个元素的最小堆：不足k个时暂存全部，达到后保留当前最大的k个，堆顶才是第k大：

    class KthLargest:
    def __init__(self, k, nums):
        self.k, self.heap = k, list(nums)  # 不修改调用者的列表
        heapq.heapify(self.heap)
        while len(self.heap) > k:
            heapq.heappop(self.heap)

    def add(self, val):
        heapq.heappush(self.heap, val)
        if len(self.heap) > self.k:
            heapq.heappop(self.heap)        # 弹掉当前最小的
        return self.heap[0]

    为什么必须是小顶堆？因为要淘汰的是"这 k+1 个里最小的那个"，而小顶堆的堆顶正好是它。
