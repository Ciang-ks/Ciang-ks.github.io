    第 9 讲 · 线性时间排序¶

    阅读起点：第 2 讲：前缀和；第 3、8 讲：字典与期望；第 7 讲：稳定性。

    首读范围：先做月份分桶、计数排序；决策树下界选读。

    第 7 讲归并排序最坏 Θ(n log n)，第 8 讲对互异元素的随机快速排序期望 Θ(n log n)。一个自然的问题是：能不能更快？

    答案分两半，很耐人寻味：如果只允许"比较两个元素的大小"，不能，有 Ω(n log n) 的下界；但如果元素的键有额外结构（比如"是 1 到 12 之间的整数"），能，因为那时可以不用比较。

    从一个特别朴素的场景说起¶

    先看一个特别朴素的场景：把 n 个学生按出生月份排序，月份只有 12 种取值，同月份内部顺序随便。

    用归并排序是 Θ(n log n)，但这里的信息被浪费了——键的取值范围只有 12 个，为什么还要做 n log n 次比较？开 13 个桶，让下标 1..12 直接对应月份，第 0 桶空着：

    def sort_by_month(students):        # students: [(name, month)]
    buckets = [[] for _ in range(13)]
    for name, m in students:
        buckets[m].append((name, m))
    out = []
    for m in range(1, 13):
        out.extend(buckets[m])
    return out

    Θ(n + 13) = Θ(n)。这就是"用空间换取低于比较下界"的思路。

    计数排序¶

    更一般的版本是：键是 [0, k] 内的整数（两端都包含，故分配 k+1 个槽），可以先统计每个键出现多少次，再算出每个键在输出中的位置。

    def counting_sort(A, k):
    count = [0] * (k + 1)
    for x in A:
        count[x] += 1
    for i in range(1, k + 1):
        count[i] += count[i - 1]        # 前缀和：count[v] = "<= v 的元素个数"
    out = [0] * len(A)
    for x in reversed(A):               # 从后往前扫描
        count[x] -= 1
        out[count[x]] = x
    return out

    这里返回新的升序列表，不修改 A。先计数要 O(n)，累计 k+1 个计数要 O(k)，按原数组回填要 O(n)，所以时间为 Θ(n+k)，额外空间为 O(n+k)。最后一遍的扫描方向还使它保持稳定性。

    先把“个数”变成“下标”：若恰有 3 个数≤2，那么值为 2 的最后一个位置最多是下标 2，而不是 3。因此先把 count[2] 减 1，再写到那个下标。再遇到一个 2 时继续减，就填到前一格。

    reversed(A) 表示按原列表从后往前遍历，不修改 A。第三步为什么要从后往前？ count[x] 表示"≤ x 的元素个数"，也就是 x 该放的位置区间的末尾。从后往前扫时，后出现的相同键会被放到更靠后的位置，保持了输入顺序——这就是稳定性。

    再看一个会丢失重复元素的坏例子（它不只是“不稳定”，而是连元素都没保全）：如果直接用"键当数组下标"（所谓直接访问数组排序），重复的键会互相覆盖，根本排不了有重复元素的数组。计数排序多出的那一步"统计每个键有多少个"，正是为了把重复键连续地放在一段区间里。

    稳定性为什么值钱¶

    因为有了它，基数排序才可能出现。

    例如对 [21,12,11] 排序，先按个位稳定排序得到 [21,11,12]；再按十位稳定排序，把十位为 1 的两个数按原先的次序取出，得到 [11,12,21]。第二轮保留了“十位相同就比较个位”的结果，才得到整个数的升序。

    这就是基数排序：把整数看成若干位，从最低位到最高位依次做稳定排序。代码中的 d 从 0 开始，d=0 是个位；(x // 10**d) % 10 先去掉更低位，再取出当前位。例如 x=234、d=1，得到 3。

    下面假设非负整数，且每个数小于 base**digits；digits 不够会漏掉高位。用稳定分桶补全子程序：

    def counting_sort_by_digit(A, d, base):
    buckets = [[] for _ in range(base)]
    place = base ** d
    for x in A:
        buckets[(x // place) % base].append(x)
    out = []
    for bucket in buckets:
        out.extend(bucket)
    return out

def radix_sort(A, digits=10, base=10):
    for d in range(digits):
        A = counting_sort_by_digit(A, d, base)
    return A

    这个“全数组逐位稳定排序”的版本为什么从低位到高位？ 因为后面一轮会覆盖前面一轮的顺序，但稳定性保证了"同一高位分组内部，仍然按低位有序"。若仍每轮对整个数组排序，先排高位后排低位会破坏优先级；也存在先按高位分桶、再各桶递归的MSD基数排序，那是另一套算法。

    形式化地说，记 P(t) 为"数组按最低 t 位有序"。P(1) 由第一轮直接得到。做第 t+1 轮时，若两个元素截取最低 t+1 位后 x < y：第 t+1 位不同时靠这一轮排定；第 t+1 位相同时，比较取决于更低的 t 位，而由 P(t) 它们已经有序，又因为本轮排序稳定，这个顺序被保留。所以 P(t+1) 成立。∎

    注意证明里"稳定"起的作用：没有它，第二种情况就失去保证。这解释了为什么基数排序必须用稳定排序做子过程。

    复杂度：每轮计数排序 Θ(n + base)，共 digits 轮，Θ(digits × (n + base))。

    图中是十位这一轮：上排 [50,21,101,1,13,234,345] 已按个位排好。按十位稳定分桶后得到 [101,1,13,21,234,345,50]。十位相同的 101 与 1 保持原先次序。下方表格另用 [170,45,75,90,802,24,2,66] 演示完整三轮。

    桶排序¶

    当键是 [0, 1) 上近似均匀分布的实数时，可以切成 n 个等长的桶，桶内再排序（本例调用 Python sorted；若改插入排序，偏斜分布下最坏可达 Θ(n²)）：

    def bucket_sort(A):
    n = len(A)
    buckets = [[] for _ in range(n)]
    for x in A:
        buckets[int(x * n)].append(x)
    out = []
    for b in buckets:
        out.extend(sorted(b))
    return out

    每桶的平均元素数是 1，但仅凭平均数还不能推出平均排序成本。设某桶大小为 X，独立均匀分桶时 E[X]=1、E[X²]=2−1/n；而 sorted 的 O(X log(X+1)) 成本可用 O(1+X²) 界定，所以每桶期望 O(1)，n 个桶合计期望 Θ(n)。这项分析依赖独立均匀分布，第一遍只需记住适用条件。但如果分布严重偏斜（所有元素挤进一个桶），它会退化成 Θ(n log n)。 这一点和快速排序需要随机化形成了有趣的对照。

    走一遍基数排序：A = [170, 45, 75, 90, 802, 24, 2, 66]

    轮次 按哪位 结果
    1 个位 [170, 90, 802, 2, 24, 45, 75, 66]
    2 十位 [802, 2, 24, 45, 66, 170, 75, 90]
    3 百位 [2, 24, 45, 66, 75, 90, 170, 802]

    比较排序的下界¶

    任何只用"比较两个元素"来决定顺序的排序算法，最坏情况下至少需要 Ω(n log n) 次比较。

    证明用的是决策树。把算法的执行过程画成一棵二叉树，每个内部节点是一次比较、两个分支对应两种结果，每个叶子上挂着一种输出排列。要正确排序，不同的输入排列必须落到不同的叶子。

    这里用 n 个互异且带身份的元素来证明最坏下界。n! 读作 n 的阶乘，即 n×(n−1)×…×1。算法虽会把数排成升序，但不同输入次序所需的身份排列不同，所以必须有足够多的叶子区分它们。

    n 个元素有 n! 种排列，所以叶子至少 n! 个；深度为 d 的二叉树最多 2^d 个叶子，于是 2^d ≥ n!。取对数并估计 n!≥(n/2)^(n/2)（后半段各因子≥n/2），因此log₂(n!)≥(n/2)log₂(n/2)；同时n!≤n^n，得到log₂(n!)=Θ(n log n)，得 d = Ω(n log n)。∎

    这个下界只约束比较排序。 计数排序、基数排序使用整数数位来定位桶，不只靠两两比较。桶排序也会在桶内比较，但利用分布假设降低期望成本；它没有突破任意输入下的比较排序最坏下界。"要不要比较"是算法设计里一条根本的分界线。

    从讲义走到代码¶

    状态码或月份的取值范围很小时，按值分桶能省去两两比较。

    先写 counting_sort([2,1,2],2)，得到 [1,2,2]，记录计数 [0,1,2] 如何变成累计计数 [0,1,3]。再做 Top K Frequent Elements：先用字典数频率，再把同频率的值放在同一桶。

    对 [1,1,1,2,2,3]、k=2，计数为 {1:3,2:2,3:1}，从频率 n 向 1 扫，取出 1、2 即可。频率桶最多 n+1 个，即使原数值很大也不受影响。

    练习¶

    1. 对"按月份排序"，如果还要求同月份内部按名字字典序排，上面那个做法要怎么改？复杂度呢？

    先按名字排一遍（Θ(n log n)），再做一次稳定的按月份分桶。总复杂度由第一步主导。这个"先按次要键排、再按主要键稳定排"的套路就是基数排序的思路。

    2. 如果月份不是 1..12 而是任意字符串，还能做到 Θ(n) 吗？

    不能无条件做到——键的取值范围不再有界，计数数组开不出来。但如果是固定长度的短字符串，可以逐字符做基数排序，Θ(d(n + σ))，d 是字符数，σ 是字符集大小；小写 σ 在这里表示一个数量，与求和符号 Σ 不同。这又一次说明"线性时间排序需要额外结构假设"。

    3. 学生记录为 (姓名,月份)，要求先按月份、同月再按姓名排。为什么只按月份排序还不够？

    单键排序只保证月份有序，同月记录可能仍按原输入顺序。可以先按姓名排序，再稳定地按月份排序；也可以给排序提供一个取比较字段的函数：

    def student_key(student):
    return (student[1], student[0])   # 先月份、再姓名

students = [('小周', 3), ('小林', 3), ('小陈', 1)]
ordered = sorted(students, key=student_key)

    key= 指定拿哪个字段比较，sorted 返回新列表，不改变 students；元组从左往右比较，第一项相同才比较第二项。lambda student: (student[1],student[0]) 是上面这个只含一个 return 的函数的简写，后面会用同样写法选区间的结束时间。逐维稳定排序是一种多键排序方法，并非唯一做法；它的重要性在于能把有限值域的每一位都交给线性时间子程序处理。

    4. 计数排序必须事先知道键的范围 k。如果不知道呢？

    先扫一遍取最大值（Θ(n)），非负整数时把它作为k；总成本仍为O(n+k)，但k可能极大而不实用。负数可先用最小值平移，再看整个值域宽度。也可用基数排序，但要从最大值的位数确定 digits，或不断处理到所有高位都为 0；不能固定处理不足的位数。

    5. 实现 top_k_frequent(nums, k)，要求 O(n)。

    先用普通字典 freq={} 计数，对每个 x 更新 freq[x]=freq.get(x,0)+1（期望 O(n)），再按频率分桶——桶的下标是频率，范围是 1..n。从高频往低频取 k 个。这题提醒我们：桶排序的关键不是"数字"，而是"找到一个值域有限且小的量"。
