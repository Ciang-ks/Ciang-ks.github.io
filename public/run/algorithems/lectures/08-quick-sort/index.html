    第 8 讲 · 快速排序与随机化¶

    阅读起点：第 7 讲：递归与分治；第 3 讲：期望；本讲引入指示变量与期望的线性性。

    首读范围：先看 partition 的四段区间；概率求和第二遍读。

    归并排序的做法是"先切两半、排好、再合并"。能不能换个思路：先随便挑一个元素当标杆，把比它小的都放左边、比它大的都放右边？这样标杆自动到了最终位置，剩下的两边递归处理就好。

    这就是快速排序。它在原数组上交换元素，不需要额外的合并数组；递归调用本身仍占空间。但它有一个致命弱点：标杆选得不好会退化成 Θ(n²)。这一讲的一大半篇幅都在处理这件事，而解决它的工具（随机化与期望分析）比快速排序本身更重要。

    划分¶

    先实现一次划分，再调用它完成排序。partition(A,lo,hi) 处理闭区间 A[lo..hi]，本次选最右边的 A[hi] 作标杆 pivot；函数会修改这段数组，并返回标杆最终所在下标。它只保证左边小于标杆、右边不小于标杆，不保证两边内部已经排好。例如对 [3,1,2] 以 2 为标杆，得到 [1,2,3] 是碰巧两边各只有一个元素；较长区间还要递归排序。

    def partition(A, lo, hi):
    pivot = A[hi]
    i = lo                            # i 指向"小于区"的下一个空位
    for j in range(lo, hi):
        if A[j] < pivot:
            A[i], A[j] = A[j], A[i]
            i += 1
    A[i], A[hi] = A[hi], A[i]         # 把标杆放到正确位置
    return i

    理解这段代码只需要看循环不变式：

    在每轮 j 开始时：
  A[lo..i-1] 全部 < pivot
  A[i..j-1]  全部 >= pivot
  A[j..hi-1] 尚未处理
  A[hi]      = pivot

    循环结束时 A[lo..i-1] < pivot ≤ A[i..hi-1]，再把标杆换到位置 i，就得到"左边全部更小、右边全部不小于它"的格局——标杆从此不会再动，它已经在最终位置上了。

    图严格采用本代码的定义：i 是“小于区的下一个空位”，初始 i=lo；命中 A[j]<pivot 后先交换 A[i] 与 A[j]，再让 i 加1；最后交换 A[i] 与 pivot。另一种把 i 定义成“小于区末尾”的模板会用 i+1，但本讲不能混用。

    随机选标杆，避免固定规则总遇到坏划分¶

    有了 partition，完整排序就能分成三步：选一个标杆并移到末尾，划分这段数组，再分别排序标杆左右两侧。长度为 0 或 1 时直接结束。本实现用 random.randint(lo,hi) 等概率选取闭区间内的一个下标，并原地修改 A；调用 quicksort(A) 就会处理整个数组。

    import random

def quicksort(A, lo=0, hi=None):
    if hi is None:
        hi = len(A) - 1
    if lo >= hi:
        return A
    r = random.randint(lo, hi)             # 关键：随机选标杆
    A[r], A[hi] = A[hi], A[r]
    p = partition(A, lo, hi)
    quicksort(A, lo, p - 1)
    quicksort(A, p + 1, hi)
    return A

    如果固定选末尾元素当标杆，输入 [1,2,3,4,5] 时每次划分都得到"左边 n−1 个、右边 0 个"，递归深度变成 n，总代价 Θ(n²)。而"已排序的输入"恰恰是非常常见的情况。

    对元素互异的输入，这份随机二路划分实现的期望时间为 Θ(n log n)。重复值很多时，须使用后文的三路划分；全相等输入在二路版中仍是 Θ(n²)。 这里固定一份满足元素互异条件的输入，只让每次标杆选择随机变化；期望是对这些算法内部的随机选择取的。这个区别是随机化算法最值得玩味的地方。

    期望分析：指示变量与线性性¶

    要分析它的期望运行时间，得先用上两个工具，先把它们摆出来。

    先从抛硬币理解期望：一次公平硬币取正面为 1、反面为 0，期望是 1×1/2+0×1/2=1/2。期望是按概率加权的平均值，不一定是某次运行真的取到的值。下面的 Pr[E] 表示事件 E 的概率，E[X] 表示变量 X 的期望；Σ 表示把所有指定项相加。这部分可在掌握划分代码后再读。

    指示变量：把"某事件是否发生"编码成 0/1 随机变量 X_E，那么 E[X_E] = Pr[E]。

    期望的线性性：对任意随机变量（不要求独立），E[X₁ + ⋯ + X_k] = E[X₁] + ⋯ + E[X_k]。

    为什么可以先分别求期望再相加？把所有随机结果列出时，“先把这次结果里的工作量相加，再按概率平均”，与“每部分先按概率平均，最后相加”只是分配律交换了求和顺序。两部分是否一起变大，不影响这个等式。

    两条合起来，就能把总比较次数拆成逐对发生比较的概率，无需先求出整棵随机递归树的分布。

    现在分析快速排序的比较次数。设排序后的元素依次是 z₁ < z₂ < ⋯ < zₙ，定义 X_ij 表示"zᵢ 与 z_j 是否被比较过"。总比较次数 X = Σ_{i<j} X_ij，由线性性

    E[X] = Σ_{i<j} Pr[zᵢ 与 z_j 被比较]

    关键引理：Pr[zᵢ 与 z_j 被比较] = 2 / (j − i + 1)。

    考虑集合 {zᵢ, …, z_j}，共 j − i + 1 个元素。在"这个集合里第一次有元素被选为标杆"之前，zᵢ 和 z_j 一定还在同一个待处理区间里。此时：

    • 若选中的标杆是 zᵢ 或 z_j，它们就会被比较（划分时标杆要和区间内所有元素比）；
    • 若选中的是中间的某个 z_k（i < k < j），zᵢ 和 z_j 会被分到左右两侧，从此再也不会比较。

    标杆是从这 j − i + 1 个元素里均匀随机选的，两个"会触发比较"的选择在总共 j−i+1 个等可能选择中占 2 个，所以概率是 2/(j−i+1)。

    代回求和：

    E[X] = Σ_{i=1}^{n-1} Σ_{j=i+1}^{n} 2/(j−i+1) ≤ Σ_{i=1}^{n} Σ_{k=1}^{n} 2/k
     = 2n·H_n = O(n log n)

    H_n = 1 + 1/2 + ⋯ + 1/n 是调和数。按下标分组：第 2 项、第 3～4 项、第 5～8 项……每组的和至多 1，分组数为 O(log n)，所以 H_n=O(log n)。上式先得到上界；反过来，只取间隔 j−i≤n/2 的那些项，就有至少 n/2 个起点各累加一个 Θ(log n) 的调和和，得到 Ω(n log n) 下界。所以期望比较次数是 Θ(n log n)，而且这个结论不依赖输入分布。

    快速选择¶

    快速排序的直接推广：题目要第 k 小的值时，先换算为升序下标 index=k−1；要第 k 大时则是 index=len(A)−k。划分后比较标杆位置 p 与 index，只保留含这个位置的一侧。以下参数 index 始终表示从 0 开始的目标下标，不能直接传入从 1 开始的名次 k。

    def quickselect(A, index, lo=0, hi=None):
    if hi is None:
        hi = len(A) - 1
    while lo <= hi:
        r = random.randint(lo, hi)
        A[r], A[hi] = A[hi], A[r]
        p = partition(A, lo, hi)
        if p == index:
            return A[p]
        elif p < index:
            lo = p + 1
        else:
            hi = p - 1
    return None

    只递归一侧不等于每轮都平分。 若标杆每次都最差，仍有 n+(n−1)+…+1=Θ(n²)。元素互异、标杆均匀随机时，期望才是 O(n)，第 10 讲会把“等到一次足够好的划分要付多少账”讲清楚。代码中的 index 为从 0 开始的升序位置，需保证 0≤index<len(A)，并且会修改 A。

    大量重复元素怎么办¶

    数组里有大量相等元素时，partition 会把它们全堆到一侧，性能退化。三路划分把数组分成 < pivot、= pivot、> pivot 三段，等于标杆的元素一次全部就位：

    def quicksort_3way(A, lo, hi):
    if lo >= hi:
        return A
    pivot = A[random.randint(lo, hi)]
    lt, i, gt = lo, lo, hi      # [lo,lt) < p, [lt,i) == p, (gt,hi] > p
    while i <= gt:
        if A[i] < pivot:
            A[lt], A[i] = A[i], A[lt]; lt += 1; i += 1
        elif A[i] > pivot:
            A[i], A[gt] = A[gt], A[i]; gt -= 1
        else:
            i += 1
    quicksort_3way(A, lo, lt - 1)
    quicksort_3way(A, gt + 1, hi)
    return A

    遇到 A[i]>pivot 时，只让 gt 左移，i 不能加 1：从右端换回来的数还没检查。例如 [5,1,3]、pivot=3，第一次交换把 3 换到 i=0，必须再检查它，才能正确归入等于区。调用完整数组时写 quicksort_3way(A,0,len(A)-1)。

    两种排序的取舍¶

    归并排序 快速排序
    主要工作在哪一步 先递归排两半，再归并 先按标杆划分，再递归排两侧
    稳定性 稳定 不稳定
    额外空间 Θ(n) Θ(log n)（期望）
    最坏时间 Θ(n log n) Θ(n²)
    适用取舍 要求稳定与最坏时间界时易分析 原地交换；性能依赖划分与实现

    期望 O(n log n) 与最坏 O(n log n) 是两种不同的保证：前者是"反复运行，长期平均"，后者是"任何输入任何随机选择都不超过"。工程上按需求选。

    从讲义走到代码¶

    分区能按阈值把元素分组，选择第 k 个元素只需保留其中一侧。

    先手写 partition，对 [7,2,8,3,5,1,4] 分区应返回 p=3，并得到 [2,3,1,4,5,8,7]。检查左侧都<4、右侧都≥4；两边内部不要求有序。

    再做 Kth Largest Element in an Array：输入数组与从 1 开始的名次 k，返回排序后倒数第 k 个数，重复值也占名次。把第 k 大转换为升序下标 n−k。用 [3,2,1,5,6,4]、k=2 检查返回 5；再试 [2,2,2] 的第 2 大，传 index=1：每次 partition 返回当前 lo，第一轮 p=0，下一轮 p=1 才命中。相同数值仍占不同名次；全相等且目标 index 靠右时，每轮只排除一个位置，会退化到平方量级。

    练习¶

    1. 设 X 以 1/100 的概率取 1、以 99/100 的概率取 0。(a) E[X]？(b) 取 n 个独立同分布的 Xᵢ，E[ΣXᵢ]？(c) 反复取到第一次出现 1，所需试验次数 N 的期望（第一次试验计为 1）？

    (a) 1/100。(b) 由线性性（不要求独立）得 n/100。(c) 几何分布，E[N] = 1/p = 100。严格推导是 E[N] = 1 + (1−p)E[N]。

    2. 下面这个"排序"算法，第 i 次 shuffle 后恰好有序的指示变量期望是多少？while 循环期望执行几次？

    def bogosort(A):
    while A != sorted(A):
        random.shuffle(A)
    return A

    一次随机排列恰好有序的概率是 1/n!，所以 E[Xᵢ] = 1/n!，若初始尚未有序且元素互异，期望 shuffle n! 次；若一开始有序则是 0 次。这就是 bogosort 只能出现在段子里的原因：n = 20 时 20! ≈ 2.4 × 10¹⁸。

    3. 为什么线性性里"不要求独立"这个条件这么重要？举一个"变量强相关但仍可用线性性"的例子。

    期望的线性性对任意随机变量都成立。例子：把 n 个球随机放进 n 个盒子，令 Xᵢ 表示"第 i 个盒子为空"，则 E[Xᵢ] = (1 − 1/n)ⁿ，空盒数的期望是 n(1−1/n)ⁿ ≈ n/e。这些 Xᵢ 高度相关（一个盒子空会略微影响另一个），但求和仍然成立。

    4. 如果标杆总是选到真中位数，快速排序多快？为什么实际不用它？

    每次都平分，T(n) = 2T(n/2) + Θ(n) = Θ(n log n)。但"找到真中位数"本身要花 O(n)（第 10 讲），虽然渐进一样，常数不如随机化。

    5. 随机化快速排序的最坏情况仍是 Θ(n²)，"期望 O(n log n)"到底保证了什么？

    对元素互异的随机划分，极端坏划分仍可能发生；期望界本身不等于任何特定的失败概率界。期望保证的是平均表现：反复运行，长期平均代价是 O(n log n)。
