    第 5 讲 · 双指针与滑动窗口¶

    阅读起点：第 2 讲：数组下标与前缀和；第 3 讲：字典与集合。

    首读范围：先掌握有序 Two Sum 与不重复子串；接雨水和 3Sum 选读。

    第 3 讲用字典加速寻找配对值。如果数组已经有序，或问题要求处理连续的一段，还可以用两个整数下标标记扫描位置，这就是本讲的“双指针”。它们的移动利用了某种只朝一个方向变化的关系，例如有序数组向右数值不会变小。每次移动都遵守一条规则：每次移动指针，都必须能说清"被我丢掉的那个候选，为什么不可能出现在答案里"。

    从有序数组里找一对数¶

    给定升序数组 A 和目标 t，找一对下标使两数之和为 t，要求只允许 \(\mathcal{O}(1)\) 额外空间。

    暴力枚举所有对是 \(\Theta (n^{2})\)，瓶颈很清楚：内层在"找一个特定的值"。通常我们会用哈希表把每次补数查询降到期望 \(\mathcal{O}(1)\)——但哈希表要 \(\Theta (n)\) 空间，违反了 \(\mathcal{O}(1)\) 的约束。

    关键在于题目多给了一个条件：数组是有序的。这个条件必须用上。

    让两个指针从两端出发：

    def two_sum_sorted(A, t):
    l, r = 0, len(A) - 1
    while l < r:
        s = A[l] + A[r]
        if s == t:
            return [l, r]
        elif s < t:
            l += 1          # 和太小，需要更大的数
        else:
            r -= 1          # 和太大，需要更小的数
    return []

    本函数返回从0开始的下标；LeetCode Two Sum II的题面要求从1开始，提交时要对两个结果各加1。这只是接口差别，移动与证明不变。

    凭什么可以这样移动？假设 \(A[l] + A[r] < t\)。因为数组升序，对任意 \(j \le r\) 都有 \(A[j] \le A[r]\)，所以 \(A[l] + A[j] \le A[l] + A[r] < t\)。也就是说 A[l] 和 l..r 里任何元素搭配都太小，而小于 l 的下标在之前的迭代里已经被同样的论证排除了。所以 A[l] 可以安全地永久丢弃。

    对称地，\(A[l] + A[r] > t\) 时 A[r] 可以丢弃。

    这就是双指针的证明模板：每一步都说明被丢掉的那个候选，它的所有可能搭配都不满足条件。 面试里把这句话说出来，比代码写得漂亮更有价值。

    三种形态¶

    对撞指针：两个指针从两端往中间走。前提是数组有序，或问题有"两端向中间收缩"的性质。

    快慢指针：一个负责扫描、一个负责写入。例如给定数组 A 和待删除值 val，要把所有不等于 val 的元素移到数组前部，保持原顺序，并返回保留下来的元素个数。允许修改 A，但不额外创建同样长的数组。这里两个“指针”就是两个整数下标：fast 逐个读取，slow 标出下一次写入的位置。

    def remove_element(A, val):
    slow = 0
    for fast in range(len(A)):
        if A[fast] != val:
            A[slow] = A[fast]
            slow += 1
    return slow          # slow 就是新长度

    slow 的语义是"下一个待写位置"——想清这一点，所有"原地删除/压缩"的题都是同一个模板。

    这个函数返回有效前缀的长度，不会真的缩短列表。例如 A=[3,2,2,3]、val=3，返回 2；只读取 A[:2]，它等于 [2,2]，后面残留值无需清理。fast 扫过的每个保留值恰好被写一次，时间 \(\mathcal{O}(n)\)、额外空间 \(\mathcal{O}(1)\)。

    分离指针：两个序列各一个，用于归并，第 7 讲会给出完整实现。

    三个“移动依据”的例子¶

    先区分两个容易混淆的水量问题。盛最多水的容器（Container With Most Water）给定非负高度数组 height，下标是横坐标，每个值是一条竖线的高度；选择两条线与横轴围成容器，返回最大面积。端点 l、r 围成的面积是 \((r-l)\min(\mathrm{height}[l],\mathrm{height}[r])\)。例如 [1,2,1] 选两端，面积为 2。

    接雨水（Trapping Rain Water）则把每个值看成宽度为 1 的柱子，问雨后所有柱子之间总共能积多少水。例如 [2,0,2] 中间能积 2 单位水。这里要逐格求水量并相加，不能只选两根柱子算一个容器。

    两题都能从两端向内扫描，但每次移动的理由不同：

    题目 移动规则 为什么安全
    Two Sum II 和偏小右移左指针 左指针与任何更小的右端搭配只会更小
    Container With Most Water 移动较矮的一边 移动高的一边时高度上限不变、宽度变小，面积只会更小
    Trapping Rain Water 比较已扫描的 left_max 与 right_max，处理较小一侧 需要的是两侧最高墙，而不是把容器题的当前柱高直接照搬

    第二个值得展开一句。设 \(\mathrm{height}[l] < \mathrm{height}[r]\)。考虑所有以 l 为左端点的容器：宽度最大就是当前的 \(r-l\)（右端点不能再右移），高度上限是 height[l]（min 被较矮的左线锁死）。所以当前这个已经是以 l 为左端点时的最优解，l 可以永久丢弃。

    对接雨水，某一格的水位受两侧最高柱子中较矮的那个限制；该格水量是这个水位减去自身高度，最低为 0。先设 l、r 之间尚未结算，left_max、right_max 分别记录两端已经扫描到的最高柱子。若 left_max<right_max，就向右读下一根左侧柱子：它比 left_max 低时，右侧已有更高柱子，水量可确定；它比 left_max 高时，这一格本身不能积水，只需更新左侧最高值。两种情况统一写成“移动 l、更新 left_max、累加 left_max-height[l]”。另一侧对称。

    def trap(height):
    if not height:
        return 0
    l, r = 0, len(height) - 1
    left_max, right_max = height[l], height[r]
    water = 0
    while l < r:
        if left_max < right_max:
            l += 1
            left_max = max(left_max, height[l])
            water += left_max - height[l]
        else:
            r -= 1
            right_max = max(right_max, height[r])
            water += right_max - height[r]
    return water

    本实现的判断与结算是一套：比较已扫描最高墙，再移动并更新该侧最高墙。还存在比较当前柱高的正确实现，但它们配有相应不变量；不能抽换这一行而沿用未验证的说明。

    从"找一对"到"找一段"：滑动窗口¶

    换个问题：给定字符串 s，求不含重复字符的最长连续子串的长度。

    暴力做法是枚举所有子串再检查，瓶颈在于"每次都重新检查整段"。改成维护一个窗口 \([l, r]\)：r 一路向右扩张，一旦窗口里出现重复字符，就移动 l 直到重新合法。

    这里 set() 创建空集合，window.add(c) 加入字符，window.remove(c) 删除已存在的字符。不能把空集合写成 {}，那会创建没有 add 方法的字典。

    def length_of_longest_substring(s):
    window, l, best = set(), 0, 0
    for r, c in enumerate(s):
        while c in window:            # 不合法：收缩
            window.remove(s[l])
            l += 1
        window.add(c)
        best = max(best, r - l + 1)
    return best

    先区分“集合”和“待加入字符”：每轮开始，window 恰好装着无重复的 s[l:r]，还不含当前字符 c。若 c 已存在，就删除左端直到旧 c 被删掉，再加入新 c；此时 window 才对应闭区间 \([l,r]\)。

    为什么不会漏掉最长答案？已被丢弃的某个左端 k，之前必因窗口出现重复而不合法；在右端继续扩张时，那两个重复字符仍在，k 不会重新合法。因此左端不必回退。修复结束后 l 是当前 r 下最靠左的合法起点，\(r-l+1\) 就是以 r 结尾的最长合法长度；遍历全部 r 并取最大，才覆盖全局最优。

    手推 abba：r=0 得 [0,0]='a'；r=1 得 [0,1]='ab'；r=2 要加入 b，先删 a 仍有旧 b，必须再删 b，最终 [2,2]='b'；r=3 得 [2,3]='ba'。这也解释 while 为什么不能改成只缩一次的 if。

    右端走n次、左端总共最多n次，集合操作按期望 \(\mathcal{O}(1)\) 计，总时间期望 \(\mathcal{O}(n)\)，空间 \(\mathcal{O}(\min (n,字符种类数))\)。图采用同一个 abba 例子。

    更新答案时，窗口必须符合当前题目的要求¶

    先把第二个任务说完整：给定正数数组 nums 和正目标 target，找和至少为 target 的最短非空连续子数组，返回长度；不存在则返回 0。连续意味着不能跳过中间元素。因为元素为正，右端加入元素只会增大和，左端移除元素只会减小和，这才允许逐步收缩。

    对于这里两种常见模板，目标和收缩条件都不同：最长无重复子串在“重复时”缩；正数数组的最短达标和在“仍达标时”缩。更新位置必须和该时刻的合法性配套，不能只挪一行就变成另一题。

    目标 更新答案的位置
    最长 while 之后（此时窗口一定合法）
    最短 while 内部（收缩过程本身在产生合法窗口）

    例如 target=7、nums=[2,3,4]，加入4后和为9，先记录长度3；删2后和为7，仍合法，记录长度2；再删3后和为4才停止。答案必须在丢弃一个合法窗口之前记录。

    反过来，如果数组含负数，不能直接套“和太大就缩小”的可变窗口模板——加一个负数会让和变小，"和太大就移左指针"的推理不再保证不漏解。固定长度窗口仍可以滚动求和；“和恰好为 k”的计数可以用前缀和加哈希。要按具体目标选择工具。

    选读：固定一个数，把 3Sum 化为 Two Sum¶

    3Sum 的输入是整数数组，要求选三个不同下标，使数值之和为 0，返回所有不同的数值三元组，不返回下标。输入可以有重复值，例如 [-1,-1,2] 可选两个不同位置的 -1；但同样的 [-1,-1,2] 在答案里只能出现一次。思路是排序 + 固定第一个数 + 对剩下的做 Two Sum II。nums.sort() 会直接把传入列表改成升序；排序后相同值必然相邻，因此与前一个值比较就能跳过重复候选，不需要再搜索它是否已经处理过。

    def three_sum(nums):
    nums.sort()
    res, n = [], len(nums)
    for i in range(n - 2):
        if nums[i] > 0:                          # 最小的数已是正数，剪枝
            break
        if i > 0 and nums[i] == nums[i - 1]:     # 去重 1：跳过重复的固定值
            continue
        l, r, target = i + 1, n - 1, -nums[i]
        while l < r:
            s = nums[l] + nums[r]
            if s == target:
                res.append([nums[i], nums[l], nums[r]])
                l += 1
                r -= 1
                while l < r and nums[l] == nums[l - 1]:   # 去重 2
                    l += 1
                while l < r and nums[r] == nums[r + 1]:
                    r -= 1
            elif s < target:
                l += 1
            else:
                r -= 1
    return res

    本代码在固定值和命中后的左右值两处去重。其他实现也可只跳一侧的重复并另行保证唯一性；要说明自己的版本如何避免重复。 第一处防"相同的固定值重复开分支"，第二处防"命中后左右指针停在相同值上"。另外注意去重判断写的是 \(\mathrm{nums}[i] = \mathrm{nums}[i-1]\)——和前一个已选值比，不是和后一个比。

    走一遍 [-1,0,1,2,-1,-4]（排序后 [-4,-1,-1,0,1,2]）：i = 0 时固定 -4，需要凑 4，双指针够不到；i = 1 固定第一个 -1，能凑出 (-1,0,1) 和 (-1,-1,2)；i = 2 又是 -1，被去重跳过；i = 3 固定 0，只剩 [1,2] 和为 3，不行。答案两组。

    从讲义走到代码¶

    一段连续事件中不允许 ID 重复时，可以用左右边界维护当前合法片段。

    先写有序 two_sum_sorted([1,3,5,8,11,15],13)，结果应为 [2,3]。再做 Longest Substring Without Repeating Characters，给窗口中的集合写一句定义：它在加入当前字符前包含 s[l:r]。

    手推 abba→2、bbbbb→1、空串→0；第二个 b 到来时应删两次。最后试正数最短达标窗口 [2,3,4]、目标 7，答案 2，比较两个问题更新答案的时刻。

    练习¶

    1. 为什么无序的 Two Sum 用哈希，而有序的 Two Sum II 用双指针？

    无序时"谁是补数"没有任何可利用的顺序信息，直接扫描每次查找要 \(\mathcal{O}(n)\)，用哈希把单次查询降到期望 \(\mathcal{O}(1)\)，代价是 \(\mathcal{O}(n)\) 空间。有序时"和偏小就右移左指针"这个推理成立，于是空间降到 \(\mathcal{O}(1)\)。关键在于题目给的"有序"是一个信息，必须用掉。

    2. Container With Most Water 里如果两边一样高，移动哪一边？

    都行。两边等高时，无论丢弃哪一边，新指针处的柱子可能更高，但被保留的旧端点仍限制着“固定这一旧端点”的所有更窄容器，而宽度一定变小，所以当前容器已经是这一侧的最优解。

    3. 为什么"和为 k 的子数组计数"在数组含负数时不能用滑动窗口？

    这里按和收缩的模板要求窗口和有相应的单调性。含负数时加入一个负数会让和变小，"和太大就移左指针"不再保证不漏解。改用前缀和 + 哈希：若 pre[r+1]-pre[l]=k，则查先前的 pre[l]=pre[r+1]-k。

    4. 实现 min_subarray_len(target, nums)：找出和 不小于 target 的最短连续子数组长度，不存在返回 0。

    这是“最短窗口”模板，答案要在 while 内部更新。float('inf') 表示正无穷，比任何有限长度都大，用来代表“尚未找到答案”；一旦遇到合法窗口，min 就会把它换成有限长度。若扫描结束仍为无穷，就返回 0。后面的 float('-inf') 对称地表示负无穷，比任何有限值都小。

    def min_subarray_len(target, nums):
    l = cur = 0
    best = float('inf')
    for r, x in enumerate(nums):
        cur += x
        while cur >= target:
            best = min(best, r - l + 1)
            cur -= nums[l]
            l += 1
    return 0 if best == float('inf') else best

    题目保证元素是正数，这正是滑动窗口能用的前提。
