    第 15 讲 · 图与图搜索¶

    阅读起点：第 4 讲：队列与栈；第 7 讲：递归；第 14 讲：树的遍历。

    首读范围：先建邻接表、做 BFS；再读 DFS 与拓扑排序；反向搜索第二遍读。

    关于图，有一句话概括得最好：图无处不在。 随手就能想到三类例子：物理网络（道路、计算机、社交）；状态空间（棋局、魔方、俄罗斯方块——每个局面是顶点，一次合法走法是一条边）；依赖与流程（课程先修、构建系统）。

    例如把共同出演过电影的演员连起来，就能问某人最少经过几层合作关系能联系到演员 Kevin Bacon；把“课程 A 必须先于 B”画成箭头，就能问有没有合法修课顺序；把会打架的两条鱼连起来，就能问能否分进两个鱼缸，使每缸内部都不打架。它们分别引出最短路径、拓扑排序和二分图判定，下面会逐步给出定义。

    这一讲真正要训练的，是"把问题翻译成图"这件事：节点是什么？边是什么？要解决的是"能不能到"、"最少几步"、还是"有没有环"？

    定义与存储¶

    先用三个地点 A、B、C 想象道路：地点是顶点，道路是边。如果道路只能从 A 到 B，就记有向边 A→B；双向道路则记无向边 A—B。有向图中 A→B 不自动包含 B→A。

    图 G = (V, E)，V 是顶点集，E 是边集。所谓“顶点对”，就是一条边连接的两个端点；有向边要区分起点与终点，因此是有序对，无向边则不区分先后。这里假设图是简单图：没有重边、没有自环。由"简单"立刻得到 |E| = O(|V|²)。

    两个记号后面一直用：出邻居集 Adj⁺(u) = {v | (u,v) ∈ E}，出度 deg⁺(u) = |Adj⁺(u)|；入邻居集与入度对称定义。无向图里两者相等。

    最常用的存储是邻接表：

    def build(n, edges, directed=False):
    g = {}
    for u in range(n):
        g[u] = []                   # 孤立顶点也保留空邻接表
    for u, v in edges:
        g[u].append(v)
        if not directed:
            g[v].append(u)          # 无向图要加两条边
    return g

    例如 n=4、edges=[(0,1),(0,2),(1,3),(2,3)]，有向存储得到 {0:[1,2],1:[3],2:[3],3:[]}；无向时还加反向条目。编号0..n−1不是固定数学规则，只是本讲代码约定。|V| 中的竖线表示集合元素个数，Σ表示逐个相加。无向边被两端各记一次，这就是握手引理的2倍；有向图的总出度则等于|E|。

    它的空间是 Σ_u (1 + deg(u)) = |V| + 2|E| = Θ(|V| + |E|)——这里用了握手引理 Σ deg(u) = 2|E|。这就是为什么"图算法的线性时间"指的是 Θ(|V| + |E|)，而不是 Θ(|V|)。

    写代码前先确认一件事：边要不要存方向。这比选哪种存储方式更容易出错。

    从"反复扫描"到"搜索"¶

    判断 s 能否到达 t，最朴素的做法是维护一个"已确认可达"的集合，不断扫描所有边直到不再变化。它是对的，但代价是 O(|V|·|E|)——因为每一轮都要重扫全部边，最多扫 |V| 轮。

    瓶颈很清楚：已经处理过的边被反复检查。 改成"从一个顶点出发，沿它的邻接表一直走"——走过一个顶点就把它的邻居放进待访问容器。每条边只在它的起点被访问时被检查一次，总代价降到 O(|V| + |E|)。

    而这个"容器"用队列就是广度优先，用栈就是深度优先。队列优先处理先发现的顶点，栈优先处理最近发现的顶点；访问顺序不一定恰好相反。递归 DFS 还隐含“回来继续处理剩余邻居”的调用栈。

    广度优先：按距离分层¶

    先把“距离”说清：无权图中，路径是沿边走的一串顶点，长度是边数；δ(s,v) 是从 s 到 v 的最少边数，不可达记为 ∞。Lᵢ 表示距离恰好为 i 的顶点集合。

    例如 0→1, 0→2, 1→3, 2→3：第 0 层是 {0}，第 1 层是 {1,2}，第 2 层是 {3}。3 虽有两个入口，也只应入队一次。代码中的 dist 既存距离，也记录是否已发现。

    为什么逐层扩展正确？已知第 i 层时，从它向外走一条边能给未发现的 v 一条长 i+1 的路径；若 v 有更短路径，它早应由前一层发现。两边合起来，首次发现的距离恰好就是最短距离。

    于是算法就是"从 L₀ = {s} 开始，一层一层往外生成"：

    from collections import deque

def bfs(graph, s):
    dist, parent = {s: 0}, {s: None}
    q = deque([s])
    while q:
        u = q.popleft()
        for v in graph[u]:
            if v not in dist:            # 还没访问过
                dist[v] = dist[u] + 1
                parent[v] = u
                q.append(v)
    return dist, parent

    访问标记放在入队时做，这样每个顶点最多入队一次。（放在出队时会重复入队，结果虽可能仍对，但复杂度会退化。）

    代码处理一个顶点的全部邻居后再取队头，所以先入队的同层点一定先于下一层点被处理。结合前面的距离上下界，首次发现的层号就是最短边数。图中队列状态是逐次出队后的队列，不能把整层缩略状态当作每次循环的实际内容。

    顺带说一个工程上的点：最短路径树只需 O(V) 个父指针，就能为每个可达顶点保存一条最短路径，比"把每条路径都存下来"（可能要 Θ(V²)）聪明得多。

    拿到 parent 后，可以这样恢复一条路径。这里只给“从 s 可达”的点设置父指针，不可达的 t 应返回空列表。沿父指针得到的是终点到起点的逆序，所以最后用 path[::-1] 返回一个倒序的新列表；切片的第三项 −1 表示从后向前取：

    def restore_path(parent, t):
    if t not in parent:
        return []
    path = []
    while t is not None:
        path.append(t)
        t = parent[t]
    return path[::-1]

    对四点有向图，执行 g=build(4,[(0,1),(0,2),(1,3),(2,3)],directed=True)，再 dist,parent=bfs(g,0)，得到 dist={0:0,1:1,2:1,3:2}。restore_path(parent,3) 返回 [0,1,3]；如果按相反顺序存储 0 的邻居，也可能返回 [0,2,3]，两条都长 2。

    深度优先与拓扑排序¶

    深绿色节点的全部出边已经探索完；橙线是尚未返回的 DFS 调用沿途经过的边；斜线起点仍有邻边待探索。橙色路线表示当前探索过程，不保证是最短路线。

    DFS 的递归结构很自然：

    def dfs(graph, s, visited, order):
    visited.add(s)
    order.append(s)              # 前序：刚进入时记录
    for v in graph[s]:
        if v not in visited:
            dfs(graph, v, visited, order)

    这里 order 记录进入顺序；若改到递归邻居之后追加，就得到完成顺序。拓扑排序使用完成顺序的逆序；有向图判环还需要区分“正在递归栈中”与“已经完成”的顶点，单有 visited 不够。

    只从 s 调用一次 DFS，只覆盖它能到达的点。若要遍历整张图，应再循环所有顶点，每遇到一个未访问点就启动 DFS，这叫完整 DFS；孤立点也必须处理。

    拓扑排序的定义是：给一个有向无环图（DAG），输出一个顶点序列，使每条边 (u,v) 都满足 u 排在 v 前面。DFS 给出的结论是：

    若 G 是 DAG，则 Full-DFS 的"完成顺序"的逆序就是一个拓扑序。

    证明只需对一条边 (u,v) 讨论两种情况。若 u 比 v 先被访问，那么访问 u 的过程中必然（直接或间接）访问到 v，于是 v 先完成。若 v 比 u 先被访问，由于图无环，u 不可能从 v 到达（否则会有环），于是访问 v 时碰不到 u，v 也先完成。两种情形都满足"v 先于 u 完成"。∎

    在前面的四点有向图中，按邻接表顺序从 0 做完整 DFS，完成顺序为 [3,1,2,0]，它本身把 3 放在先修 1 的前面，不能直接用；反转为 [0,2,1,3] 才是一个合法拓扑序。

    另一个更容易直接手写的方法是 Kahn 算法。入度就是“还有多少条边指向这个点”，在先修模型里表示“还有多少门先修没完成”。入度为 0 的课可以现在上；完成它后，从图中逻辑上删掉它的出边，让后续课的未完成先修数减 1。无需真的删除邻接表条目，维护计数即可。

    下面引入标准库 defaultdict。普通字典第一次执行 graph[u].append(v) 前，必须先保证键 u 已存在；defaultdict(list) 遇到缺失键时会自动新建并保存一个空列表。因此终点即使没有出边，也能通过 graph[u] 读到空列表。它简化的是缺键处理，图的含义与前面的普通字典邻接表相同：

    from collections import defaultdict

def topo_sort(n, edges):
    graph, indeg = defaultdict(list), [0] * n
    for u, v in edges:              # u -> v 表示 u 必须先做
        graph[u].append(v)
        indeg[v] += 1
    q = deque()
    for i in range(n):
        if indeg[i] == 0:
            q.append(i)
    order = []
    while q:
        u = q.popleft()
        order.append(u)
        for v in graph[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)
    return order if len(order) == n else []      # 长度不足 → 有环

    判环的方式非常直观：环上的顶点入度永远降不到 0，所以永远不会被处理。"处理过的顶点数是否等于 n"就是判据。

    用同一张四点有向图手推Kahn：初始入度 [0,1,1,2]，队列 [0]；处理0后入度 [0,0,0,2]、队列 [1,2]；处理1后3的入度降为1，仍不能入队；处理2后3降为0，入队；最后得到 [0,1,2,3]。3必须等所有先修完成，不能在第一个先修处理后就加入。

    若额外有3→1，1和3互相等待，队列最终处理不完所有点。无环时则一定还能找到一个剩余入度0的点，否则一直逆着入边走，会在有限顶点中重复而形成环。

    网格上的搜索¶

    以岛屿数量为例：输入字符网格，'1' 表示陆地、'0' 表示水；上下左右连在一起的陆地算一个岛，斜角接触不算，输出岛的数量。例如一行 [['1','1','0','1']] 有两个岛。

    把每个陆地格看作顶点，相邻陆地之间连边。扫描网格时遇到未访问的陆地，说明发现一个新岛，答案加 1，再搜索并标记这一整片陆地。这样同一片陆地以后不会重复计数。代码用四个方向偏移代替显式邻接表：

    def num_islands(grid):
    if not grid or not grid[0]:
        return 0
    ROWS, COLS = len(grid), len(grid[0])
    count = 0
    for r in range(ROWS):
        for c in range(COLS):
            if grid[r][c] != '1':
                continue
            count += 1
            q = deque([(r, c)])
            grid[r][c] = '#'                    # 入队时就标记
            while q:
                cr, cc = q.popleft()
                for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                    nr, nc = cr + dr, cc + dc
                    if (0 <= nr < ROWS and 0 <= nc < COLS and grid[nr][nc] == '1'):
                        grid[nr][nc] = '#'
                        q.append((nr, nc))
    return count

    "就地标记"是网格题的标准技巧：把访问过的格子改成一个不会出现的值（'#'、0），可省独立 visited 集合，但会修改输入，BFS 队列仍可能占 O(mn) 空间。需要保留网格时应复制或另用 visited。

    多源 BFS¶

    输入整数网格：0 是空格，1 是新鲜橘子，2 是腐烂橘子。每分钟，所有腐烂橘子会同时使上下左右相邻的新鲜橘子变腐烂。返回所有新鲜橘子都腐烂所需的最少分钟数；原本没有新鲜橘子则返回 0，有橘子永远无法感染则返回 −1，空格不能传播。

    例如一行网格 [[2,1,1]] 要 2 分钟；[[2,0,1]] 被空格隔开，返回 −1。为模拟同时开始，把所有最初腐烂的格子都放进队列，设它们属于第 0 层；做一次 BFS，层数就是时间。

    def oranges_rotting(grid):
    if not grid or not grid[0]:
        return 0
    ROWS, COLS = len(grid), len(grid[0])
    q, fresh = deque(), 0
    for r in range(ROWS):
        for c in range(COLS):
            if grid[r][c] == 2:
                q.append((r, c))
            elif grid[r][c] == 1:
                fresh += 1
    if fresh == 0:
        return 0
    minutes = 0
    while q and fresh > 0:
        minutes += 1
        for _ in range(len(q)):                  # 按层推进
            r, c = q.popleft()
            for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                nr, nc = r + dr, c + dc
                if (0 <= nr < ROWS and 0 <= nc < COLS and grid[nr][nc] == 1):
                    grid[nr][nc] = 2
                    fresh -= 1
                    q.append((nr, nc))
    return minutes if fresh == 0 else -1

    例如一行网格 [[2,1,1,2]]，两个端点同时在第 0 分钟入队，第 1 分钟分别感染相邻的两个新鲜橘子，答案 1。若先把左端一路传播完，再处理右端，就失去了“同时开始”的含义。

    "所有源点同时入队"是多源 BFS 的灵魂——依次对每个源点做 BFS 会让复杂度乘以源点个数。同一个模板稍作改动就是"每个房间到最近门的距离"（把源点换成门）。

    反向搜索¶

    有些问题正向很难，反向很简单。两个典型：

    Pacific Atlantic（水流入两大洋）：输入每格的高度，水只能向上下左右不高于自己的格子流。上、左边界接太平洋，下、右边界接大西洋；要求返回既能流到太平洋、又能流到大西洋的所有格子坐标。正向要问"这个格子能不能流到某个海洋"，反向则从两个海洋的边界出发，逆着水流方向往高处爬，能到达的格子就是"能流到该海洋"的。起点只有 O(m+n) 个，复杂度降到 O(mn)。

    反向走时只允许进入高度不低于当前格的邻格。分别得到“能流到太平洋”和“能流到大西洋”两个可达集合，取交集才是答案。

    Surrounded Regions（被围绕的区域）：输入由 X、O 组成的网格，要把所有不能沿上下左右的 O 路径到达边界的 O 改成 X，与边界连通的 O 保留。正向判断"某块 O 是否被完全包围"很麻烦，反向则从四条边界上的 O 出发标记，剩下的 O 就是被包围的。

    "正向难、反向易"是网格题里非常常见的转折点，值得单独记一条。

    练习¶

    1. 三个场景分别怎样建图、要输出什么？(a) 演员共同出演就算有一层关系，求每个人到演员 Kevin Bacon 的最少关系层数，并找出恰好为 6 的人；(b) 课程之间有先修要求，给出一个可修课顺序；(c) 一些鱼互相会打架，能否分进两个鱼缸，使每缸内部都不打架？

    Bacon 数：演员是顶点、共同出演一部电影就连边，问的是无权图单源最短路——也就是 BFS；第 2 问"所有 Bacon number 等于 6 的人"就是取出第 6 层。课程先修：课程是顶点、A 是 B 的先修 是有向边，排出合法顺序就是拓扑排序，有环就无解。鱼缸分组：会打架就连边，分成两个互不打架的缸就是二分图判定（2-着色）。

    2. 二分图判定什么时候做不到？

    当图里有奇环时。沿奇环走一圈，染色会要求"和自己颜色不同"。实现上就是在 BFS/DFS 里顺便染色，遇到"相邻同色"就返回失败。

    def is_bipartite(graph, n):
    color = [-1] * n
    for s in range(n):
        if color[s] != -1:
            continue
        color[s] = 0
        q = deque([s])
        while q:
            u = q.popleft()
            for v in graph[u]:
                if color[v] == -1:
                    color[v] = 1 - color[u]
                    q.append(v)
                elif color[v] == color[u]:
                    return False
    return True

    3. 为什么 BFS 的复杂度不能写成 O(|V|²)？

    因为 O(|V|²) 是更松的上界。对稀疏图（|E| = O(|V|)）它会把真实的线性代价夸大一个 |V| 因子。渐进记号要给尽可能紧的界，否则会掩盖真实性能。

    4. 证明"有向图有拓扑序 ⟺ 它是 DAG"。

    （DAG ⇒ 有拓扑序）对顶点数归纳：DAG 必有入度为 0 的顶点（否则沿入边一直往回走会重复，形成环），删掉它之后剩下的仍是 DAG，递归得到拓扑序并放在最前面。

    （有拓扑序 ⇒ DAG）若图有环 v₀ → v₁ → ⋯ → v_k → v₀，由拓扑序可得 v₀ 排在 v₁ 前、⋯、v_k 排在 v₀ 前，串起来是"v₀ 排在 v₀ 前"，矛盾。∎

    5. 为什么"从 s 出发的 BFS"求不了带权图的最短路？

    BFS 假设每条边代价都是 1，所以"层数 = 距离"。带权时，"边数少但权重巨大"的路径可能比"边数多但权重小"的路径更贵。反例：A —1— B —1— C 与 A —3— C，BFS 说 A 到 C 距离 1，按权重算最短路是 A→B→C 代价 2。这就是第 18 讲要引入 Dijkstra 的原因。

    6. 用 DFS 的后序实现拓扑排序，与 Kahn 算法对比。

    DFS 版不需要统计入度，但必须显式检测环（否则结果可能错）；Kahn 通过"长度是否等于 n"自然检测。DFS 版更适合需要遍历顺序的场景，Kahn 更适合判环，或者用堆代替队列来得到字典序最小的拓扑序。
