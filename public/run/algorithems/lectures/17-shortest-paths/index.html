    第 17 讲 · 并查集与最小生成树¶

    阅读起点：第 15 讲：无向图、连通、环；第 12 讲：堆。

    首读范围：先写 DSU，再读割的交换证明；稠密图 Prim 是实现变体。

    这一讲有两个看起来无关的问题。

    问题一（动态连通性）：有一张图，边一条一条加进来。每加一条之后，快速回答"某两个点现在连通吗"。

    问题二（最小生成树）：给定带权连通无向图，选择一棵覆盖全部顶点的树，使它的边权总和最小。边权可表示铺设一条线路的费用；树要求连通且无环。例如三个地点之间的费用为 A—B=1、B—C=2、A—C=4，只铺前两条就能连通全部地点，总费用为 3。

    生成树先要求覆盖全部顶点、连通且无环，因此恰有 |V|−1 条边。最小是在所有生成树中比较边权总和，并不是边数更少。形式定义为：V_T = V、E_T ⊆ E、无环连通、Σ w_e 最小。在看算法之前值得自己先脑暴一下：能不能贪心？取边还是取顶点？怎么取？ 这里没有标准答案，好几种做法都对。

    这两个问题会在下面合流：Kruskal 求 MST 时的核心判断正是"这条边的两个端点是否已经连通"——那就是问题一要解决的事。

    让“合并”也变快¶

    先给动态连通性准备三个操作。DSU(n) 让编号 0..n−1 的点各自成组；find(x) 返回 x 所在组的代表编号，比较两个代表是否相同就能判断同组；union(a,b) 把两组并成一组，已经同组则不动。例如加入边 0—1、1—2 后，0、1、2 应在同一组，即使原图没有直接边 0—2，它们仍然连通。这里仅处理加边，暂不处理删边。

    维护动态连通性，最直接的想法是用数组 group 给每个元素记一个组号，初始 group=list(range(n))。下面的合并片段假定这个数组保存在 self.group 中；合并时，把第二组所有成员的组号改成第一组：

    def union_naive(self, a, b):
    ga, gb = self.group[a], self.group[b]
    if ga == gb:
        return False
    for i in range(len(self.group)):     # O(n)：要扫描所有人改组号
        if self.group[i] == gb:
            self.group[i] = ga
    return True

    查找是 O(1)，但合并是 O(n)。n 次合并就是 O(n²)。

    改成维护一棵代表树——每个元素指向父节点，一直往上找就到达"根"，根代表这一组：

       （组 1）           （组 2）
      a                  d
     / \                /
    b   c              e

    已经拿到两个根时，挂接只需 O(1)；完整 union 还包含两次 find，必须把找根的成本算进去。这就是并查集。

    但还有隐患：如果总是"把大树挂到小树下面"，树会越来越高。于是要两个优化一起用：

    • 按大小合并：小集合的根挂到大集合的根；按秩是另一种规则，把秩小的根挂到秩大的根。两者都能控制高度，但“大小”不等于“高度”；
    • 路径压缩：find 的过程中顺手把路径上的节点直接挂到根上。

    只用按大小合并时树高是 O(log n)：对任意节点，它所在集合的大小在根被挂到另一根、导致它的深度增加时至少翻倍，所以每个节点最多被挂 O(log n) 次。

    选读：两个优化一起用，单次操作的摊销代价为 O(α(n))。α 是增长极慢的反阿克曼函数，在通常使用的数据规模下可以看作很小的数；它并非数学上的固定常数。完整摊销证明超出本讲范围。首读时，先用上面已经证明的“按大小合并使树高 O(log n)”来理解操作上界，再观察路径压缩如何减少后续查找的步数。

    class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n
        self.count = n                    # 连通分量个数

    def find(self, x):
        root = x
        while self.parent[root] != root:  # 先找到根
            root = self.parent[root]
        while self.parent[x] != root:     # 再把路径上的节点直接挂到根上
            self.parent[x], x = root, self.parent[x]
        return root

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False                  # 已经在同一组
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra               # 保证 ra 是较大的那棵
        self.parent[rb] = ra              # 小树挂到大树下面
        self.size[ra] += self.size[rb]
        self.count -= 1
        return True

    先用三个点跑通接口：d=DSU(3)；d.union(0,1) 返回 True，分量数变成 2；再 d.union(1,0) 返回 False，分量数不变；d.find(0)==d.find(2) 为 False。union 的布尔返回值正好可以表示“新边是否连起了原本不同的两组”。

    并查集的 parent 树是管理分组的辅助结构，不是原图中的路线。即使 parent[5]=1，原图也未必有边5—1，不能沿 parent 输出真实路径。size 只在根上有效；路径压缩会改父指向但不改集合成员，因此不用改根的size。

    图先执行 union(7,2)，查根1与5后只挂 parent[5]=1；再执行 find(2)，只把这次路径上的2改指1。没有被本次查找经过的节点不会自动变成根的直接孩子。

    MST 的两条性质¶

    割性质：对任意把顶点分成两部分的"割"，跨越这个割的最小权重边一定属于某棵 MST。

    环性质：对任意环，环上权重最大的边一定不属于任何 MST（假设权重互不相同）。

    先解释“割”：把所有顶点分成非空两组 S 与其余顶点，连接两组的边叫跨割边。生成树要连通，必得跨过去。

    割性质为什么对？ 取跨割最轻边 e 和一棵 MST T。若 T 已含 e，无须修改；否则给 T 加 e 会形成唯一一个环，环上必有另一条跨割边 f。因为 w(e)≤w(f)，用 e 换掉 f 后仍是生成树且不更贵，所以仍为 MST。

    但“每条边各属于某棵 MST”还不保证选出来的全部边能共同属于一棵 MST。贪心需要更强的保证：存在一棵包含当前全部已选边 F 的 MST。若割没有切断 F 中的边，替换掉的跨割边 f 就不在 F 中，因此交换保留了 F，这才允许再加入 e。

    环性质也可用交换理解：严格最重边 e 若在生成树里，去掉后分成两块，原环上存在更轻的跨块边可替换它，总重下降，所以不可能最优。相同权重时不能说“每条最重边都不在任何 MST”。

    Kruskal：按边贪心¶

    先把所有边按费用升序排列，从空边集开始检查：两端已连通的边会产生环，跳过；否则选入，并用并查集合并两组。输入 n≥1、顶点编号 0..n−1，边表中的一项为 (权重,起点,终点)。函数返回总权重、已选边表和“是否连通全部顶点”的布尔值；输出边项则写成 (起点,终点,权重)。

    def kruskal(n, edges):
    # 与 prim 的 (u,v,w) 不同，这里为方便排序，输入是 (w,u,v)。

    edges = sorted(edges)                 # 按权重升序
    dsu = DSU(n)
    total, chosen = 0, []
    for w, u, v in edges:
        if dsu.union(u, v):               # 只在两端不连通时加入
            total += w
            chosen.append((u, v, w))
            if len(chosen) == n - 1:
                break                     # 生成树恰好 n−1 条边
    return total, chosen, dsu.count == 1

    Kruskal 的已选边 F 是森林。若新边两端已连通，加入就成环；若未连通，取其中一个端点的整个连通块为 S。没有 F 中的边跨这个割，而当前边是跨割最轻的候选：更轻的跨割边若曾处理，早会把块连在一起，分量又不会拆开。由上面的安全交换，仍有一棵 MST 包含 F 加新边。

    排序 O(E log E)，并查集操作共 O(Eα(V))，还需 O(V) 初始化。图不连通时得到的是最小生成森林，返回值中的布尔量会标出这一点。

    Prim：从一个点逐步长成树¶

    Prim 从一个起点开始，每次找“已在树中的点到树外点”的最轻边，选它并把新点加入树。最小堆保存这些候选边的 (权重,终点)；一条边入堆时，它的起点已经在树中，因此不必再保存起点。若弹出的终点也已经加入，就跳过这条旧候选。

    下面输入边项为 (起点,终点,权重)，返回 MST 的总权重；无法覆盖全部顶点则返回 None。最初 (0,start) 表示零成本纳入起点，不是一条原图中的边。

    import heapq
from collections import defaultdict

def prim(n, edges, start=0):
    graph = defaultdict(list)
    for u, v, w in edges:
        graph[u].append((v, w))
        graph[v].append((u, w))
    visited, heap = [False] * n, [(0, start)]
    total, used = 0, 0
    while heap and used < n:
        d, u = heapq.heappop(heap)
        if visited[u]:
            continue                      # 过期条目
        visited[u] = True
        total += d
        used += 1
        for v, w in graph[u]:
            if not visited[v]:
                heapq.heappush(heap, (w, v))
    return total if used == n else None   # None 表示图不连通

    本实现从 start 开始，只把图的一块连起来；n≥1 且 start 必须为合法顶点。每条无向边至多贡献两份堆候选，每份最多进出一次，在简单图上时间 O((V+E)log(V+1))，建图与堆共需 O(V+E) 空间。

    正确性来自不变式"当前已选边集是某棵 MST 的子集"：每轮把"已访问顶点集合"与其余顶点看作一个割，先丢弃终点已访问的过期记录，再取跨割最轻边；该割没有切开已有树边，由安全交换可保留此前所有选择。

    第 18 讲学到 Dijkstra 后，可以回看两者堆项的差别：

    算法 堆里存的量
    Dijkstra 从起点到该顶点的累计距离
    Prim 某条从已选集合跨到外部顶点的单边权重；同一终点可有多份候选

    这个区别决定了它们解决完全不同的问题。另外别忘了 MST 与最短路是两回事：MST 最小化总权重，不保证任意两点间路径最短。反例是等边三角形（三条边权重都是 1），MST 只取两条边，被排除那条边所连的两点在 MST 上的距离是 2，而图中最短是 1。

    选型：边以列表给出、图稀疏用 Kruskal（排序 O(E log E)）；顶点是坐标、边要现算，或者图很稠密，用 Prim但本节的堆实现仍接收显式边表。坐标完全图若想省 O(V²) 边空间，应改用数组记录每个点到当前树的最小边权，做 O(V²) 时间、O(V) 空间的 Prim；不能直接照搬这里的建图。

    走一遍¶

    四个顶点，边按“起点、终点、权重”记为 (A,B,5), (A,C,4), (B,D,2), (C,D,3), (B,C,6)。这行是配图的文字记法；实际调用时将 A、B、C、D 编号为 0、1、2、3。Kruskal 还要求权重在前，因此这组输入应写成 kruskal(4,[(5,0,1),(4,0,2),(2,1,3),(3,2,3),(6,1,2)])，总权重为 9；Prim 则保持 (u,v,w) 的输入顺序。

    图的割为S={A}，跨割边只有A—C(4)、A—B(5)，最轻的是4。图与下表都使用这四点五边；Kruskal代码选满3条边就停止，下表后两行仅供继续验证“为何会成环”，不表示代码仍会运行。

    Kruskal 按权重升序处理：

    顺序 边 权重 两端已连通？ 动作 累计
    1 B–D 2 否 加入 2
    2 C–D 3 否 加入 5
    3 A–C 4 否 加入 9
    4 A–B 5 是（A–C–D–B 已连通） 跳过 9
    5 B–C 6 是 跳过 9

    选中的是 B–D, C–D, A–C，共 3 条边，总权重 9。第 4 步跳过 A–B 正是环性质的体现：A–B–D–C–A 构成环，而 A–B 是这个环上权重最大的边。

    Prim 从 A 出发：先选 A–C(4)，再选 C–D(3)，最后选 D–B(2)，总权重同样是 9。注意 Prim 每轮选的边权重并不单调递增，但结果相同。

    从讲义走到代码¶

    铺设线路时使总铺设长度最小是 MST；从某站最快到达各站则是最短路。

    先做 Redundant Connection：边 [1,2]、[1,3]、[2,3] 中，第三次 union 返回 False，应报告 [2,3]。题目从 1 编号时，可开 n+1 个槽，或统一减 1。

    再把正文四点五边编号为 0..3，分别跑 Kruskal 与 Prim，总权重都应为 9。Kruskal 输入是 (w,u,v)，Prim 是 (u,v,w)，调用前先转换字段顺序。

    练习¶

    1. 列出至少两种"看起来合理的贪心策略"，判断对错。

    策略 是否可行
    按边：每次取全局最小的、且不与已选边成环的边 ✅ 这就是 Kruskal
    按顶点：每次取连接"已选顶点集与外部"的最小边 ✅ 这就是 Prim
    每次取全局最小边但不检查成环 ❌ 会形成环
    按权重从大到小尝试删除，且删除后必须仍连通 ✅ 这就是反向删除法

    2. 为什么"每次删除最重的边"也对？

    由环性质，任何环上最重的边都可以安全删除。反复执行"删掉某个环上最重的边"直到剩下 n−1 条边，剩下的必然是一棵 MST。它和 Kruskal 用的是同一个性质的两面。

    3. 如果图里有权重相同的边，MST 唯一吗？Kruskal 会输出什么？

    MST 可能不唯一（正方形四条边权重都为 1，任取三条都是 MST），Kruskal 会输出其中一棵，具体哪棵取决于排序与输入顺序。但总权重是唯一的。

    4. 如果存在负权边，MST 会包含它们吗？

    可以包含负边，算法无需改动；但不保证所有负边都入树。例如负边组成环时，仍得舍弃一条。注意这与最短路不同：最短路在负权下会遇到"负环"的麻烦，而 MST 完全不受影响。

    5.（选读） 并查集能不能用来求"瓶颈路径"（最小化路径上的最大边权）？

    能。MST 有一个重要性质：树上任意两点之间路径的最大边权，等于原图中这两点之间所有路径里"最大边权"的最小值。 为何成立？删掉MST路径中最重边e，把树分成S/T，起终点分居两侧。原图任意连接它们的路径都得跨此割；若存在跨割边比e轻，就能替换e得到更轻生成树，矛盾。因此任何路径的最大边权≥w(e)，而MST路径恰达到它。这也正是 Swim in Rising Water 可以用"按高度升序激活 + 并查集"解决的原因。

    6. 实现 equations_possible(equations)：输入一组形如 "a==b"、"a!=b" 的约束，变量用小写字母表示，问能否给它们赋整数值，使所有约束同时成立。例如 ["a==b","b==c","a!=c"] 应返回 False；["a!=b"] 可以令 a=0、b=1，返回 True。

    第一步只处理所有 ==（用并查集合并），第二步再检查所有 !=（若两端在同一集合则矛盾）。顺序不能反——这是本题的关键。
