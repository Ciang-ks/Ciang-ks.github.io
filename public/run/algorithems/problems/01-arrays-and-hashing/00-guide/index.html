    Arrays & Hashing · 解题手册¶

    这一族题的共同点：问题看起来需要"两两比较"，但用一张哈希表就能把"查找"从 \(\mathcal{O}(n)\) 降到 \(\mathcal{O}(1)\)。读完题先在脑子里问一句"我的瓶颈是不是'找得太慢'"，如果是，哈希表通常就是答案。

    一、从题面提出候选，再核对条件¶

    已学基础：02-数组与摊销分析、03-哈希表。下面将讲义中的结构性质用于选择解法。

    先问重复工作究竟是什么：反复查值、重算频次，还是逐段求和。哈希表能减少查询成本，却不会自动减少必须枚举的结果数量。

    题目特征 需要验证的依据 迁移边界与反例
    查某值是否已出现 只需存在性可用 set；需位置或次数则用 dict Two Sum 要返回下标，不能只存值
    按某种等价关系分组 构造 key，证明同组同键且异组不同键 字母计数保留次数，字符集合会把 ab 与 aab 混为一组
    最长连续整数序列 顺序无关，按数值相邻，从集合中的起点扩展 连续子数组要求位置相邻，不是本题
    统计和为 k 的子数组 维护此前前缀和的频次，先查询再登记当前前缀 仅用 set 不能统计多个相同前缀对应的方案数

    写代码前先给每个键和值命名：seen[x] 是位置、次数还是布尔信息？哈希查询通常按期望 \(\mathcal{O}(1)\) 计，新构造长字符串键仍需计入构造与哈希的字符成本。

    二、这一族的共同本质¶

    暴力解的骨架几乎都是同一个形状：两层循环，内层在"找某个东西"。

    for i in range(n):
    for j in range(n):          # 内层在找一个"满足条件的 j"
        if 条件(nums[i], nums[j]):
            ...

    哈希表做的只有一件事：把内层的线性扫描替换成一次 \(\mathcal{O}(1)\) 查询。于是三种常见瓶颈对应三种武器：

    内层在找什么 换成什么
    "有没有出现过这个值" set
    "某个补数 / 配对值在不在" dict（值 → 下标或次数）
    "有没有和它同类的元素" 规范化 key + 分组字典

    三、从读题到写码：五步流程¶

    1. 先定性：题目要输出的是"是否存在"、"有多少种/多少个"、还是"最优值"？
    2. 写暴力解并指明瓶颈行：通常能一句话说清——"瓶颈在于每次查找都要扫描一遍数组"。
    3. 挑数据结构： - 查"存在" → set - 查"补数/配对" → dict（值 → 下标 / 次数） - "分组" → 设计 key 后用 defaultdict(list) - 值域小且确定 → 计数数组 - 值域是 1..n 且要求 \(\mathcal{O}(1)\) 空间 → 原地标记
    4. 补边界：空数组、单元素、全相同、含负数、存在重复元素。
    5. 报复杂度并说出取舍："时间从 \(\mathcal{O}(n^{2})\) 降到 \(\mathcal{O}(n)\)，代价是 \(\mathcal{O}(n)\) 额外空间；若还要求常数额外空间，需检查是否允许修改输入、是否满足原地标记值域；排序的辅助空间也要按具体实现计算。"

    四、五个常用模板与使用条件¶

    模板 1 存在性判断¶

    def has_duplicate(nums):
    seen = set()
    for x in nums:
        if x in seen:
            return True
        seen.add(x)
    return False

    模板 2 边遍历边查补数（Two Sum 型）¶

    def two_sum(nums, target):
    seen = {}                       # 值 -> 下标
    for i, x in enumerate(nums):
        need = target - x
        if need in seen:            # 先查
            return [seen[need], i]
        seen[x] = i                 # 后写
    return []

    "先查后写"是这套模板的灵魂：如果先写再查，当 \(\mathrm{target} = 2 * x\) 时会把同一个元素用两次。

    模板 3 规范化 key 分组¶

    from collections import defaultdict

def group_by_key(items):
    groups = defaultdict(list)
    for item in items:
        key = 规范化(item)          # 必须是可哈希类型
        groups[key].append(item)
    return list(groups.values())

    关键在设计 key：异位词用 tuple(sorted(s))；按对角线分组用 r - c；按斜对角线分组用 \(r + c\)。

    模板 4 前缀和 + 哈希（结合示例走一遍）¶

    问题：统计"和恰好为 k 的连续子数组"的个数（含负数，不能用滑动窗口）。

    推导：设 prefix[i] 为前 i 个元素之和，那么子数组 (j, i] 的和等于 prefix[i] - prefix[j]。要求它等于 k，等价于

    \[ \mathrm{prefix}[j]=\mathrm{prefix}[i]-k \]

    于是遍历时只需要问一句："历史上出现过多少个前缀和等于 prefix[i] - k？"——这正是哈希表的强项。

    from collections import defaultdict

def subarray_sum(nums, k):
    count = defaultdict(int)
    count[0] = 1                     # 空前缀（让从下标 0 开始的区间能被计入）
    prefix = 0
    res = 0
    for x in nums:
        prefix += x
        res += count[prefix - k]     # 有多少个历史前缀能凑出 k
        count[prefix] += 1
    return res

    对照示例：\(\mathrm{nums} = [1, 2, 3]\)，k = 3。

    i x prefix prefix-k 之前出现过的 prefix 新增答案
    0 1 1 -2 {0} 0
    1 2 3 0 {0, 1} 1（区间 [1,2]）
    2 3 6 3 {0, 1, 3} 1（区间 [6-3+1..]，即 [3]）

    答案是 2，正确。注意 \(\mathrm{count}[0] = 1\) 不能省，否则 [1,2] 会漏掉。

    模板 5 原地哈希与符号标记¶

    def first_missing_positive(nums):
    n = len(nums)
    for i in range(n):
        # 把 nums[i] 换到它"该在"的位置 nums[i] - 1
        while 1 <= nums[i] <= n and nums[nums[i] - 1] != nums[i]:
            target = nums[i] - 1
            nums[i], nums[target] = nums[target], nums[i]
    for i in range(n):
        if nums[i] != i + 1:
            return i + 1
    return n + 1

    def find_disappeared(nums):
    # 值域是 1..n 时，用"取负数"表示"这个值出现过"
    for x in nums:
        idx = abs(x) - 1
        nums[idx] = -abs(nums[idx])
    return [i + 1 for i, v in enumerate(nums) if v > 0]

    两个式子都要记住：while 里的交换要带 \(\mathrm{nums}[\mathrm{nums}[i]-1] \ne \mathrm{nums}[i]\) 防止重复值死循环；标记时读值要先 abs()。

    五、逐题推演：从题面到思路¶

    1. Contains Duplicate（217）¶

    题面信号：判断"是否存在重复元素"，不要求返回位置。

    候选思路：存在性 → set。退一步想，排序后相邻比较也能做，代价是 \(\mathcal{O}(n \log n)\)。

    走一遍示例：[1,2,3,1]

    • 遇到 1，集合里没有 → 放入；
    • 遇到 2、3 → 放入；
    • 再遇到 1 → 集合里已有 → 返回 True。

    关键细节：如果面试官追问"找出第一个重复出现的元素"，set 版本天然支持（遇到重复立刻返回该值），而排序版本会丢失"谁先出现"的信息——这是选择方案时要主动说明的取舍。

    进阶追问："不允许额外空间怎么办？" → 排序，或当值域是 [1, n] 时用原地标记。

    2. Valid Anagram（242）¶

    题面信号："两个字符串是否由相同字符重排而成"，即频率表必须完全相同。

    候选思路：频率 → 计数。限定小写字母就开长度 26 的数组，字符集不确定就用 Counter。

    走一遍示例：s = "anagram"，t = "nagaram"

    用 26 数组做"一边加、一边减"，最后检查是否全 0：

    字符对 处理后 a 的计数 g 的计数
    a/n +1 -1
    n/a 0 0
    a/g +1 -1
    g/a 0 0
    r/r、a/a、m/m 0 0

    最终全为 0，返回 True。这一趟遍历同时处理两个字符串，是本解法最优雅的地方。

    关键细节：先做长度剪枝；用固定 26 数组时要注意题目是否限定字母表（遇到 Unicode 会越界）。

    3. Two Sum（1）¶

    题面信号：找"两个数和为 target"，要返回下标。

    候选思路：把"找另一个数"转成"查补数" → 哈希表边遍历边存。

    走一遍示例：\(\mathrm{nums} = [2,7,11,15]\)，target = 9

    • \(i=0, x=2\)：需要 7，表里没有 → 存 {2:0}；
    • \(i=1, x=7\)：需要 2，表里有，下标 0 → 返回 [0, 1]。

    关键细节：先查后写。如果先写再查，target = 4 且数组为 [2,2] 时会返回 [1,1]。

    对照记忆：数组有序时（167）应该换成双指针，空间从 \(\mathcal{O}(n)\) 降到 \(\mathcal{O}(1)\)——有序时可以优先评估双指针，以减少额外空间。

    4. Group Anagrams（49）¶

    题面信号："把互为异位词的字符串分到同一组"。

    候选思路：分组 → 设计一个"同组必然相同、异组必然不同"的 key。异位词的天然 key 是"排序后的字符串"或"字符计数元组"。

    走一遍示例：["eat","tea","tan","ate","nat","bat"]

    单词 排序后的 key
    eat / tea / ate aet
    tan / nat ant
    bat abt

    key 相同的落到同一个桶，得到 3 组。

    关键细节：key 必须是可哈希的类型。用列表当 key 会直接抛 TypeError: unhashable type，必须转成 tuple。另外要能说出"排序 key 是 \(\mathcal{O}(k \log k)\)，计数 key 是 \(\mathcal{O}(k)\)"。

    5. Top K Frequent Elements（347）¶

    题面信号：求"出现频率前 k 高的元素"，顺序不限。

    候选思路：先计数；再按频率取 Top-K。关键观察：频率的取值范围是 [1, n]，值域有限且连续 → 可以用桶排序把 \(\mathcal{O}(n \log n)\) 降到 \(\mathcal{O}(n)\)。

    走一遍示例：\(\mathrm{nums} = [1,1,1,2,2,3]\)，k = 2

    计数结果：1→3、2→2、3→1。桶数组长度 \(n+1 = 7\)：

    buckets[3] = [1]
buckets[2] = [2]
buckets[1] = [3]

    从高频往低频扫，先拿到 1，再拿到 2，凑够 k 个即返回。

    关键细节：桶的长度是 len(nums) + 1（最大频率可能等于数组长度），不是 len(count) + 1。

    追问准备："数据是流式的" → 改用大小为 k 的小顶堆，每次插入 \(\mathcal{O}(\log k)\)。

    6. Product of Array Except Self（238）¶

    题面信号：求"除自身外所有元素的乘积"，禁止除法，要求 \(\mathcal{O}(n)\)。

    候选思路：题目禁止除法；直接总乘积除自身也不能完整处理零。将排除当前位置的元素拆成左右两段，各自聚合后相乘，就能统一处理零与负数：

    \[ \mathrm{res}[i]=\left(\prod_{j<i}\mathrm{nums}[j]\right)\left(\prod_{j>i}\mathrm{nums}[j]\right) \]

    于是一趟正向算出"左边乘积"，一趟反向乘上"右边乘积"。

    走一遍示例：\(\mathrm{nums} = [1,2,3,4]\)

    i 正向扫描后的 res[i]（= 左边乘积） 反向乘上 suffix 最终
    0 1 \(1\times(2\cdot3\cdot4)=24\) 24
    1 1 \(1\times(3\cdot4)=12\) 12
    2 \(1\cdot2=2\) \(2\times4=8\) 8
    3 \(1\cdot2\cdot3=6\) \(6\times1=6\) 6

    关键细节：\(\mathrm{res}[0] = 1\) 代表"左边没有元素，乘积是乘法的单位元"；第二趟必须倒序且"先用后乘"。

    这个"把区间拆成左半 + 右半，两趟扫描合并"的模板可以推广：42 接雨水的“前缀最大值与后缀最大值”就是同一个骨架。

    7. Valid Sudoku（36）¶

    题面信号："校验 \(9\times9\) 棋盘是否合法"，三类约束：行、列、\(3\times3\) 宫。

    候选思路：三类约束 → 三张哈希表，一次遍历全查完。

    走一遍示例：格子 (4, 7) 上的数字 5

    行：rows[4] 里有没有 '5'
列：cols[7] 里有没有 '5'
宫：(4//3, 7//3) = (1, 2) → boxes[(1,2)] 里有没有 '5'

    三处都没有重复就登记，任何一处冲突立即返回 False。

    关键细节：宫的索引是 (r // 3, c // 3)，不是 (r % 3, c % 3)——后者只是块内的相对坐标。这是本题第一大坑。

    注意题目只要"合法性"，不需要判断数独有没有解（那是 37 题，要回溯）。

    8. Encode and Decode Strings（271）¶

    题面信号：把字符串列表编码成一个字符串，再原样解码。输入可以包含任意字符。

    候选思路：任何"选一个特殊分隔符"的方案都能被构造输入击穿（比如输入里真的含有那个分隔符）。正确做法是长度前缀：

    "lint" → "4#lint"
""     → "0#"
"a#b"  → "3#a#b"

    解码时先读到 # 拿到长度 k，再精确读 k 个字符——知道长度，后面出现什么字符都无所谓。

    关键细节：长度可能是多位数，所以要循环读到 # 为止；空列表编码成 ""，解码回 []，游标写法天然正确。

    这个思路的工业对应：HTTP 分块传输、protobuf、Redis 的 RESP 协议都用长度而不是分隔符来界定边界。面试中能提这一句很加分。

    9. Longest Consecutive Sequence（128）¶

    题面信号："最长连续序列"，要求 \(\mathcal{O}(n)\)，元素在原数组中的位置无关。

    候选思路：排序是 \(\mathcal{O}(n \log n)\)，不符合要求；但"连续"意味着可以用集合做 \(\mathcal{O}(1)\) 查找。关键优化是只从序列起点扩展。

    走一遍示例：\(\mathrm{nums} = [100, 4, 200, 1, 3, 2]\)

    考察的 x x-1 在集合里吗 动作
    3 在（2） 跳过，3 不是起点
    4 在（3） 跳过
    1 不在 从 1 往上数：1,2,3,4 → 长度 4
    100 / 200 不在 各自长度 1

    答案是 4。

    关键细节：复杂度为什么是 \(\mathcal{O}(n)\)？ 外层 \(\mathcal{O}(n)\)；内层 while 只在"x 是起点"时执行，而每个元素最多作为一个序列的成员被访问一次，所以内层总次数 不大于 n。这是本题必答的追问。

    六、复杂度速查¶

    题目 主套路 时间 空间
    Contains Duplicate 集合 \(\mathcal{O}(n)\) \(\mathcal{O}(n)\)
    Valid Anagram 计数数组 \(\mathcal{O}(n)\) \(\mathcal{O}(1)\)
    Two Sum 边遍历边查 \(\mathcal{O}(n)\) \(\mathcal{O}(n)\)
    Group Anagrams 规范化 key \(\mathcal{O}(n\cdot k \log k)\) \(\mathcal{O}(n\cdot k)\)
    Top K Frequent 计数 + 桶排序 \(\mathcal{O}(n)\) \(\mathcal{O}(n)\)
    Product Except Self 前后缀分解 \(\mathcal{O}(n)\) \(\mathcal{O}(1)\)
    Valid Sudoku 三张哈希表 \(\mathcal{O}(81)\) \(\mathcal{O}(81)\)
    Encode/Decode 长度前缀 \(\mathcal{O}(n)\) \(\mathcal{O}(n)\)
    Longest Consecutive 集合 + 起点判断 \(\mathcal{O}(n)\) \(\mathcal{O}(n)\)

    七、易错点速查¶

    1. res.append(path) vs res.append(path[:])——本题型里虽然少见，但凡是"收集列表"都要注意引用问题。
    2. list 不能当字典 key，必须转 tuple。
    3. Two Sum 的"先查后写"顺序写反。
    4. Valid Sudoku 的宫索引写成 (r % 3, c % 3)。
    5. 桶排序的桶长度写成 len(count) + 1。
    6. 前缀和忘记 \(\mathrm{count}[0] = 1\)（空前缀）。
    7. Encode/Decode 用固定分隔符而不是长度前缀。
    8. Longest Consecutive 漏掉 x - 1 not in set 的起点判断，复杂度退化成 \(\mathcal{O}(n^{2})\)。
    9. 在循环里调用 sorted：会让复杂度悄悄升到 \(\mathcal{O}(n^{2} \log n)\)。
    10. 以为"有负数就不能用哈希"——哈希和前缀和对负数完全没问题，只有滑动窗口才要求非负。

    八、面试话术¶

    开场："最直接的做法是两层循环枚举所有对，时间 \(\mathcal{O}(n^{2})\)。" 找瓶颈："瓶颈在于每次查找都要线性扫描一遍。" 换武器："用哈希表把查找降到 \(\mathcal{O}(1)\)，整体降到 \(\mathcal{O}(n)\)，代价是 \(\mathcal{O}(n)\) 额外空间。" 处理追问："如果要求 \(\mathcal{O}(1)\) 额外空间，我会核对输入是否可修改与值域范围，再考虑常数空间排序或原地标记；Python list.sort 不能直接承诺 \(\mathcal{O}(1)\) 辅助空间。"
