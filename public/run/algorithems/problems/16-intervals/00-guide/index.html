    Intervals · 解题手册¶

    区间题几乎都遵循同一个套路：先排序，再一次线性扫描。排序的 key 通常是"左端点"或"右端点"，选哪个直接决定贪心能否成立。记住这条规则：涉及"重叠/删除/覆盖"按右端点排序，涉及"合并"按左端点排序。

    一、从题面提出候选，再核对条件¶

    已学基础：24-贪心算法、25-区间调度与合并。下面将讲义中的结构性质用于选择解法。

    先确认端点语义和输出目标，再决定排序方向。同样的区间输入，求并集、最多兼容项、最大同时数量是不同问题。

    题目特征 需要验证的依据 迁移边界与反例
    合并覆盖范围 按起点扫描，比较最后的合并段 不能只比较相邻的原始区间
    插入有序区间 原集合同时有序且互不重叠才直接三段扫描 仅有序但内部仍重叠时需先处理旧冲突
    最多互不冲突区间 最早结束选择，按数量目标作交换论证 最少会议室则求同时重叠数
    大量点查询最短覆盖区间 允许重排独立查询，离线扫描加长度堆 堆内可留过期项，读取前清理过期堆顶

    相接端点是否冲突必须按题意决定：会议常用半开区间，闭区间覆盖查询则计入两个端点。空间复杂度应同时看结果、堆和 Python 排序辅助空间。

    二、两种排序方式与它们的适用场景¶

    排序方式 适用 为什么
    按左端点升序 合并、插入 起点递增，只需和"上一个合并结果"比较
    按右端点升序 选择不重叠、最少箭数 结束越早，给后面留的空间越大

    为什么"选择不重叠"要按右端点排序？ 用一个反例就能说明：[[1,100],[2,3],[4,5]]。按左端点会先选 [1,100]，只能保留 1 个；按右端点会选 [2,3] 和 [4,5]，保留 2 个。

    三、常用模板与使用条件¶

    模板 1 合并重叠区间¶

    def merge(intervals):
    intervals.sort()                      # 按左端点排序
    res = []
    for start, end in intervals:
        if res and start <= res[-1][1]:   # 与上一个合并结果重叠
            res[-1][1] = max(res[-1][1], end)     # 注意取 max
        else:
            res.append([start, end])
    return res

    max 不能省：[[1,10],[2,3]] 里后一个区间完全被包含，终点不能变小。

    模板 2 选择最多的不重叠区间（活动选择）¶

    def max_non_overlapping(intervals):
    intervals.sort(key=lambda x: x[1])    # 按右端点升序
    count = 0
    last_end = float("-inf")
    for start, end in intervals:
        if start >= last_end:             # 不与已选冲突
            count += 1
            last_end = end
    return count

    435 题的答案就是 len(intervals) - count（删掉最少 = 保留最多）。

    模板 3 扫描线（求"同时重叠数"）¶

    def max_overlap(intervals):
    events = []
    for start, end in intervals:
        events.append((start, 1))         # 开始
        events.append((end, -1))          # 结束
    events.sort()                         # 同一时刻，-1 排在 +1 之前
    cur = ans = 0
    for _, delta in events:
        cur += delta
        ans = max(ans, cur)
    return ans

    最关键的一点：同一时刻"结束"要排在"开始"之前。 因为本题约定半开区间 \([\mathrm{start}, \mathrm{end})\)——一场会议 10 点结束，另一场 10 点开始，可以共用同一间会议室。(time, delta) 元组排序天然让 -1 排在 \(+1\) 前面，正好符合这个约定。

    如果题目是闭区间（比如 2406），把每个 end 换成 \(\mathrm{end} + 1\) 就能复用这个模板。

    模板 4 最小堆求同时会议数¶

    import heapq

def min_meeting_rooms(intervals):
    intervals.sort()                      # 按开始时间排序
    heap = []                             # 正在进行的会议的结束时间
    ans = 0
    for start, end in intervals:
        while heap and heap[0] <= start:  # 已经结束的会议，释放会议室
            heapq.heappop(heap)
        heapq.heappush(heap, end)
        ans = max(ans, len(heap))
    return ans

    四、从读题到写码：四步流程¶

    1. 先确认区间约定：闭区间 [a, b] 还是半开区间 \([a, b)\)？这决定了所有边界判断用 \(<\) 还是 \(\le\)。
    2. 确定要"合并/选择/覆盖/计数"中的哪一种，据此选排序 key。
    3. 写扫描主体：合并就维护"当前合并区间"，选择就维护 last_end，计数就用扫描线或堆。
    4. 补边界：空数组、单区间、完全包含、首尾相接。

    五、逐题推演：从题面到思路¶

    1. Meeting Rooms（252）¶

    题面信号："一个人能否参加所有会议"（任意两个不重叠）。

    候选思路：按开始时间排序，然后只需检查相邻两个是否重叠——因为排序后如果某个区间和更早的区间重叠，它一定也和某个相邻区间重叠。

    走一遍示例：[[0,30],[5,10],[15,20]]（排序后不变）

    比较 [0,30] 和 [5,10]: 5 < 30 → 重叠 → 返回 False

    关键细节：判断条件是 start < prev_end（严格小于），因为半开区间下"上一场 10 点结束、这一场 10 点开始"是允许的。如果题目改成闭区间，就要用 \(\le\)。

    2. Insert Interval（57）¶

    题面信号："原区间列表已排序且互不重叠，插入一个新区间"。

    候选思路：题目特意说"已排序"，就是在提示你能做到 \(\mathcal{O}(n)\)。三段式扫描：

    阶段 1：interval.end < newInterval.start        → 直接放进结果
阶段 2：interval.start <= newInterval.end       → 合并进 newInterval（两端都取极值）
阶段 3：剩下的（都在右边）                       → 直接接上

    走一遍示例：intervals = [[1,3],[6,9]]，newInterval = [2,5]

    阶段 1：[1,3] 的 end=3 不小于 2 → 不满足
阶段 2：[1,3] 的 start=1 <= 5 → 合并 → newInterval = [1,5]
        [6,9] 的 start=6 > 5 → 退出阶段 2，把 [1,5] 放进结果
阶段 3：接上 [6,9]
答案 [[1,5],[6,9]]

    关键细节：阶段 1 用严格小于（\(\mathrm{end} < \mathrm{start}\)），阶段 2 用带等号（\(\mathrm{start} \le \mathrm{end}\)）——两个条件的等号位置必须配套；合并时 start 和 end 都要取极值（新区间可能被已有区间完全包裹）。

    3. Merge Intervals（56）¶

    题面信号："合并所有重叠区间"。

    候选思路：按左端点排序 + 一次扫描。排序后"当前区间是否与上一个合并结果重叠"只需要比较一个端点。

    走一遍示例：intervals = [[1,3],[2,6],[8,10],[15,18]]

    res = [[1,3]]
[2,6]: 2 <= 3 → 合并 → [[1,6]]
[8,10]: 8 > 6 → 新区间 → [[1,6],[8,10]]
[15,18]: 15 > 10 → [[1,6],[8,10],[15,18]]

    关键细节：合并时必须 max(res[-1][1], end)——这是本题最经典的错误来源（[[1,10],[2,3]] 如果直接赋值会得到 [[1,3]]）。

    4. Non-overlapping Intervals（435）¶

    题面信号："最少删掉几个区间，使剩下的互不重叠"。

    候选思路：转化——删掉最少 = 保留最多 → 经典的活动选择问题 → 按右端点排序，每次选"最早结束且不冲突"的区间。

    为什么按右端点排序是对的（交换论证）：设最优解的第一个区间是 A，贪心选的是 B（B.end <= A.end）。把最优解里的 A 换成 B：B 不会和最优解里第二个区间冲突（因为 B.end <= A.end，A 都不冲突，B 更不会），后面的区间数量不变。所以"换过之后仍然是最优解"，贪心成立。

    走一遍示例：intervals = [[1,2],[2,3],[3,4],[1,3]]

    按右端点排序: [1,2], [2,3], [1,3], [3,4]
last_end=-inf → 选 [1,2]（count=1, last_end=2）
[2,3]: 2 >= 2 → 选（count=2, last_end=3）
[1,3]: 1 < 3 → 冲突，跳过
[3,4]: 3 >= 3 → 选（count=3, last_end=4）
答案 = 4 - 3 = 1 ✓（删掉 [1,3]）

    关键细节：必须按右端点排序；判断条件是 start >= last_end（首尾相接不算重叠）；答案是 n - count 而不是 count。

    5. Meeting Rooms II（253）¶

    题面信号："最少需要几间会议室" = "最多同时有几场会议"。

    候选思路：两种做法都要会。

    做法 A 扫描线：把区间拆成 \((\mathrm{start}, +1)\) 和 (end, -1) 两类事件，排序后累加 cur，最大值就是答案。同一时刻"结束"必须排在"开始"之前（半开区间约定）。

    做法 B 最小堆：按开始时间排序，堆里存"正在进行的会议的结束时间"；每场会议开始前把已经结束的弹出，堆的大小就是此刻同时进行的会议数。

    走一遍示例：intervals = [[0,30],[5,10],[15,20]]

    扫描线事件（排序后）: (0,+1) (5,+1) (10,-1) (15,+1) (20,-1) (30,-1)
cur: 1 → 2 → 1 → 2 → 1 → 0，最大值 2 ✓

    关键细节：堆解法里判断是 heap[0] <= start（带等号，结束时刻等于开始时刻可以复用）；扫描线里如果区间是闭区间，要把开始事件排在结束事件之前。

    6. Minimum Interval to Include Each Query（1851）¶

    题面信号："对每个查询点，找包含它的最短区间"。

    候选思路：对每个查询暴力扫所有区间是 \(\mathcal{O}(nq)\)。关键突破是"离线"——查询之间互相独立，所以可以把查询排序后一起处理，最后再按原顺序输出答案。

    算法：

    1. 区间按左端点排序；查询按数值排序（同时记录原始下标）
2. 用一个指针把"左端点 <= 当前查询"的区间压入最小堆（键是区间长度）
3. 把堆中"右端点 < 当前查询"的区间弹出（它们已经过期）
4. 堆顶就是覆盖该查询点的最短区间；堆空则为 -1

    为什么能 \(\mathcal{O}((n+q) \log n)\)？ 因为查询值是递增的，所以"区间的加入"和"区间的过期"都是单调的——每个区间最多进堆一次、出堆一次。

    走一遍示例：intervals = [[1,4],[2,3],[3,4]]，queries = [2,3,4]（排序后仍是 2,3,4）

    查询 2: 压入 [1,4]（长 4）、[2,3]（长 2）；堆顶长 2 → 答案 2
查询 3: 压入 [3,4]（长 2）；弹掉右端点 < 3 的（没有）→ 堆顶长 2 → 答案 2
查询 4: 弹掉右端点 < 4 的（[2,3]）→ 堆顶长 2（[3,4]）→ 答案 2

    关键细节：必须记录查询的原始下标（最后要按原顺序输出）；过期条件是 \(\mathrm{right} < q\)（严格小于，\(\mathrm{right} = q\) 时区间仍然覆盖）；堆里存 (长度, 右端点)。

    追问准备："为什么可以离线？" → 因为查询之间没有依赖；如果必须实时作答，就需要线段树等在线结构。

    六、复杂度速查¶

    题目 排序 key / 结构 时间
    Meeting Rooms 左端点 \(\mathcal{O}(n \log n)\)
    Insert Interval 已排序 \(\mathcal{O}(n)\)
    Merge Intervals 左端点 \(\mathcal{O}(n \log n)\)
    Non-overlapping Intervals 右端点 \(\mathcal{O}(n \log n)\)
    Meeting Rooms II 扫描线 / 堆 \(\mathcal{O}(n \log n)\)
    Minimum Interval to Include Query 离线 + 堆 \(\mathcal{O}(n \log n+q \log q+(n+q)\log (n+1))\)

    七、易错点速查¶

    1. 排序 key 选错（区间题失分的第一大原因）。
    2. 合并时忘记 max。
    3. 闭区间 / 半开区间的约定没确认，导致 \(<\) 与 \(\le\) 用错。
    4. 扫描线里同一时刻的先后没处理。
    5. 435 返回 count 而不是 n - count。
    6. 253 堆解法漏掉 \(\le\) 的等号，会议室数量算多。
    7. 1851 忘记记录查询的原始下标。

    八、面试话术¶

    "区间问题我一般先排序。这题要合并重叠区间，所以我按左端点排序；排序后一次线性扫描，如果当前区间的起点不超过上一个合并区间的终点，就合并（终点取较大者）。时间 \(\mathcal{O}(n \log n)\)（瓶颈在排序），空间 \(\mathcal{O}(n)\)。"

    九、30 秒自测¶

    1. 为什么"选择最多不重叠区间"按右端点排序，而"合并区间"按左端点排序？
    2. 扫描线做法里，为什么"结束"事件要排在"开始"事件之前？
    3. 合并区间时为什么终点要取 max？
    4. 闭区间和半开区间的差异会怎样影响答案？
    5. 1851 为什么可以"离线"处理查询？
