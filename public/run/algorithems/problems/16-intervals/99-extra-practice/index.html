    1. 1288 Remove Covered Intervals¶

    LeetCode 1288 ｜ Medium

    题目：删除所有"被其他区间完全覆盖"的区间，返回剩下的区间数。

    为什么放这里：排序 key 的巧妙运用——它需要"左端点升序、右端点降序"的双重排序。

    思路提示

    排序规则是：左端点升序；左端点相同时，右端点降序。

    为什么？因为这样排序后，"能覆盖别人的区间"一定排在"被覆盖的区间"前面。然后只需一次扫描，维护"目前为止见过的最大右端点 max_end"：

    • 如果当前区间的 end <= max_end → 它被覆盖了，不计入；
    • 否则 → 它是一个有效区间，更新 max_end。

    "左端点相同时右端点降序"是关键：否则长的那个区间会排在短的后面，导致漏判。

    方法辨析：同起点时先放长区间，才能让 max_end 在遇到短区间前已代表覆盖者。只按起点升序可能先把短区间计入且无法撤销；这与普通合并只取终点 max 的目标不同。

    class Solution:
    def removeCoveredIntervals(self, intervals: List[List[int]]) -> int:
        intervals.sort(key=lambda x: (x[0], -x[1]))    # 左升序，右降序
        count = 0
        max_end = 0

        for start, end in intervals:
            if end > max_end:                          # 没有被之前的区间覆盖
                count += 1
                max_end = end

        return count

    易错点：排序 key 必须是 (start, -end)；题目说"完全覆盖"包含相等的情形，所以判断用 <=（即 end > max_end 才计入）。

    复杂度：时间 O(n log n)，辅助空间 O(n)（Python 排序）。

    2. 986 Interval List Intersections¶

    LeetCode 986 ｜ Medium

    题目：给定两个各自有序且互不重叠的区间列表，求它们的交集。

    为什么放这里：双指针处理两个区间的标准模板，能练熟"求交集 / 判断重叠"的基本功。

    思路提示

    两个列表各用一个指针，每次比较当前的 [a_start, a_end] 和 [b_start, b_end]：

    交集 = [max(a_start, b_start), min(a_end, b_end)]
如果 max_start <= min_end → 有交集，记录下来
然后移动"结束时间更早"的那一个指针（因为其右端不晚于当前另一段右端，而另一列表的后续段从更右处才开始）

    "移动结束更早的那个"是本题的关键贪心：因为另一个区间的结束时间更晚，它还有机会和后面的区间相交。

    方法辨析：两列表各自互不重叠且有序，当前右端更小者不可能再与另一列表后续区间相交，所以可前移它。交集取左端较大、右端较小，闭区间有相等端点时仍输出一个单点交集。

    class Solution:
    def intervalIntersection(self, firstList: List[List[int]],
                             secondList: List[List[int]]) -> List[List[int]]:
        res = []
        i = j = 0
        while i < len(firstList) and j < len(secondList):
            a_start, a_end = firstList[i]
            b_start, b_end = secondList[j]

            start = max(a_start, b_start)
            end = min(a_end, b_end)
            if start <= end:                    # 有交集
                res.append([start, end])

            if a_end < b_end:                   # 移动结束更早的那个
                i += 1
            else:
                j += 1

        return res

    易错点：交集条件是 max(start) <= min(end)（带等号，单点交集也算）；必须移动结束更早的那个指针。

    复杂度：时间 O(m + n)，空间 O(1)（不计输出）。

    3. 646 Maximum Length of Pair Chain¶

    LeetCode 646 ｜ Medium

    题目：给定数对 [a, b]（a < b），若前一个的 b < 后一个的 a 就可以连成链，求最长链的长度。

    为什么放这里：435 Non-overlapping Intervals 的换壳题——"选的区间不能重叠"变成了"前一个的 b 必须严格小于后一个的 a"。

    思路提示：按右端点排序，然后贪心地选择"左端点大于上一个选中区间右端点"的区间。

    方法辨析：本题后一个左端必须严格大于前一个右端，所以连接条件为 >，与允许会议首尾衔接的 >= 不同。按最早结束交换仍成立，但等号不能随模板一起迁移。

    class Solution:
    def findLongestChain(self, pairs: List[List[int]]) -> int:
        pairs.sort(key=lambda p: p[1])          # 按右端点升序
        count = 0
        last_end = float('-inf')

        for a, b in pairs:
            if a > last_end:                    # 严格大于（不能相接）
                count += 1
                last_end = b

        return count

    易错点：条件是 a > last_end（严格大于，因为本题不允许相接），这和 435 的 start >= last_end 不同。

    复杂度：时间 O(n log n)，辅助空间 O(n)（Python 排序）。

    和 435 的对照：435 里 [1,2] 和 [2,3] 可以共存（相接不算重叠），本题里不行。这个细微差别正是"闭区间 vs 半开区间"约定的体现。

    4. 2406 Divide Intervals Into Minimum Number of Groups¶

    LeetCode 2406 ｜ Medium

    题目：把区间分成若干组，要求同组内任意两个区间不相交，求最少组数。

    为什么放这里：253 Meeting Rooms II 的换壳题——"最少会议室数"就是"最少组数"。唯一的区别是边界约定。

    思路提示：扫描线。本题的区间是闭区间 [left, right]，所以"一个区间在 5 结束，另一个在 5 开始"算作相交，不能放在同一组。

    于是排序时必须让"开始"排在"结束"之前（与 253 相反）。

    方法辨析：闭区间在右端点仍占用一组，把整数右端改成 right+1 的结束事件才表示下一时刻释放。这个转换利用端点为整数；连续时间可直接定义同点开始先于结束，不能任意加一改变长度。

    class Solution:
    def minGroups(self, intervals: List[List[int]]) -> int:
        events = []
        for left, right in intervals:
            events.append((left, 1))            # 开始
            events.append((right + 1, -1))      # 技巧：把结束推迟到 right+1
        events.sort()                           # 这样 -1 会排在下一个 +1 之前

        cur = ans = 0
        for _, delta in events:
            cur += delta
            ans = max(ans, cur)
        return ans

    关键技巧：把 right 替换成 right + 1，这样就把闭区间问题转化成了半开区间问题，实现了"同一时刻开始优先"。这是一个非常实用的转换技巧。

    易错点：闭区间要转成 right + 1；不能用 (time, -delta) 之类的排序魔法而不解释清楚。

    复杂度：时间 O(n log n)，空间 O(n)。

    5. 759 Employee Free Time¶

    LeetCode 759 ｜ Hard

    题目：给定每个员工的已排序工作区间列表，求所有员工的共同空闲时间。

    为什么放这里："合并所有区间，然后取空隙" 的典型应用，是区间合并的进阶练习。

    思路提示

    两步：

    1. 把所有员工的所有工作区间合并（合并后得到的是一段段"有人在忙"的时间）——因为员工内部的区间已经有序，可以用多路归并（k 个指针）或者直接把所有区间丢到一起排序；
    2. 合并后的相邻区间之间的空隙就是共同空闲时间。

    方法辨析：全体都空闲等于没有任何人在忙，即所有工作区间并集的补集；只返回并集内部有界的正长度空隙。不能分别求每人的空档后简单拼接，因为另一员工可能仍在工作。

    class Solution:
    def employeeFreeTime(self, schedule: '[[Interval]]') -> '[Interval]':
        # 把所有区间摊平并排序
        intervals = sorted((iv.start, iv.end) for emp in schedule for iv in emp)

        # 合并区间
        merged = [list(intervals[0])]
        for s, e in intervals[1:]:
            if s <= merged[-1][1]:
                merged[-1][1] = max(merged[-1][1], e)
            else:
                merged.append([s, e])

        # 相邻合并区间之间的空隙就是答案
        res = []
        for i in range(1, len(merged)):
            res.append(Interval(merged[i - 1][1], merged[i][0]))
        return res

    易错点：合并时终点取 max；空隙是"前一个的 end 到后一个的 start"（本题允许端点相接，即 [1,3] 和 [3,5] 之间没有空隙）。

    复杂度：时间 O(N log N)（N 为区间总数），空间 O(N)。

    更优的写法：利用"每个员工的列表已经有序"这一条件，用一个大小为 k 的最小堆做 k 路归并，复杂度 O(N log k)。面试中能主动提出这一点很加分。

    6. 732 My Calendar III¶

    LeetCode 732 ｜ Hard

    题目：设计一个日历，每次 book(start, end) 加入一个半开区间 [start, end)，并返回当前所有区间里同时重叠的最大数量。

    为什么放这里：动态扫描线的代表——不是算一次，而是每次插入后都要报出当前的"最大重叠数"。

    思路提示

    用有序字典（或 SortedDict）维护"时间点 → 覆盖次数的变化量"：

    • book 时：diff[start] += 1，diff[end] -= 1；
    • 然后按时间顺序遍历整个字典，累加 cur，取最大值。

    这个版本每次对至多 O(n) 个差分端点重新排序并扫描，第 n 次调用 O(n log n)，n 次总成本上界 O(n² log n)。是否满足时限需结合调用规模判断。

    更优的做法是使用带子树和与最大前缀和的增强平衡树，或维护覆盖峰值的线段树。只有排序容器并不能自动将每次查询峰值降到对数。

    方法辨析：差分记录的是各端点的净增减，按顺序累加的最大前缀和就是重叠峰值。普通字典每次重新排序可得到正确结果，但排序不免费；要让在线更新高效，需维护区间覆盖或增强树的聚合摘要。

    from sortedcontainers import SortedDict        # LeetCode 支持该第三方库

class MyCalendarThree:
    def __init__(self):
        self.diff = SortedDict()

    def book(self, startTime: int, endTime: int) -> int:
        self.diff[startTime] = self.diff.get(startTime, 0) + 1
        self.diff[endTime] = self.diff.get(endTime, 0) - 1

        cur = ans = 0
        for delta in self.diff.values():           # 按时间顺序累加
            cur += delta
            ans = max(ans, cur)
        return ans

    如果不方便使用 SortedDict，也可以用普通字典 + 每次 sorted(self.diff) 遍历，效果相同。

    易错点：区间是半开区间（end 处减 1，意味着 end 时刻不占用）；每次 book 都要重新扫描一遍求最大值（因为历史上插入的区间会影响当前的最大重叠）。

    复杂度：时间最坏 O(n² log n)（n 次插入，每次重新排序端点），空间 O(n)。

    进阶：用线段树维护"区间加 + 全局最大值"，可以做到 O(log n) 每次插入。面试中能说出这个优化方向就足够了。
