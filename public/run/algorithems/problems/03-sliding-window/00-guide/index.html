    Sliding Window · 解题手册¶

    滑动窗口是双指针的特化版本：右指针扩张、左指针收缩，窗口内维护一份可增量更新的状态。它能成立的前提只有一个——窗口的"合法性"对收缩是单调的（子窗口一定也合法）。面试时把这句话说出来，整套推理就站住了。

    一、从题面提出候选，再核对条件¶

    已学基础：05-双指针与滑动窗口。下面将讲义中的结构性质用于选择解法。

    连续性只说明可以表示一个区间；还要检查何时能永久丢弃左端、窗口状态能否增量更新。固定窗口与可变窗口的依据不同。

    题目特征 需要验证的依据 迁移边界与反例
    固定长度 k 的区间统计 每次加入一项、移出一项，长度固定 含负数也不妨碍维护固定窗口和
    最长不超过某限制的区间 删除不会使约束更坏，扩张不能修复已超限的旧起点 非负和不大于K、无重复满足；一般含负数的和约束不满足
    最短覆盖区间 扩张补足要求，合法时逐次移左端并记录候选 合法性方向与最长无重复窗口相反
    窗口最值 用下标队列记录未过期且未被支配的候选 存在负数不影响单调队列

    普通合法窗口在记录答案时应满足约束。字符替换题的历史最高频数版是另外需要证明的变式，不能把其临时不合法的窗口状态迁移到最短覆盖等题。

    二、两种窗口 + 一个决定成败的细节¶

    固定长度窗口¶

    def fixed_window(s, k):
    res = []
    for r in range(len(s)):
        # 1. 把 s[r] 加入窗口状态
        if r >= k:
            pass                 # 2. 把 s[r-k] 移出窗口状态
        if r >= k - 1:
            res.append(r - k + 1)   # 3. 此时窗口正好是 [r-k+1, r]
    return res

    可变长度窗口¶

    def variable_window(nums):
    l = 0
    best = 0
    for r in range(len(nums)):
        # 1. 加入 nums[r]
        while 窗口不合法:
            pass                 # 2. 移出 nums[l]，l += 1
        best = max(best, r - l + 1)     # 3. 收缩之后再更新答案
    return best

    那个决定成败的细节¶

    要求 更新答案的位置
    最长合法窗口 while 之后（此时窗口一定合法）
    最短合法窗口 while 内部（收缩过程本身就在产生合法窗口）

    位置写反是这一类题最常见的失分点。 记法：求最长——先收缩到合法再记录；求最短——边收缩边记录。

    三、为什么右指针不需要回退¶

    左右指针不回退，需要按问题分别证明，不能只凭“区间连续”。

    • 最长合法窗口：若某个起点在当前右端已超限，继续向右扩张也不能修复它，就可以永久移走这个起点。无重复、至多 k 种字符等约束满足此性质；恢复合法后记录当前右端的最长窗口。
    • 最短覆盖窗口：右端扩张前，左边已经移走的每个起点都曾得到一个合法候选。以后用同样起点配更远右端只会更长，不会改善答案；因此合法时收缩并逐个记录即可。
    • 固定窗口：端点位置由固定长度决定，不要求数值和随扩张单调。

    两个指针各移动至多 n 次，仅保证窗口增删次数 \(\mathcal{O}(n)\)；总时间还取决于每次状态更新、合法性检查的成本。

    四、从读题到写码：五步流程¶

    1. 确认连续性：题目问的是"连续子数组/子串"吗？（不是"子序列"）
    2. 确认单调性：窗口变大时，条件会单调变差吗？如果不会（例如含负数求和），改用前缀和。
    3. 确定窗口类型：固定长度还是可变长度？
    4. 确定要维护的状态：和？计数表？不同元素个数？最值（要单调队列）？
    5. 确定答案更新位置：求最长还是最短？

    五、四个常用模板与使用条件¶

    模板 1 计数表可增量更新（不要每轮重建 Counter）¶

    from collections import defaultdict

def count_window(s):
    window = defaultdict(int)
    l = 0
    for r, c in enumerate(s):
        window[c] += 1              # 增量加入
        while 窗口不合法:
            window[s[l]] -= 1       # 增量移除
            if window[s[l]] == 0:
                del window[s[l]]    # 删掉零计数，len(window) 才是"不同字符数"
            l += 1

    如果每轮重建 Counter(s[l:r+1])，复杂度会悄悄变成 \(\mathcal{O}(n^{2})\)。

    模板 2 覆盖型最短窗口（Minimum Window Substring）¶

    from collections import Counter

def min_window(s, t):
    if not s or not t:
        return ""
    need = Counter(t)
    window = {}
    have = 0
    required = len(need)
    best_len = float("inf")
    res = ""
    l = 0
    for r, c in enumerate(s):
        window[c] = window.get(c, 0) + 1
        if c in need and window[c] == need[c]:
            have += 1                      # 这个字符刚好达标（用 == 而不是 >=）
        while have == required:
            if r - l + 1 < best_len:       # 求最短：在 while 内部更新
                best_len = r - l + 1
                res = s[l:r + 1]
            d = s[l]
            window[d] -= 1
            if d in need and window[d] < need[d]:
                have -= 1                  # 不再达标
            l += 1
    return res

    have 统计的是"达标的字符种类数"，不是字符总数；加入时用 \(=\)、移除时用 \(<\)，两个方向不能写反。

    模板 3 单调队列求窗口最值¶

    from collections import deque

def max_sliding_window(nums, k):
    dq = deque()                 # 存下标，对应值单调递减
    res = []
    for r, x in enumerate(nums):
        while dq and nums[dq[-1]] <= x:
            dq.pop()             # 队尾更小的元素被 x 淘汰，不可能再当最大值
        dq.append(r)
        if dq[0] <= r - k:       # 队首滑出窗口
            dq.popleft()
        if r >= k - 1:
            res.append(nums[dq[0]])
    return res

    模板 4 滑动窗口计数（以右端点为锚）¶

    def num_subarrays(nums, k):
    l = 0
    cur = 1
    count = 0
    for r, x in enumerate(nums):
        cur *= x
        while cur >= k:
            cur //= nums[l]
            l += 1
        count += r - l + 1        # 以 r 结尾的合法子数组个数
    return count

    "以 r 结尾的合法子数组恰好有 \(r - l + 1\) 个" 这个计数技巧在子数组计数类题里反复出现。

    六、逐题推演：从题面到思路¶

    1. Best Time to Buy and Sell Stock（121）¶

    题面信号：只能买一次卖一次，求最大利润。

    候选思路：这是滑动窗口的退化形式——"左指针永远指向历史最低价"。

    关键观察：如果在第 i 天卖出，最优买入价就是第 i 天之前出现过的最低价。所以只需一次遍历，边更新最低价边算利润。

    走一遍示例：\(\mathrm{prices} = [7,1,5,3,6,4]\)

    天 价格 历史最低 今日利润 最优
    0 7 7 0 0
    1 1 1 0 0
    2 5 1 4 4
    3 3 1 2 4
    4 6 1 5 5
    5 4 1 3 5

    关键细节：best 初始化为 0（允许"不交易"），这样单调下跌的数组会正确返回 0。

    追问准备：能多次交易 → 122（贪心：累加所有上涨段）；含冷冻期 → 309（状态机 DP）；最多 k 次 → 188。

    2. Longest Substring Without Repeating Characters（3）¶

    题面信号：最长、连续、无重复子串。

    候选思路：可变长度窗口求最长。窗口内维护"字符出现情况"，出现重复就收缩左边界。

    走一遍示例：s = "abcabcbb"

    r 字符 窗口 最大长度
    0-2 a,b,c abc 3
    3 a（重复） 收缩到 bca 3
    4 b（重复） 收缩到 cab 3
    5 c（重复） 收缩到 abc 3
    6 b（重复） 收缩后长度 3 3
    7 b（重复） 收缩后长度 3 3

    答案是 3。

    关键细节：用哈希表记"最近下标"的写法里，更新左指针必须写 l = max(l, last[c] + 1)——max 不能省。反例："abba" 处理第二个 a 时 last['a'] = 0，直接写 l = 1 会把左指针从 2 退回 1。

    3. Longest Repeating Character Replacement（424）¶

    题面信号："最多替换 k 个字符，使子串全为同一字符，求最长子串"。

    候选思路：把问题翻译成"窗口合法性"——把窗口变成全同一字符，需要替换的次数是

    窗口长度 - 窗口内出现次数最多的那个字符的次数

    于是合法性条件是 (r - l + 1) - max_count <= k。

    走一遍示例：s = "AABABBA"，k = 1

    窗口 长度 最高频字符次数 需要替换 合法？
    AAB 3 A 出现 2 1 合法
    AABA 4 A 出现 3 1 合法
    AABAB 5 A 出现 3 2 不合法 → 收缩

    最终答案是 4。

    关键细节：先掌握每轮重新求真实 max(count)、收缩到合法的写法。保留历史最高频数的版本可能让当前窗口暂时不合法，需另证明它不会制造更长虚假纪录，见本题详解，不能只凭“条件更宽松”接受。

    同结构题：1004 Max Consecutive Ones III（窗口长度 - 1 的个数 不大于 k）。

    4. Permutation in String（567）¶

    题面信号："s2 中是否包含 s1 的某个排列作为连续子串"。

    候选思路：是"连续子串"+"字符频率相同" → 固定长度窗口 + 频率表比较。

    走一遍示例：s1 = "ab"，s2 = "eidbaooo"，窗口长度固定为 2

    窗口 "ei" → 计数 {e:1,i:1} ≠ {a:1,b:1}
窗口 "id" → 不匹配
窗口 "db" → 不匹配
窗口 "ba" → {b:1,a:1} 匹配 → True

    关键细节：s1 里可能有重复字符，所以必须用计数而不是集合；用 Counter 比较时，移除元素后要 del 掉零计数的键，否则比较会失败。

    5. Minimum Window Substring（76）¶

    题面信号："最短的、包含 t 全部字符（含重复次数）的子串"。

    候选思路：可变长度窗口求最短 → 答案必须在 while 收缩循环内部更新。

    难点：怎么 \(\mathcal{O}(1)\) 判断"窗口已经覆盖 t"？→ need / window 两张表 + have 计数器。

    走一遍示例：s = "ADOBECODEBANC"，t = "ABC"，required = 3

    r 一路扩张，直到窗口 "ADOBEC" 首次让 have == 3
→ 进入收缩循环：记录长度 6，移出 'A'，have 降到 2，退出
r 继续扩张到 "ADOBECODEBA" ... 直到 "ADOBECODEBANC" 中再次达标
→ 反复收缩，最终得到 "BANC"（长度 4）

    关键细节：have == required 时才进入收缩；t 里重复的字符必须计数（"AA" 要求窗口里有两个 A）。

    6. Sliding Window Maximum（239）¶

    题面信号："每个固定长度窗口的最大值"。

    候选思路：窗口最值 → 单调队列。普通队列拿不到最大值；每次重扫窗口是 \(\mathcal{O}(nk)\)。

    单调队列的淘汰依据：如果 \(\mathrm{nums}[j] \le \mathrm{nums}[i]\) 且 \(j < i\)，那么任何包含 j 的窗口都包含 i，j 永远不可能成为最大值，可以直接丢掉。

    走一遍示例：\(\mathrm{nums} = [1,3,-1,-3,5,3,6,7]\)，k = 3

    r=0: 队列 [0(1)]
r=1: 3 比队尾的 1 大 → 弹出 0，队列 [1(3)]
r=2: 队列 [1(3), 2(-1)]，窗口成形 → 最大值 3
r=3: 队列 [1(3), 2(-1), 3(-3)] → 最大值 3
r=4: 5 淘汰前面全部 → 队列 [4(5)] → 最大值 5
... 最终 [3,3,5,5,6,7]

    关键细节：队列存下标（不是值），否则无法判断是否滑出窗口；过期判断写成 \(dq[0] \le r - k\)；先入队再清理队首。

    七、复杂度速查¶

    题目 窗口类型 维护状态 时间
    Best Time to Buy/Sell Stock 可变 历史最小值 \(\mathcal{O}(n)\)
    Longest Substring w/o Repeating 可变（最长） 字符集合 / 最近下标 \(\mathcal{O}(n)\)
    Longest Repeating Char Replacement 可变（最长） 频次 + 最高频 \(\mathcal{O}(n)\)
    Permutation in String 固定 频次表 \(\mathcal{O}(n)\)
    Minimum Window Substring 可变（最短） 频次 + have \(\mathcal{O}(n)\)
    Sliding Window Maximum 固定 单调队列 \(\mathcal{O}(n)\)

    八、易错点速查¶

    1. 求最长 / 最短的答案更新位置写反。
    2. 忘记移除左指针处的状态，窗口状态和实际窗口不一致。
    3. 窗口长度写成 r - l（正确是 \(r - l + 1\)）。
    4. 每轮重建 Counter，复杂度退化成 \(\mathcal{O}(n^{2})\)。
    5. .get(c, 0) 之外的零计数键没删，导致 len(window) 不变而死循环。
    6. have 的更新用 \(=\) 和 \(<\)，两个方向写反。
    7. 含负数还硬用滑窗求和。
    8. 单调队列存值不存下标。

    九、面试话术¶

    "这是一个连续子串问题，我用滑动窗口。右指针不断扩张，当窗口不再满足条件时移动左指针收缩。由于'窗口合法'这个性质对收缩是单调的——子窗口一定也合法——所以两个指针都只向右移动，总复杂度 \(\mathcal{O}(n)\)。窗口内我用一个长度 26 的计数数组维护字符频次，加入和移除都是 \(\mathcal{O}(1)\)。"

    十、30 秒自测¶

    1. 为什么滑窗求最长和求最短的"更新答案"位置不同？
    2. 424 里 max_count 为什么可以在收缩时不更新？
    3. 76 为什么要维护 have 而不是每轮比较两个 Counter？
    4. 239 为什么必须用单调队列而不是普通队列？
    5. 什么情况下"和为 k 的子数组"不能用滑动窗口？
