    1. 463 Island Perimeter¶

    LeetCode 463 ｜ Easy

    题目：网格中恰好有一个岛屿，求它的周长。

    为什么放这里：网格遍历的最简应用，而且它有一个不需要 DFS 的巧妙公式。

    思路提示（方案 A）：遍历每个陆地格子，数它的四条边里有多少条"挨着水或出界"，累加起来就是周长。

    思路提示（方案 B，更妙）：

    周长 = 4 × 陆地格数 − 2 × 相邻的陆地边数

    因为每块陆地默认贡献 4 条边，每有一对相邻的陆地，就有 2 条边被"合并"掉了。只统计向右、向下两个方向即可避免重复计数。

    方法辨析：周长按边计数而非岛屿节点数，内部相邻边不贡献外露边界。每块陆地先加四、每条无向相邻关系减二，与逐边判断水或出界等价；只查右、下是为了每条相邻关系只扣一次。

    class Solution:
    def islandPerimeter(self, grid: List[List[int]]) -> int:
        ROWS, COLS = len(grid), len(grid[0])
        land = adjacent = 0
        for r in range(ROWS):
            for c in range(COLS):
                if grid[r][c] == 1:
                    land += 1
                    if r + 1 < ROWS and grid[r + 1][c] == 1:
                        adjacent += 1          # 下方相邻
                    if c + 1 < COLS and grid[r][c + 1] == 1:
                        adjacent += 1          # 右方相邻
        return 4 * land - 2 * adjacent

    易错点：只统计两个方向（右、下），统计四个方向会重复计算相邻边。

    复杂度：时间 O(mn)，空间 O(1)。

    2. 547 Number of Provinces¶

    LeetCode 547 ｜ Medium

    题目：给定邻接矩阵，求连通分量（省份）的个数。

    为什么放这里：323 的邻接矩阵输入版。它提醒你："图的表示方式会影响代码，但算法思想不变。"

    思路提示：和 323 完全一样，只是把边列表换成矩阵遍历。

    方法辨析：输入是邻接矩阵，节点仍是城市，每次从未访问城市启动遍历才新增一省。即使图很稀疏，扫描矩阵仍可能花 O(n²)，不能将邻接表 O(V+E) 的结论直接忽略表示成本。

    class Solution:
    def findCircleNum(self, isConnected: List[List[int]]) -> int:
        n = len(isConnected)
        visited = [False] * n
        count = 0

        def dfs(i: int) -> None:
            visited[i] = True
            for j in range(n):
                if isConnected[i][j] == 1 and not visited[j]:
                    dfs(j)

        for i in range(n):
            if not visited[i]:
                count += 1
                dfs(i)
        return count

    并查集版同样适用：遍历矩阵的上三角，遇到 1 就 union(i, j)，最后统计根节点的个数。

    易错点：邻接矩阵是无向的（对称），遍历时可以只扫上三角来加速，但正确性上扫描全矩阵也没问题。

    复杂度：时间 O(n²)，空间 O(n)。

    3. 542 01 Matrix¶

    LeetCode 542 ｜ Medium

    题目：给定 0/1 矩阵，返回每个格子到最近的 0 的距离。

    为什么放这里：多源 BFS 的第三个成员（我们一起对比 994、286、542）。

    思路提示：把所有 0 当作源点同时入队，BFS 逐层扩展，每个格子的距离就是它第一次被访问时的层数。

    关键点：直接从每个 1 出发找最近的 0 是 O((mn)²)；从所有 0 同时出发是 O(mn)。这就是"多源 BFS = 反向搜索"的价值。

    方法辨析：所有零作为距离零的源点，第一次发现的格子已有到最近零的最短距离。此图邻接无方向，反向视角不改变边；多源 BFS 与反向搜索是两个可结合的想法，不是任何场景都等价。

    from collections import deque

class Solution:
    def updateMatrix(self, mat: List[List[int]]) -> List[List[int]]:
        ROWS, COLS = len(mat), len(mat[0])
        dist = [[-1] * COLS for _ in range(ROWS)]     # -1 表示未访问
        q = deque()

        for r in range(ROWS):
            for c in range(COLS):
                if mat[r][c] == 0:
                    dist[r][c] = 0
                    q.append((r, c))

        while q:
            r, c = q.popleft()
            for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                nr, nc = r + dr, c + dc
                if 0 <= nr < ROWS and 0 <= nc < COLS and dist[nr][nc] == -1:
                    dist[nr][nc] = dist[r][c] + 1     # 第一次访问就是最短距离
                    q.append((nr, nc))

        return dist

    易错点：用 dist == -1 同时充当"未访问"标记；不要在 mat 上就地修改（必要时需保留原矩阵）。

    复杂度：时间 O(mn)，空间 O(mn)。

    4. 841 Keys and Rooms¶

    LeetCode 841 ｜ Medium

    题目：房间 0 是起点，每个房间里有若干把钥匙（能打开对应房间）。判断能否访问所有房间。

    为什么放这里：有向图的可达性最纯粹的形态，用来巩固"visited + 遍历"这个基本套路。

    思路提示：从房间 0 出发做 DFS/BFS，最后检查访问过的房间数是否等于 n。

    方法辨析：钥匙给出一条有向可达关系，拿到房间 j 的钥匙并不代表 j 能回到当前房间。只从 0 开始遍历即可，若对每个未访问房间另起搜索，就会把本来进不去的区域也错误视为可访问。

    class Solution:
    def canVisitAllRooms(self, rooms: List[List[int]]) -> bool:
        visited = {0}
        stack = [0]
        while stack:
            room = stack.pop()
            for key in rooms[room]:
                if key not in visited:
                    visited.add(key)
                    stack.append(key)
        return len(visited) == len(rooms)

    易错点：房间 0 要预先标记为已访问（否则可能重复入栈）；len(rooms) 就是房间总数。

    复杂度：时间 O(V + E)，空间 O(V)。

    5. 1254 Number of Closed Islands¶

    LeetCode 1254 ｜ Medium

    题目：网格中 0 表示陆地、1 表示水，求完全被水包围的岛屿数量（不接触边界）。

    为什么放这里：与 130 Surrounded Regions 是同一思路的"计数版"——先干掉所有与边界相连的陆地，再数剩下的连通块。

    思路提示

    1. 从四条边界上的所有 0 出发做 DFS/BFS，把它们和连通的 0 全部"淹掉"（标成 1）；
    2. 剩下的 0 就是"封闭岛屿"，用 200 题的方法数个数。

    方法辨析：边界连通块先被排除，剩下每次启动遍历对应一个封闭岛。这里 0 是陆地、1 是水，与 Number of Islands 的表示相反；复用遍历代码前先改判断条件，不能只改函数名。

    class Solution:
    def closedIsland(self, grid: List[List[int]]) -> int:
        ROWS, COLS = len(grid), len(grid[0])

        def flood(r: int, c: int) -> None:
            if not (0 <= r < ROWS and 0 <= c < COLS) or grid[r][c] != 0:
                return
            grid[r][c] = 1                       # 淹掉
            flood(r + 1, c)
            flood(r - 1, c)
            flood(r, c + 1)
            flood(r, c - 1)

        for r in range(ROWS):                    # 边界上的陆地都要淹掉
            flood(r, 0)
            flood(r, COLS - 1)
        for c in range(COLS):
            flood(0, c)
            flood(ROWS - 1, c)

        count = 0
        for r in range(ROWS):                    # 剩下的 0 就是封闭岛屿
            for c in range(COLS):
                if grid[r][c] == 0:
                    count += 1
                    flood(r, c)
        return count

    易错点：两个阶段的 flood 用的是同一个函数；第二阶段要遍历内部所有格子而不是只遍历边界。

    复杂度：时间 O(mn)，空间 O(mn)（递归栈）。

    6. 802 Find Eventual Safe States¶

    LeetCode 802 ｜ Medium

    题目：有向图中，如果一个节点出发的所有路径最终都到达出度为 0 的节点，它就是"安全节点"。返回所有安全节点。

    为什么放这里：拓扑排序的"反向"应用——它把"从终点倒推"这个思路讲得非常清楚。

    思路提示（正向思考很难）：一个节点安全 ⟺ 它不能到达任何环。

    思路提示（反向拓扑排序，巧妙）：

    1. 把有向图反向（原来 u → v 变成 v → u）；
    2. 统计出度（原图）；
    3. 把所有出度为 0 的节点入队（它们显然是安全的）；
    4. 每次取出一个安全节点 v，把反向图中指向它的 u 的出度减 1——如果 u 的出度变成 0，说明 u 的所有出边都通向安全节点，于是 u 也安全，入队；
    5. 最终所有入过队的节点就是答案。

    方法辨析：一个安全节点的所有后继都应安全，仅有一条通往终点的路并不够。反图队列从原出度零的终点开始，直到某前驱的全部未处理出边都被消去才加入，表达的是“所有选择都终止”。

    from collections import deque

class Solution:
    def eventualSafeNodes(self, graph: List[List[int]]) -> List[int]:
        n = len(graph)
        reverse = [[] for _ in range(n)]
        outdeg = [0] * n

        for u in range(n):
            for v in graph[u]:
                reverse[v].append(u)          # 反向边
                outdeg[u] += 1

        q = deque(i for i in range(n) if outdeg[i] == 0)
        safe = []
        while q:
            v = q.popleft()
            safe.append(v)
            for u in reverse[v]:
                outdeg[u] -= 1
                if outdeg[u] == 0:
                    q.append(u)

        return sorted(safe)

    易错点：用的是出度而不是入度（这和 207 正好相反，是本题最需要理解的地方）；结果要排序。

    复杂度：时间 O(V + E)，空间 O(V + E)。

    7. 310 Minimum Height Trees¶

    LeetCode 310 ｜ Medium

    题目：给定一棵树，找出所有"以它为根时树高最小"的节点。

    为什么放这里：拓扑排序的"剥叶子"变体——一个非常漂亮的应用，能让你更深刻地理解"度"这个概念。

    思路提示

    树的最小高度根是树的中心（使到最远节点的距离最小，最多两个）。重心优化的是删根后的最大分量大小，是另一个概念。求中心可用逐层剥掉所有叶子节点：

    1. 把所有度为 1 的节点（叶子）入队；
    2. 反复"剥掉"当前的叶子层，同时让相邻节点的度减 1；
    3. 当剩下节点数 ≤ 2 时停止——剩下的就是答案。

    每轮同时去掉全部叶子，相当于将最长路径的两端各缩短一条边，保留其中点。最后剩 1 个或 2 个中心，取决于树的直径边数是偶数还是奇数，与总节点数的奇偶无必然关系；四节点星形树就只有一个中心。

    方法辨析：最小高度等于根到最远点的最小可能距离，中心位于直径中间。每轮要同时剥掉整层叶子，不能边删边把新叶子在同一轮继续删尽；两中心对应直径中间一条边，不由总节点数奇偶决定。

    from collections import deque, defaultdict

class Solution:
    def findMinHeightTrees(self, n: int, edges: List[List[int]]) -> List[int]:
        if n == 1:
            return [0]                        # 特例：只有一个节点

        graph = defaultdict(list)
        degree = [0] * n
        for a, b in edges:
            graph[a].append(b)
            graph[b].append(a)
            degree[a] += 1
            degree[b] += 1

        leaves = deque(i for i in range(n) if degree[i] == 1)
        remaining = n

        while remaining > 2:
            layer = len(leaves)               # 一次剥掉一整层
            remaining -= layer
            for _ in range(layer):
                leaf = leaves.popleft()
                for nxt in graph[leaf]:
                    degree[nxt] -= 1
                    if degree[nxt] == 1:
                        leaves.append(nxt)

        return list(leaves)

    易错点：n == 1 要特判；必须一层一层剥（用 len(leaves) 锁定当前层的数量），不能每轮只剥一个。

    复杂度：时间 O(V)，空间 O(V)。

    8. 990 Satisfiability of Equality Equations¶

    LeetCode 990 ｜ Medium

    题目：给定形如 "a==b"、"a!=b" 的等式集合，判断是否自洽。

    为什么放这里：并查集的"分组"应用，而且它不是网格也不是图——能让你体会"并查集是一种通用的等价关系工具"。

    思路提示

    分两步，顺序很关键：

    1. 先处理所有 ==：把相等的变量合并到同一集合（它们构成"等价类"）；
    2. 再检查所有 !=：如果发现两个变量在同一个集合里，说明矛盾，返回 False。

    为什么必须先处理 ==？ 因为 a==b、b==c、a!=c 这种矛盾只有在合并完成后才能被发现。

    方法辨析：相等关系可传递，先合并完等式才能准确知道哪些变量被迫相同。不等式不是反向可合并关系，a≠b 且 b≠c 不推出 a=c 或 a≠c，只能在等价类完成后逐条检查冲突。

    class Solution:
    def equationsPossible(self, equations: List[str]) -> bool:
        parent = list(range(26))              # 用 0-25 表示 'a'-'z'

        def find(x):
            while parent[x] != x:
                parent[x] = parent[parent[x]]
                x = parent[x]
            return x

        for eq in equations:                  # 第一步：处理所有 ==
            if eq[1] == '=':
                a, b = ord(eq[0]) - 97, ord(eq[3]) - 97
                parent[find(a)] = find(b)

        for eq in equations:                  # 第二步：检查所有 !=
            if eq[1] == '!':
                a, b = ord(eq[0]) - 97, ord(eq[3]) - 97
                if find(a) == find(b):
                    return False

        return True

    易错点：两轮遍历的顺序不能颠倒；字符到下标的映射 ord(c) - ord('a')。

    复杂度：时间 O(n · α(26)) ≈ O(n)，空间 O(1)。
