    Greedy · 解题手册¶

    贪心的难点从来不是写代码，而是证明"局部最优能推出全局最优"。需要找到交换、支配、强制选择等依据；证明暂时找不到时，应重新检查策略或考虑其他算法。面试里"为什么这样贪心是对的"这个问题，比代码本身更重要。

    一、从题面提出候选，再核对条件¶

    已学基础：24-贪心算法。下面将讲义中的结构性质用于选择解法。

    贪心需要证明当前决定不会排除整体最优。排序、堆、一趟扫描只是实现工具，不能替代安全选择依据。

    题目特征 需要验证的依据 迁移边界与反例
    区间数量最大 最早结束选择可用交换论证 不同收益的带权区间不能直接套用
    跳跃覆盖 可达位置确为前缀时只存最远右界 必须恰好跳指定步数时可能有空洞
    失败后排除一段候选 找出被排除者不可能比当前失败者更好 加油站依赖首次断油前的前缀累计非负
    用范围合并很多可能状态 证明可行状态集合无空洞且变换后仍连续 只有最大最小界不代表中间状态都可达

    先给策略找反例，再尝试交换、支配或覆盖范围证明。某个贪心策略失败并不自动说明必须 DP，也可能换一种贪心依据；应回到目标与状态结构重新判断。

    二、贪心 vs DP：怎么判断¶

    维度 贪心 DP
    决策方式 证明某个当前选择安全后固定它 按状态合并历史，比较足够的候选转移
    复杂度 取决于选择与维护成本 状态数×每状态转移成本，也可能 O(n)
    正确性依据 需要证明贪心选择性质 + 最优子结构 由状态定义和转移保证

    判断方法：把贪心策略丢到一个小反例上试。 一个反例足以否定当前策略，却不能否定其他贪心策略；下一步根据问题结构评估 DP、搜索或其他方法。

    一个经典反例：Coin Change（322）用"每次选最大硬币"的贪心会错——coins = [1,3,4]、amount = 6 时贪心得 3 枚，最优是 2 枚。

    三、六种常见贪心模式¶

    模式 1 一次遍历维护最优状态（Kadane）¶

    def max_subarray(nums):
    best = cur = nums[0]
    for x in nums[1:]:
        cur = max(x, cur + x)         # 要么接着之前，要么重新开始
        best = max(best, cur)
    return best

    "重新开始"的依据：一旦 cur < 0，它对未来只有坏处。

    模式 2 维护最远可达位置¶

    def can_jump(nums):
    farthest = 0
    for i, step in enumerate(nums):
        if i > farthest:              # 到不了这里
            return False
        farthest = max(farthest, i + step)
    return True

    模式 3 排序后贪心¶

    def min_arrows(points):
    if not points:
        return 0
    points.sort(key=lambda p: p[1])   # 按右端点升序
    arrows = 1
    end = points[0][1]
    for start, e in points[1:]:
        if start > end:               # 这支箭射不到它
            arrows += 1
            end = e
    return arrows

    模式 4 用"最远边界"切分区间¶

    def partition_labels(s):
    last = {c: i for i, c in enumerate(s)}
    res = []
    start = end = 0
    for i, c in enumerate(s):
        end = max(end, last[c])       # 右边界只能扩大
        if i == end:                  # 到达边界，可以切一刀
            res.append(end - start + 1)
            start = i + 1
    return res

    模式 5 用"区间"维护状态集合¶

    def check_valid_string(s):
    lo = hi = 0                       # 未匹配左括号数量的可能范围
    for c in s:
        if c == "(":
            lo, hi = lo + 1, hi + 1
        elif c == ")":
            lo, hi = lo - 1, hi - 1
            if hi < 0:
                return False
        else:                         # '*'
            lo, hi = lo - 1, hi + 1   # 当成 ')' 就是 lo-1，当成 '(' 就是 hi+1
        lo = max(lo, 0)
    return lo == 0

    模式 6 全局记账¶

    def can_complete_circuit(gas, cost):
    total = cur = start = 0
    for i in range(len(gas)):
        diff = gas[i] - cost[i]
        total += diff
        cur += diff
        if cur < 0:                   # 从 start 出发到这里就断油
            start = i + 1             # 起点必须更靠后
            cur = 0
    return start if total >= 0 else -1

    四、从读题到写码：四步流程¶

    1. 先想"每步的最优选择是什么"，再问"这个选择会不会影响后面的最优性"。
    2. 试着构造反例：如果构造出来了，改用 DP。
    3. 确定排序的 key（如果要排序）：区间类问题通常按右端点排序。
    4. 写出贪心的论证（交换论证 / 归纳 / 下界），这是面试的得分点。

    五、逐题推演：从题面到思路¶

    1. Maximum Subarray（53）¶

    题面信号："和最大的连续子数组"。

    候选思路：维护"以当前位置结尾的最大和"cur。对每个新元素只有两个选择：接在前面（cur + x）或重新开始（x）。当 cur < 0 时重新开始，因为负前缀只会拖累后面。

    走一遍示例：nums = [-2,1,-3,4,-1,2,1,-5,4]

    i x cur best
    0 -2 -2 -2
    1 1 1 1
    2 -3 -2 1
    3 4 4 4
    4 -1 3 4
    5 2 5 5
    6 1 6 6
    7 -5 1 6
    8 4 5 6

    关键细节：best 和 cur 都初始化为 nums[0]（数组可能全是负数，答案是负的）；不能写成 cur = max(0, cur + x)（那在全负数时返回 0）。答案是 best 而不是 cur。

    2. Jump Game（55）¶

    题面信号："每个位置最多能跳几步，判断能否到终点"。

    候选思路：维护"能到达的最远位置"farthest。为什么贪心成立？ 因为可达性具有"前缀封闭"的性质——如果位置 i 可达，那么所有 j < i 都可达，所以遍历到 i 时"i 之前所有位置的跳跃范围"已经全部合并进 farthest 了。

    走一遍示例：nums = [2,3,1,1,4]

    i=0: farthest = max(0, 0+2) = 2
i=1: 1 <= 2 ✓，farthest = max(2, 1+3) = 4
i=2: 2 <= 4 ✓，farthest = max(4, 3) = 4
i=3: 3 <= 4 ✓，farthest = max(4, 4) = 4
i=4: 4 <= 4 ✓ → True

    对比 [3,2,1,0,4]：到 i=4 时 farthest 仍是 3，i > farthest → False。

    关键细节：i > farthest 的判断要放在更新之前——否则会允许"从不可达的位置起跳"。

    3. Jump Game II（45）¶

    题面信号："求最少跳跃次数"。

    候选思路：把"最远可达"理解成一层一层地扩展（BFS 视角）。维护两个变量：end（当前层右边界）、farthest（下一层右边界）。到达 end 就说明必须再跳一次。

    走一遍示例：nums = [2,3,1,1,4]

    i nums[i] farthest i == end？ jumps
    0 2 2 是（end=0） 1，end=2
    1 3 4 否 1
    2 1 4 是 2，end=4 ≥ 终点 → 停

    答案 2（0 → 1 → 4）。

    关键细节：必须先更新 farthest 再判断 i == end；循环只到 n-2；n == 1 返回 0。

    追问准备："为什么不能做 BFS 队列？" → 因为可达位置永远是连续区间，用一个右边界就能表示整层，不需要队列。

    4. Gas Station（134）¶

    题面信号："环形加油站，求能绕行一周的起点"。

    候选思路：两个观察。

    1. 总量判断可行性：sum(gas) < sum(cost) 一定无解；反之一定有解；
    2. 一旦在某处断油，起点必须跳到下一个位置——因为在断油点之前的任何位置都不可能是起点（从中间出发只会"少了前面积累的油"）。

    走一遍示例：gas = [1,2,3,4,5]，cost = [3,4,5,1,2]

    i diff cur total start
    0 -2 -2 → 重置 -2 1
    1 -2 -2 → 重置 -4 2
    2 -2 -2 → 重置 -6 3
    3 +3 3 -3 3
    4 +3 6 0 3

    total = 0 ≥ 0，返回 3。

    关键细节：total 和 cur 都要维护（一个判可行性、一个找起点）；可行性必须在最后才判断，不能中途返回 -1。

    论证要能说清：为什么"从 i 出发在 j 断油"意味着"i 到 j 之间任何点都不能作为起点"？用反证法——若从 k（i<k≤j）出发能成功，那么从 i 出发时"i 到 k 的净油量 ≥ 0"（否则 k 之前就断了），所以从 i 出发也应该成功，矛盾。

    5. Hand of Straights（846）¶

    题面信号："把牌分成若干组，每组 groupSize 张连续的牌"。

    候选思路：设当前最小的牌是 x，那么任何包含 x 的组必须以 x 开头（x 已是最小）。而 x 必须被分到某一组里——所以选择是强制的，贪心自动成立。

    走一遍示例：hand = [1,2,3,6,2,3,4,7,8]，groupSize = 3（排序后 [1,2,2,3,3,4,6,7,8]）

    最小是 1 → 必须组 [1,2,3]，计数后剩 [2,3,4,6,7,8]（2 还剩 1，3 还剩 1）
最小是 2 → 组 [2,3,4]，剩 [6,7,8]
最小是 6 → 组 [6,7,8] → 全部用完 ✓

    关键细节：必须用 while 而不是 if（同一个值可能要开好几组，比如 [1,1,2,2,3,3]）；len(hand) % groupSize != 0 提前返回 False。

    这类贪心为什么不需要复杂证明？ 因为"当前最小值必须当起点"是被迫的选择——当选择唯一时，贪心自动成立。这是最好证明的一类贪心。

    6. Merge Triplets to Form Target Triplet（1899）¶

    题面信号："用逐位取最大值合并三元组，能否得到 target"。

    候选思路：合并只会让数值变大或不变，所以——

    任何某一维超过 target 的三元组都不能参与合并（一旦参与，那一维永远大于 target）。

    筛掉这些之后，问题变成"每个维度是否都存在一个安全三元组，其该维恰好等于 target 的对应维"。

    走一遍示例：target = [2,7,5]，triplets = [[2,5,3],[1,7,5]]

    [2,5,3]：三维都 ≤ target → 安全；第 1 维等于 2 → 标记第 1 维 ✓
[1,7,5]：安全；第 2 维等于 7、第 3 维等于 5 → 标记第 2、3 维 ✓
三维都标记 → True

    关键细节：判断是"恰好等于"而不是"≤"；不需要考虑合并顺序（取最大值满足交换律和结合律）。

    7. Partition Labels（763）¶

    题面信号："划分成尽可能多的片段，同一字母只能出现在一个片段里"。

    候选思路：某个片段一旦包含字符 c，就必须延伸到 c 最后出现的位置。于是扫描时维护"必须延伸到的最远处"end，到达 end 时第一次允许切开，为最多段数应立即切。

    走一遍示例：s = "ababcbacadefegdehijhklij"

    last[a]=8, last[b]=5, last[c]=7 ...
从 start=0 出发：扫到 'a' → end=max(0,8)=8；扫到 'b' → end=max(8,5)=8 ...
扫到 i=8 时 i==end → 切出长度 9
下一段从 9 开始，同理得到 7 和 8
答案 [9,7,8]

    关键细节：end = max(end, last[c]) 必须写在 i == end 判断之前；长度是 end - start + 1。

    本质：这就是"区间合并"——每个字符的 [首次出现, 最后出现] 是一个区间，把它们合并后的长度就是答案。能看出这层联系说明你对区间贪心已经有直觉了。

    8. Valid Parenthesis String（678）¶

    题面信号："* 可以是 (、) 或空串，判断括号串是否合法"。

    候选思路：每个 * 有 3 种可能，n 个星号就是 3ⁿ 种组合，枚举不可行。关键是不枚举每种可能，而是维护"未匹配左括号数量"的可能范围 [lo, hi]。

    范围怎么更新：

    字符 对范围的影响
    ( lo += 1, hi += 1
    ) lo -= 1, hi -= 1；若 hi < 0 → 直接 False
    * lo -= 1（当 )）、hi += 1（当 (）
    每轮结束 lo = max(lo, 0)（左括号数不可能为负）

    走一遍示例：s = "(*))"

    字符 lo hi
    ( 1 1
    * 0 2
    ) -1 → 截断 0 1
    ) -1 → 截断 0 0

    结束时 lo == 0 → True。

    为什么"维护范围"等价于枚举所有可能？ 因为"未匹配左括号数"的取值是连续的一段区间（每步只是整体平移或向两端扩展），所以两个端点就能完整表示这个集合。这是本题最精妙的地方。

    关键细节：hi < 0 要立即返回 False；每轮都要 lo = max(lo, 0)；最终判断是 lo == 0。

    六、复杂度速查¶

    题目 贪心模式 时间
    Maximum Subarray 维护当前最优 O(n)
    Jump Game 维护最远可达 O(n)
    Jump Game II 最远可达 + 分层 O(n)
    Gas Station 全局记账 O(n)
    Hand of Straights 排序 + 分组 O(n log n)
    Merge Triplets 逐维筛选 O(n)
    Partition Labels 最远边界切分 O(n)
    Valid Parenthesis String 区间维护状态 O(n)

    七、易错点速查¶

    1. 不证明就用贪心，在边界用例上失败。
    2. 区间类按"开始时间"排序（多数情况应该按结束时间）。
    3. 忘记处理"不可达"（55、134 都要返回特殊值）。
    4. 把"局部最优"理解错（Coin Change 的经典反例）。
    5. 53 题用 0 当初始值，全负数时出错。
    6. 846 题用 if 而不是 while。
    7. 763 题先判断 i == end 再更新 end。
    8. 45 题先判断 i == end 再更新 farthest。

    八、面试话术¶

    "我用贪心。每一步都维护'到目前为止能到达的最远位置'，因为一旦确认某个位置可达，更靠前的选择就不会影响后面的结果——这保证了局部最优可以累积成全局最优。时间 O(n)，空间 O(1)。"
