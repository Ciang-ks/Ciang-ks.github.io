    Stack · 解题手册¶

    栈的价值在于 LIFO：它能回答"离我最近的、还没被处理的那个东西是谁"。题目里出现"配对、嵌套、最近的更大/更小元素、撤销"，栈几乎都是正解。

    一、从题面提出候选，再核对条件¶

    已学基础：04-链表栈与队列。下面将讲义中的结构性质用于选择解法。

    先辨认尚未完成的任务是否只能从最后一个开始解决；单调栈再额外利用大小关系，批量确定答案或删去被支配项。

    题目特征 需要验证的依据 迁移边界与反例
    嵌套括号、后缀表达式 最近未配对左括号或最近两个子表达式优先被处理 生成全部括号序列还需搜索分支
    最近一个更大或更小 栈保存尚未解决的下标，当前值弹出可结算者 要全局最大值时不必维护完整单调栈
    直方图最大矩形 每根柱作为最低高度，弹出时确定可延伸范围 栈相等值的处理决定边界是严格小于还是小于等于
    随 push/pop 查询最小值 为每层保存历史最小摘要，pop 同时恢复 支持任意下标删除时这个结构不够

    解释每次弹出：它是得到了最终答案，还是被新候选支配而放弃？两者代码看似相同，证明和保存的信息可能不同。

    二、三种题型与它们的模式¶

    类型 1 配对 / 嵌套¶

    遇到"开"就入栈，遇到"闭"就出栈并检查是否匹配。核心是"最内层最先闭合"。

    类型 2 表达式求值¶

    遇数字入栈；遇运算符弹出两个操作数算完压回。注意先弹出的是右操作数。

    类型 3 单调栈¶

    维护一个单调的栈，用来快速找"左边/右边第一个更大（更小）的元素"。

    想找 栈的单调性 弹出条件
    右边第一个更大的元素 递减栈 nums[top] < x 时弹出
    右边第一个更小的元素 递增栈 nums[top] > x 时弹出
    左边第一个更大 / 更小 同上，答案在新栈顶 ——

    单调栈的直觉：栈里保存的是"还没找到答案的元素"，一旦来了一个能"干掉"它们的元素，就结算。

    三、从读题到写码：四步流程¶

    1. 判断是不是"最近相关性"：如果答案只和"最近的一个还没被处理的东西"有关，栈就对了。
    2. 决定栈里存什么：需要算距离/宽度时必须存下标；只做配对时存值即可。
    3. 写清弹出条件：< 还是 <=？这决定了"严格更大"还是"不小于"。
    4. 处理收尾：栈里剩下的元素怎么办？（加哨兵最省事）

    四、常用模板与使用条件¶

    模板 1 括号配对¶

    def is_valid(s):
    pairs = {')': '(', ']': '[', '}': '{'}
    stack = []
    for c in s:
        if c in pairs:
            if not stack or stack.pop() != pairs[c]:
                return False
        else:
            stack.append(c)
    return not stack                 # 必须全部配对完

    模板 2 单调栈（找下一个更大元素）¶

    def daily_temperatures(temperatures):
    n = len(temperatures)
    res = [0] * n
    stack = []                       # 存下标，对应温度单调递减
    for i, t in enumerate(temperatures):
        while stack and temperatures[stack[-1]] < t:
            j = stack.pop()
            res[j] = i - j           # j 右边第一个更高温度就是第 i 天
        stack.append(i)
    return res

    模板 3 单调栈 + 哨兵（直方图类）¶

    def largest_rectangle(heights):
    heights = [0] + heights + [0]     # 左右哨兵
    stack = [0]
    best = 0
    for i in range(1, len(heights)):
        while heights[stack[-1]] > heights[i]:
            h = heights[stack.pop()]  # 以 h 为高，右边界是 i
            w = i - stack[-1] - 1     # 左边界是新的栈顶
            best = max(best, h * w)
        stack.append(i)
    return best

    哨兵的作用：左哨兵保证栈永不为空（省掉 if not stack），右哨兵保证结束时所有柱子都被弹空（省掉收尾循环）。

    模板 4 O(1) 取最小值的栈¶

    class MinStack:
    def __init__(self):
        self.stack = []              # (值, 到目前为止的最小值)

    def push(self, val: int) -> None:
        cur_min = val if not self.stack else min(val, self.stack[-1][1])
        self.stack.append((val, cur_min))

    def pop(self) -> None:
        self.stack.pop()

    def top(self) -> int:
        return self.stack[-1][0]

    def getMin(self) -> int:
        return self.stack[-1][1]

    五、逐题推演：从题面到思路¶

    1. Valid Parentheses（20）¶

    题面信号："括号是否正确配对且嵌套合法"。

    候选思路：嵌套 → 最后出现的左括号必须最先被闭合 → 栈。

    走一遍示例：s = "([)]"

    '(' 入栈 → ['(']
'[' 入栈 → ['(', '[']
')' 出栈得到 '['，但 ')' 需要 '(' → 不匹配 → False

    关键细节：遍历结束必须检查 not stack（否则 "(((" 会被误判为 True）；右括号出现时栈空也要返回 False；不能用"三种括号数量相等"来判断（"([)]" 数量都对但嵌套非法）。

    2. Min Stack（155）¶

    题面信号：设计一个栈，要求 getMin() 也是 O(1)。

    候选思路：O(1) 意味着不能现算。要么维护一个"同步的最小值栈"，要么在每个元素里带一个"截至此处的最小值"。

    为什么不能只在 pop 时重算？ 那就变成 O(n) 了。为什么用元组就能同步？ 因为"最小值"是一个随栈深度单调变化的量，压栈时算一次就够了。

    关键细节：pop 时两个结构必须同步；若用"懒删除"的最小栈，压栈判断必须用 <=（否则重复的最小值会被提前弹掉）。

    追问准备："如何同时支持 getMax？" → 再维护一个 max 栈；"如何删除中间元素？" → 双向链表 + 哈希表（就是 LRU）。

    3. Evaluate Reverse Polish Notation（150）¶

    题面信号："逆波兰表达式求值"。

    候选思路：后缀表达式的两个操作数永远是"最近压入、还没被用掉"的两个 → 栈。

    走一遍示例：tokens = ["2","1","+","3","*"]

    2 → [2]
1 → [2, 1]
+ → 弹出 1（右）、2（左），算 2+1=3 → [3]
3 → [3, 3]
* → 弹出 3（右）、3（左），算 3*3=9 → [9]
答案 9

    关键细节：先弹出的是右操作数，- 和 / 顺序不能反；Python 的 // 是向下取整，负数除法要用 int(a / b) 才能向零截断；判断"是不是运算符"用 t in "+-*/"，不要用 isdigit()（负号会误判）。

    4. Generate Parentheses（22）¶

    题面信号："生成所有合法的 n 对括号组合"。

    候选思路：要枚举所有方案 → 回溯（不是栈）。剪枝条件来自括号的性质：任何前缀里，右括号数量不能超过左括号数量。

    走一遍示例：n = 2

    开始: path="", open=0, close=0
放 ( : "(", 1, 0
  放 ( : "((", 2, 0
    只能放 ) : "(()", 2, 1 → 再放 ) : "(())" ✓
  放 ) : "()", 1, 1
    放 ( : "()(", 2, 1 → 放 ) : "()()" ✓

    关键细节：放 ( 的条件是 open < n，放 ) 的条件是 close < open。两者写反是最常见的错误。结果个数是卡特兰数，无法再优化。

    5. Daily Temperatures（739）¶

    题面信号："对每一天，还要等几天才会遇到更高的温度"。

    候选思路：这是"右边第一个比它大的元素" → 单调栈的教科书场景。

    单调栈的推理：栈里存"还没找到答案的日子"，气温递减。新来的 x 一次把比它小的全部结算——因为这些天再也遇不到更早的更高温度了。

    走一遍示例：T = [73,74,75,71,69,72,76,73]

    i=1 (74): 73 < 74 → 弹出 0，res[0]=1；栈 [1(74)]
i=2 (75): 74 < 75 → 弹出 1，res[1]=1；栈 [2(75)]
i=3 (71): 入栈 → [2(75), 3(71)]
i=4 (69): 入栈 → [2(75), 3(71), 4(69)]
i=5 (72): 69 < 72 → res[4]=1；71 < 72 → res[3]=2；栈 [2(75), 5(72)]
i=6 (76): 72 < 76 → res[5]=1；75 < 76 → res[2]=4；栈 [6(76)]
i=7 (73): 入栈
结果 [1,1,4,2,1,1,0,0]

    关键细节：栈里存下标（要算天数差）；未找到更高温度的位置保持初始值 0；复杂度 O(n) 的依据是"每个下标最多进出栈各一次"。

    6. Car Fleet（853）¶

    题面信号："车不能超车，求最终形成几个车队"。

    候选思路：先算每辆车"单独开到终点需要的时间"；从最靠近终点的车开始处理（所以按位置降序排序）。后车如果时间 ≤ 前车，说明它会追上并并队。

    走一遍示例：target = 12, position = [10,8,0,5,3], speed = [2,4,1,1,3]

    按位置降序：(10,2)、(8,4)、(5,1)、(3,3)、(0,1)

    车（位置, 速度） 单独到达时间 与前车比 车队数
    (10, 2) (12-10)/2 = 1.0 领头车 1
    (8, 4) 1.0 ≤ 1.0 → 并队 1
    (5, 1) 7.0 > 1.0 → 新车队 2
    (3, 3) 3.0 ≤ 7.0 → 并队 2
    (0, 1) 12.0 > 7.0 → 新车队 3

    答案 3。

    关键细节：必须按位置降序（从最靠近终点的车开始）；比较用 <=（同时到达也算并队）；时间要用浮点除法。

    7. Largest Rectangle in Histogram（84）¶

    题面信号："柱状图中最大的矩形面积"。

    候选思路：任何最优矩形都可以描述成"以某根柱子 j 的高度为高，向左右扩展到第一个比它矮的柱子为止"。于是问题变成"对每根柱子找左右第一个更矮的位置" → 单调栈。

    走一遍示例：heights = [2,1,5,6,2,3]

    加哨兵后: [0,2,1,5,6,2,3,0]
i=3（值 5）时，栈顶是 (2,5)，5 > 1 → 弹出 j=2
    h = 5，左边界 = 新栈顶下标 1（值 2），右边界 = 3
    w = 3 - 1 - 1 = 1 → 面积 5
i=4（值 6）时，弹出 j=3（值 6）：w = 4-2-1 = 1 → 面积 6
i=5（值 2）时，弹出 j=4（值 5）：w = 5-2-1 = 2 → 面积 10 ✓

    最终答案 10。

    关键细节：栈存下标；宽度是 i - stack[-1] - 1；双哨兵不能漏。弹出条件用 >（严格大于）时，相等的柱子会在第二次弹出时用更宽的区间结算，同样正确。

    迁移：逐行把它当直方图调用一次，就是 85 Maximal Rectangle。

    六、复杂度速查¶

    题目 类型 栈里存什么 时间
    Valid Parentheses 配对 左括号 O(n)
    Min Stack 设计 (值, 当前最小值) 每次 O(1)
    Evaluate RPN 求值 操作数 O(n)
    Generate Parentheses 回溯 计数状态 O(4ⁿ/√n)
    Daily Temperatures 单调栈 下标 O(n)
    Car Fleet 排序 + 单调 车队到达时间 O(n log n)
    Largest Rectangle 单调栈 + 哨兵 下标 O(n)

    七、易错点速查¶

    1. 配对类忘记检查"遍历结束后栈为空"。
    2. 逆波兰搞反左右操作数；负数除法截断方向弄错。
    3. 单调栈存值而不是下标（要算距离/宽度时必须存下标）。
    4. 弹出条件 < 与 <= 的选择没想清楚，导致相等元素处理不当。
    5. 直方图类忘记加哨兵，导致收尾逻辑缺失。
    6. Min Stack 的 pop 没有同步两个结构。
    7. 22 题误用栈而不是回溯（这里要枚举方案，不是验证）。
    8. 误以为单调栈的 while 让它变成 O(n²)——每个下标最多进出栈各一次，总计 O(n)。

    八、面试话术¶

    "这类题需要找'最近的、还没被处理的元素'，所以我用单调栈。栈里存下标，保持单调递减。遍历到新元素时，把栈顶比它小的都弹出并结算——因为新元素就是它们右边第一个更大的元素。每个下标最多进出栈一次，所以总复杂度 O(n)，空间 O(n)。"

    九、30 秒自测¶

    1. 单调栈里有 while，为什么整体仍是 O(n)？
    2. 84 题里，为什么弹出栈顶时"以它为高的矩形"宽度就已经确定了？
    3. Min Stack 为什么不能在 pop 时重新求最小值？
    4. 22 题为什么是回溯而不是栈的模拟？
    5. 逆波兰表达式里"先弹出的是右操作数"会造成什么后果？
