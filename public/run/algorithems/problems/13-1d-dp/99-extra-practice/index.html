    1. 279 Perfect Squares¶

    LeetCode 279 ｜ Medium

    题目：求用最少的完全平方数之和表示 n（例如 12 = 4 + 4 + 4，答案是 3）。

    为什么放这里：Coin Change 的换壳题——把"硬币"换成"完全平方数"（1, 4, 9, 16, ...），要求最少数量。代码结构完全一样。

    思路提示：完全背包，dp[j] = min(dp[j], dp[j - k*k] + 1)。

    方法辨析：平方数就是可无限复用的硬币面额，最少数量按最后一块平方分类即可。因为 1 总存在，所有正目标均可达；这不代表随便优先最大的平方就是最优，12 取 9+1+1+1 比 4+4+4 更差。

    class Solution:
    def numSquares(self, n: int) -> int:
        dp = [0] + [float('inf')] * n
        squares = [i * i for i in range(1, int(n ** 0.5) + 1)]

        for j in range(1, n + 1):                # 外层金额
            for s in squares:                    # 内层物品
                if s > j:
                    break
                dp[j] = min(dp[j], dp[j - s] + 1)

        return dp[n]

    易错点：平方数列表要预先算好（range(1, int(n**0.5)+1)）；dp[0] = 0。

    复杂度：时间 O(n√n)，空间 O(n)。

    数学补充：拉格朗日四平方和定理告诉我们答案只可能是 1、2、3、4。所以理论上可以用数学方法 O(√n) 求解，但面试中 DP 是更稳妥的答案。

    2. 343 Integer Break¶

    LeetCode 343 ｜ Medium

    题目：把 n 拆成至少两个正整数之和，使它们的乘积最大。

    为什么放这里：它展示了"DP 的状态定义可以有多种选择"，同时也能用数学（贪心）求解，是很好的对照练习。

    思路提示（DP）：dp[i] = 把 i 拆分后的最大乘积。枚举第一个拆出来的数 j：

    dp[i] = max(dp[i], j * (i - j), j * dp[i - j])

    注意要同时考虑 j * (i - j)：因为 i - j 本身可能不再拆分（也就是只分成两份）。

    方法辨析：题目要求至少拆两份，所以 j×(i−j) 是合法的两份方案，j×dp[i−j] 表示右侧继续拆。不能只让 dp[i]=i，否则会把不拆当成答案；数学贪心还需单独处理 2、3 这些拆分反而变小的边界。

    class Solution:
    def integerBreak(self, n: int) -> int:
        dp = [0] * (n + 1)
        for i in range(2, n + 1):
            for j in range(1, i):
                dp[i] = max(dp[i], j * (i - j), j * dp[i - j])
        return dp[n]

    思路提示（贪心，O(n) 或 O(log n)）：尽量拆成 3。因为 3 是"性价比最高"的因子（3 × 3 > 2 × 4）。具体规则是：n % 3 == 0 时全拆成 3；余 1 时把一个 3 换成两个 2；余 2 时保留一个 2。

    易错点：n = 2 返回 1，n = 3 返回 2（必须拆成至少两个数，所以不能直接返回 n）。

    复杂度：DP 是 O(n²) 时间、O(n) 空间；贪心是 O(log n)（用快速幂求 3^k）。

    3. 377 Combination Sum IV¶

    LeetCode 377 ｜ Medium

    题目：给定互不相同的正整数数组和目标值，求"和为目标的排列个数"（[1,2] 和 [2,1] 算两种）。

    为什么放这里：完全背包里"内外层顺序决定组合数还是排列数"的经典例证。 这是背包问题最反直觉的一点。

    思路提示

    dp[j] = Σ dp[j - x]   （对所有 x ≤ j）

    关键的遍历顺序：

    • 外层枚举金额、内层枚举物品 → 得到排列数（本题）；
    • 外层枚举物品、内层枚举金额 → 得到组合数（518 Coin Change II）。

    为什么？ 因为"外层金额"意味着"每一层都在决定'最后一步用哪个数'"，数的顺序被区分了；而"外层物品"意味着"按物品顺序逐个决定用几个"，顺序不被区分。

    方法辨析：按最后一个数分类时，不同顺序形成不同完整序列，故金额外层能汇总全部排列。输入正数保证子目标更小且方案有限；若允许 0 或能相互抵消的正负数，又不限制长度，可能有无限多序列。

    class Solution:
    def combinationSum4(self, nums: List[int], target: int) -> int:
        dp = [0] * (target + 1)
        dp[0] = 1                    # 空组合算 1 种

        for j in range(1, target + 1):          # 外层金额
            for x in nums:                      # 内层物品
                if x <= j:
                    dp[j] += dp[j - x]

        return dp[target]

    易错点：dp[0] = 1；内外层的顺序决定了是排列数还是组合数，这是本题唯一的考点。

    复杂度：时间 O(target · n)，空间 O(target)。

    和 39 Combination Sum 的对比：39 要枚举具体组合（用回溯），本题只要求计数（用 DP）。"枚举方案"用回溯，"计数"用 DP 是一条重要的分界线。

    4. 740 Delete and Earn¶

    LeetCode 740 ｜ Medium

    题目：每次选一个数 x 获得 x 分，但必须删除所有等于 x-1 和 x+1 的数。求最大得分。

    为什么放这里："转化问题"的绝佳例子——它看起来和打家劫舍毫无关系，但转化之后代码一模一样。

    思路提示

    关键转化：把相同值的分数累加起来，得到一个按值排序的"点数字典"。选值 v 就不能选 v-1 和 v+1——这和打家劫舍里"不能选相邻的房子"完全同构！

    具体做法：

    1. 统计每个值 v 的总得分 points[v] = v × count(v)；
    2. 把值的范围 [0, max] 当作一排"房子"，第 v 间房子的价值是 points[v]；
    3. 套用 198 题的解法。

    方法辨析：选一个值 v 后，其余同值项仍可选且没有额外冲突，正收益下可一起收为 points[v]。冲突按数值 v±1 判断，而非排序列表的相邻下标；若压缩稀疏值域，两个相邻键之间差大于一就可同时拿。

    from collections import Counter

class Solution:
    def deleteAndEarn(self, nums: List[int]) -> int:
        points = Counter(nums)
        max_val = max(nums)

        prev2 = prev1 = 0                # dp[v-2], dp[v-1]
        for v in range(max_val + 1):
            gain = v * points.get(v, 0)
            prev2, prev1 = prev1, max(prev1, prev2 + gain)

        return prev1

    易错点：值域可能很大（到 10⁴），但循环 range(max_val+1) 是可接受的；也可以用排序 + 分组来避免空转。

    复杂度：时间 O(n + max(nums))，空间 O(n)。

    5. 413 Arithmetic Slices¶

    LeetCode 413 ｜ Medium

    题目：统计数组中所有长度 ≥ 3 的等差连续子数组的个数。

    为什么放这里：线性 DP 里"贡献式计数"的典型——dp[i] 表示"以 i 结尾的等差子数组个数"，答案是把它们累加。

    思路提示

    • 如果 nums[i] - nums[i-1] == nums[i-1] - nums[i-2]，那么"以 i 结尾的等差子数组"比"以 i-1 结尾的"多一个（原有各段都可延长，并新增以 i−2 开始的三元素段）；
    • 所以 dp[i] = dp[i-1] + 1，否则 dp[i] = 0；
    • 答案是把所有 dp[i] 累加（因为每个 dp[i] 统计的是"以 i 结尾"的所有等差子数组）。

    方法辨析：长度至少三的连续等差段按右端点归类。相邻差相同，则旧的每条结尾段都可延长，另新增最后三个元素的一段，所以 cur+1；差不同则没有以此处结尾的合法段。总答案需累加 cur，不是只取最大段数。

    class Solution:
    def numberOfArithmeticSlices(self, nums: List[int]) -> int:
        n = len(nums)
        if n < 3:
            return 0
        total = 0
        cur = 0                          # 以当前位置结尾的等差子数组个数
        for i in range(2, n):
            if nums[i] - nums[i - 1] == nums[i - 1] - nums[i - 2]:
                cur += 1
                total += cur
            else:
                cur = 0
        return total

    易错点：答案是把 cur 累加（不是取最大）；差值相等时 cur += 1 而不是重新计数。

    复杂度：时间 O(n)，空间 O(1)。

    6. 474 Ones and Zeroes¶

    LeetCode 474 ｜ Medium

    题目：给定只含 0/1 的字符串数组，以及 m 个 0 和 n 个 1 的预算，求最多能选出多少个字符串。

    为什么放这里：二维 0/1 背包。它把背包的"容量"从一维扩展到两维（0 的个数和 1 的个数）。

    思路提示：状态是 dp[i][j] = "用 i 个 0 和 j 个 1` 最多能选的字符串个数"。对每个字符串，倒序枚举两个维度。

    方法辨析：每个字符串消耗零、一个数两种容量，价值统一为 1；同一个字符串实例只能选一次，所以两种容量都倒序。状态用容量上限而非“必须恰用”，初始全 0 表示可以一个都不选。

    class Solution:
    def findMaxForm(self, strs: List[str], m: int, n: int) -> int:
        # dp[i][j]：用 i 个 0、j 个 1 最多能选多少个字符串
        dp = [[0] * (n + 1) for _ in range(m + 1)]

        for s in strs:
            zeros = s.count('0')
            ones = len(s) - zeros
            if zeros > m or ones > n:                # 单个就超预算，直接跳过
                continue
            # 两个维度都要倒序（0/1 背包）
            for i in range(m, zeros - 1, -1):
                for j in range(n, ones - 1, -1):
                    dp[i][j] = max(dp[i][j], dp[i - zeros][j - ones] + 1)

        return dp[m][n]

    易错点：两个维度都必须倒序（因为这是 0/1 背包）；zeros > m or ones > n 的剪枝能省不少时间。

    复杂度：时间 O(len(strs) · m · n)，空间 O(m · n)。

    7. 1049 Last Stone Weight II¶

    LeetCode 1049 ｜ Medium

    题目：每次选两块石头相撞（重量相减），求最后可能剩下的最小重量。

    为什么放这里：把"看起来像模拟"的问题转化成"最小差子集和"，和 416 是同一套思路的进阶。

    思路提示

    关键转化：这个问题等价于"把石头分成两堆，使两堆重量之差的绝对值最小"。

    为什么？因为每次相撞相当于"给某块石头赋予正号、另一块赋予负号"，最后剩下的重量就是"所有石块带符号求和"的绝对值。而符号只能取 ±1，所以问题变成"最小化 |总和 - 2 × 某一堆的和|"。

    于是：背包容量是 total // 2，问"能达到的最大子集和 s 是多少"，答案是 total - 2s。

    方法辨析：与固定碰撞最重两块的 Last Stone Weight 不同，这里可挑碰撞顺序，目标才转成重量最平衡的分组。DP 寻找不超过 total/2 的最大可达和，不能把“恰好一半不可达”就当作无解，因为本题总能返回某个最小残重。

    class Solution:
    def lastStoneWeightII(self, stones: List[int]) -> int:
        total = sum(stones)
        target = total // 2
        dp = [False] * (target + 1)
        dp[0] = True

        for x in stones:
            for j in range(target, x - 1, -1):       # 倒序 → 0/1 背包
                if dp[j - x]:
                    dp[j] = True

        # 从 target 往下找第一个可达的和
        for s in range(target, -1, -1):
            if dp[s]:
                return total - 2 * s
        return total

    易错点：内层倒序（0/1 背包）；最后从 target 往下找第一个可达的和（这样差值最小）。

    复杂度：时间 O(n · total)，空间 O(total)。

    8. 140 Word Break II¶

    LeetCode 140 ｜ Hard

    题目：在 139 的基础上，要求输出所有可能的拆分方案。

    为什么放这里："计数用 DP，枚举方案用记忆化回溯"的完美对照。它同时也说明了"为什么 139 能用纯 DP 而 140 必须回溯"。

    思路提示

    用记忆化搜索：定义 solve(i) 返回 "s[i:] 的所有拆分方案"，用字典缓存结果。

    缓存可复用同一后缀的拆分结果，但所有输出本身仍可能指数多。 因为不同的前缀可能到达同一个后缀，共享子问题能减少重复搜索，却不能省去生成与保存全部答案的成本。

    方法辨析：Word Break 的一个布尔值不足以生成所有句子，缓存需保存每个后缀的全部合法拼接。空后缀可提供一个空结尾供前一个单词接上；输出规模本身可能指数大，记忆化节约的是重复探索而非答案数量。

    class Solution:
    def wordBreak(self, s: str, wordDict: List[str]) -> List[str]:
        word_set = set(wordDict)
        n = len(s)
        memo = {}

        def solve(i: int) -> List[str]:
            if i == n:
                return [""]                    # 空后缀对应一种"空方案"
            if i in memo:
                return memo[i]

            res = []
            for j in range(i + 1, n + 1):
                piece = s[i:j]
                if piece in word_set:
                    for rest in solve(j):
                        res.append(piece if not rest else f"{piece} {rest}")

            memo[i] = res
            return res

        return solve(0)

    易错点：基线返回 [""]（空串）而不是 []，这样才能正确拼接；拼接时处理"首尾不加空格"的细节；必须用 memo 缓存。

    复杂度：时间与"方案总数 × 方案长度"同阶（最坏指数级，因为输出本身就很大），空间 O(n + 输出)。

    139 和 140 的对比：139 只要判断"能不能"，所以 dp 是布尔值，O(n²)；140 要枚举所有方案，输出规模本身可能是指数级的，所以必须回溯。这个对比能帮你判断"什么时候 DP 够用、什么时候必须枚举"。
