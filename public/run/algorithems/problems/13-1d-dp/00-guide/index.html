    1-D Dynamic Programming · 解题手册¶

    DP 的难点从来不是代码，而是状态定义。写之前必须能用一句话说清"dp[i] 代表什么"。先定义状态，再写转移，最后考虑初始化和遍历顺序——这个顺序不能乱。

    一、从题面提出候选，再核对条件¶

    已学基础：20-动态规划入门、21-子序列DP、22-背包DP。下面将讲义中的结构性质用于选择解法。

    掌握 DP 定义后，重点练习让状态留下恰好足够的历史：相同状态的不同路径，后续合法选择和收益是否完全相同？

    题目特征 需要验证的依据 迁移边界与反例
    依赖最近几项的决策 前缀或结尾状态，按最后一步或选不选分类 求所有前缀最优与必须以当前位置结尾不同
    切分字符串 以前缀边界为状态，合法词或片段为转移 贪心先选最长词可能堵死后缀
    每个元素一次或无限复用 先写二维物品状态，再决定压缩时读旧层还是本层 一维倒序与正序来自依赖，不是独立口诀
    递增子序列、乘积最大段 根据未来接法保留最优尾值或两个极值 历史全局最大值未必能作为当前结尾状态

    写代码前用小输入填一张状态表，再将变量对应到表项。计数用加法必须证明分类不重不漏；最值取 min/max 则需证明候选覆盖且子问题可独立替换。

    二、DP 四步法（所有 DP 题都按这个顺序想）¶

    1. 状态定义：dp[i] 是什么？用一句话说清，并且能用一个具体小例子验证。
    2. 转移方程：dp[i] 由哪些更小的状态组合而来？
    3. 初始化：最小的那些状态（dp[0]、dp[1]）应该是什么？
    4. 遍历顺序：怎么保证"算 dp[i] 时依赖的状态已经算好"？

    大部分 DP 的 bug 都出在第 1 步和第 3 步。 结果不对时，先回头检查状态定义是不是有歧义。

    两种实现方式¶

    from functools import lru_cache

def top_down(nums):
    @lru_cache(maxsize=None)
    def solve(i):
        if i == 0:
            return base_value                      # 基线值
        return combine(solve(i - 1))               # 由更小的状态组合而来
    return solve(len(nums) - 1)

    def bottom_up(nums):
    n = len(nums)
    dp = [0] * (n + 1)
    dp[0] = base_value                         # 基线值
    for i in range(1, n + 1):
        dp[i] = combine(dp[i - 1])             # 由更小的下标组合而来
    return dp[n]

    面试建议：先写记忆化搜索（不容易错、能证明正确性），再改写成自底向上（体现优化能力）。这个"先递归后递推"的演进过程本身就是很好的面试表现。

    空间压缩¶

    def fib(n):
    prev2, prev1 = 0, 1
    for _ in range(n):
        prev2, prev1 = prev1, prev1 + prev2
    return prev2

    当 dp[i] 只依赖前一两项时，用滚动变量把空间从 O(n) 降到 O(1)——这是面试官最爱追问的优化点。

    三、四个家族与它们的模板¶

    家族 1 线性递推（斐波那契型）¶

    def climb_stairs(n):
    if n <= 2:
        return n
    prev2, prev1 = 1, 2
    for _ in range(3, n + 1):
        prev2, prev1 = prev1, prev1 + prev2
    return prev1

    家族 2 完全背包 / 零钱兑换型¶

    def coin_change(coins, amount):
    INF = float("inf")
    dp = [0] + [INF] * amount
    for c in coins:
        for j in range(c, amount + 1):      # 正序 → 完全背包
            if dp[j - c] + 1 < dp[j]:
                dp[j] = dp[j - c] + 1
    return dp[amount] if dp[amount] != INF else -1

    当前一维压缩状态中的循环规则：

    开关 效果
    内层正序 完全背包（物品可用无限次）
    内层倒序 0/1 背包（物品最多用一次）
    外层物品、内层容量 组合数（顺序无关）
    外层容量、内层物品 排列数（顺序有关）

    家族 3 字符串 DP（"前 i 个字符"）¶

    def num_decodings(s):
    if not s or s[0] == "0":
        return 0
    prev2, prev1 = 1, 1
    for i in range(2, len(s) + 1):
        cur = 0
        if s[i - 1] != "0":
            cur += prev1
        if 10 <= int(s[i - 2:i]) <= 26:
            cur += prev2
        prev2, prev1 = prev1, cur
    return prev1

    dp 长度取 n + 1、dp[i] 表示 s[:i]——这样 dp[0] 自然表示空串，边界最好写。

    家族 4 子序列型（"以 i 结尾"）¶

    def length_of_lis(nums):
    n = len(nums)
    dp = [1] * n
    for i in range(1, n):
        for j in range(i):
            if nums[j] < nums[i]:
                dp[i] = max(dp[i], dp[j] + 1)
    return max(dp)                        # 答案是所有 dp 的最大值

    "以 i 结尾"和"前 i 个"是两种完全不同的定义：

    • "以 i 结尾" → 答案要遍历所有 dp[i] 取最值（最优解不一定以最后一个元素结尾）；
    • "前 i 个" → 答案就是 dp[n]。

    搞混这两种定义是子序列类 DP 最常见的错误。

    四、逐题推演：从题面到思路¶

    1. Climbing Stairs（70）¶

    题面信号："每次爬 1 或 2 级，求到第 n 级的方法数"。

    候选思路：定义 dp[i] = 到第 i 级的方法数。最后一步只能来自 i-1 或 i-2 → dp[i] = dp[i-1] + dp[i-2]。这就是斐波那契。

    走一遍示例：n = 4

    i 1 2 3 4
    dp 1 2 3 5

    关键细节：n ≤ 2 直接返回 n（即 dp[0] = 1, dp[1] = 1 时也可）；空间可以压到 O(1)。

    追问准备："一次可以爬 1..m 级？" → dp[i] = sum(dp[i-k] for k in 1..m)，可以用滑动窗口优化到 O(n)。"n 很大？" → 矩阵快速幂，O(log n)。

    2. Min Cost Climbing Stairs（746）¶

    题面信号："从第 i 级往上爬要花 cost[i]，可以从第 0 或第 1 级出发"。

    候选思路：与 70 同结构，只是把"计数"换成"取最小值"。

    走到第 i 级的最小花费（注意是"到达"而不是"离开"）：

    dp[i] = min(dp[i-1] + cost[i-1], dp[i-2] + cost[i-2])

    走一遍示例：cost = [10,15,20]

    dp[0] = 0, dp[1] = 0（可以直接站在这两级，不付钱）
dp[2] = min(0+15, 0+10) = 10
dp[3] = min(10+20, 0+15) = 15
答案 dp[3] = 15        ← 注意答案是 dp[n]，不是 dp[n-1]

    关键细节：加的是"出发那一级"的费用（cost[i-1]、cost[i-2]），不是 cost[i]；答案是 dp[n]（"爬到顶部"意味着越过最后一级）。

    3. House Robber（198）¶

    题面信号："不能偷相邻的房子，求最大金额"。

    候选思路：对每间房子做分类讨论——偷它 / 不偷它：

    dp[i] = max(dp[i-1],            # 不偷第 i 间
            dp[i-2] + nums[i])  # 偷第 i 间，那就不能偷 i-1

    走一遍示例：nums = [2,7,9,3,1]

    i 0 1 2 3 4
    dp 2 7 11 11 12

    答案 12（偷 2 + 9 + 1）。

    关键细节：第二项必须是 dp[i-2]（因为偷了 i 就不能偷 i-1）；空数组返回 0；空间可压到 O(1)。

    另一种写法（双状态）：rob_cur, skip_cur = skip_cur + x, max(rob_cur, skip_cur)——这套"偷/不偷"双状态在 213、309 等变体里都能用。

    4. House Robber II（213）¶

    题面信号："房子排成一个环，首尾相邻"。

    候选思路：环的麻烦只在首尾。关键观察：最优解一定满足"不偷第一间"或"不偷最后一间"中的至少一个（因为两者不能同时偷）。于是拆成两条链：

    答案 = max( rob_line(nums[:-1]), rob_line(nums[1:]) )

    走一遍示例：nums = [2,3,2]

    rob_line([2,3]) → max(2,3) = 3
rob_line([3,2]) → max(3,2) = 3
答案 3 ✓（偷中间那间）

    关键细节：n == 1 必须特判（否则两个子问题都是空数组，返回 0）；这个"固定首尾状态再拆"的技巧对 918 环形子数组同样适用。

    5. Longest Palindromic Substring（5）¶

    题面信号："最长回文子串"。

    候选思路：中心扩展最直观——回文的中心有两类（单字符 / 两个字符之间），共 2n-1 个中心，每个中心向两边扩展。

    走一遍示例：s = "babad"

    中心 i=1（字符 'a'）: 向左 'b'、向右 'b' → 得到 "bab"（长度 3）
中心在 s[0] 和 s[1] 之间: 'b','a' 不同 → 放弃
各中心比较后最长是 3

    关键细节：两类中心都要枚举（奇数长度和偶数长度）；O(n) 的 Manacher 算法知道存在即可，面试不需要手写。

    对照记忆：区间 DP 的写法也成立（dp[i][j] = (s[i]==s[j]) and (j-i<=2 or dp[i+1][j-1])），但空间 O(n²)，不如中心扩展。

    6. Palindromic Substrings（647）¶

    题面信号："统计回文子串的个数"。

    候选思路：5 题的模板，每成功扩展一步就计数 +1。

    为什么"按中心枚举"能不重不漏？ 因为每个回文子串都有唯一的中心（由奇偶长度决定），所以按中心统计刚好一一对应。

    走一遍示例：s = "aaa"

    中心 0（'a'）: 扩展到 "a"（1）→ 越界，停。计数 1
中心 0 和 1 之间: "aa"（1）→ 越界。计数 1
中心 1（'a'）: "a"（1）→ "aaa"（2）→ 越界。计数 2
中央（1 和 2 之间）: "aa"（1）
中心 2: "a"（1）
合计 6 ✓

    关键细节：计数在 while 循环体内；空字符串返回 0。

    7. Decode Ways（91）¶

    题面信号："数字串按 A=1..Z=26 解码，求方案数"。

    候选思路：字符串切分型 DP，dp[i] = 前 i 个字符的解码方式数。

    dp[i] = (dp[i-1] if s[i-1] != '0' else 0)
      + (dp[i-2] if 10 <= int(s[i-2:i]) <= 26 else 0)

    走一遍示例：s = "226"

    i 子串 一位解码 两位解码 dp[i]
    0 "" —— —— 1（人为定义）
    1 "2" dp[0]=1 无 1
    2 "22" dp[1]=1 22≤26 → dp[0]=1 2
    3 "226" dp[2]=2 26≤26 → dp[1]=1 3

    关键细节：s 以 '0' 开头直接返回 0；'0' 不能单独解码；dp[0] = 1 是人为定义，它让 "12" 这类能用两位解码的情况正确计数。

    8. Coin Change（322）¶

    题面信号："硬币数量无限，求凑出金额的最少硬币数"。

    候选思路：完全背包（物品可重复用 → 内层正序）。

    走一遍示例：coins = [1,2,5]，amount = 11（从金额 0 递推到 11）

    dp[0] = 0
dp[1] = dp[0] + 1 = 1
dp[2] = min(dp[1], dp[0]) + 1 = 1
dp[5] = 1（用一枚 5）
dp[11] = dp[10] + 1 = 3

    关键细节：其余状态初始化为 inf（不是 0，否则会出现"不存在的解"）；dp[amount] 仍是 inf 时返回 -1。

    追问准备："为什么不能用贪心（每次选最大的硬币）？" → 反例 coins = [1,3,4]、amount = 6：贪心得到 4+1+1 = 3 枚，最优是 3+3 = 2 枚。

    9. Maximum Product Subarray（152）¶

    题面信号："乘积最大的连续子数组"。

    候选思路：和 53 题（和最大）不同的是——乘法里负负得正，所以局部最小可能变成全局最大，必须同时维护 max 和 min。

    走一遍示例：nums = [-2, 3, -4]

    i x cur_max cur_min 全局最优
    0 -2 -2 -2 -2
    1 3 3 -6 3
    2 -4 24 -12 24

    24 = (-2) × 3 × (-4)，正是"最小乘以负数变成最大"。

    关键细节：更新时必须先算好 new_max 和 new_min 再赋值（否则会用到已覆盖的旧值）；best 初始化为 nums[0]（数组可能全是负数）。

    10. Word Break（139）¶

    题面信号："字符串能否拆分成词典中的单词"。

    候选思路："前 i 个字符"的 DP：dp[i] = any(dp[j] and s[j:i] in word_set)。

    走一遍示例：s = "leetcode"，词典 {leet, code}

    i 子串 可达的切分点 j dp[i]
    4 "leet" j=0（dp[0]=T 且 "leet" 在词典） True
    8 "leetcode" j=4（dp[4]=T 且 "code" 在词典） True

    关键细节：dp[0] = True 不能省（它是整条链的起点）；找到一个合法切分点就 break；用 max_len 限制 j 的下界是简单有效的优化。

    对照：本题只问能否分割，可用布尔 DP 合并路径；要输出所有方案则需保留或重新枚举路径，回溯加记忆化是一种常用实现（140 题）。

    11. Longest Increasing Subsequence（300）¶

    题面信号："最长递增子序列（可以不连续）"。

    候选思路：子序列型 DP，dp[i] = 以 nums[i] 结尾的 LIS 长度。注意"以 i 结尾"这个定义意味着答案是 max(dp)，不是 dp[-1]。

    走一遍示例：nums = [10,9,2,5,3,7,101,18]

    i 值 能接在谁后面 dp[i]
    2 2 无（前面都更大） 1
    3 5 接在 2 后 2
    4 3 接在 2 后 2
    5 7 接在 5（dp=2）后 3
    6 101 接在 7（dp=3）后 4
    7 18 接在 7（dp=3）后 4

    进阶 O(n log n) 写法（耐心排序）：维护 tails[k] = 长度为 k+1 的递增子序列的最小结尾值，对每个 x 用 bisect_left 找到第一个 ≥ x 的位置并替换。

    关键细节：tails 不保证是原数组中的一条真实 LIS，它只记录每个长度的最优结尾——这一点经常被追问；严格递增要用 bisect_left。

    12. Partition Equal Subset Sum（416）¶

    题面信号："能否分成两个和相等的子集"。

    候选思路：设总和为 total，问题等价于"能否选出和为 total / 2 的子集" → 0/1 背包（每个元素最多用一次 → 内层倒序）。

    走一遍示例：nums = [1,5,11,5]，total = 22，target = 11

    处理 1 → 可达 {0, 1}
处理 5 → {0, 1, 5, 6}
处理 11 → {0, 1, 5, 6, 11, 12, ...} → 11 可达 ✓

    关键细节：total 是奇数直接返回 False；内层必须倒序（正序会变成完全背包，答案错）；dp[0] = True。

    追问准备："为什么这是 NP 问题还能多项式求解？" → 因为 DP 的复杂度是 O(n · target)，是伪多项式；如果数值用二进制表示且极大，问题就是 NP-完全的。这个回答很能体现理论功底。

    六、易错点速查¶

    1. 状态定义说不清楚，转移就会写错。
    2. 初始化漏掉（尤其 dp[0] 这个空状态）。
    3. 遍历顺序错误（依赖更大的下标时要反向或按长度遍历）。
    4. 不可达状态没处理（inf + 1 依然是 inf，但逻辑上要能解释）。
    5. 背包内外层顺序搞反（完全背包 vs 0/1 背包；组合数 vs 排列数）。
    6. 记忆化搜索忘了 lru_cache，退化成指数级。
    7. 子序列类只返回 dp[n]，忘了取 max(dp)。
    8. 乘法类只维护 max，漏掉 min。

    七、面试话术¶

    "我定义 dp[i] 为……。转移方程是……。初始状态是 dp[0] = ……。因为 dp[i] 只依赖更小的下标，所以从小到大遍历即可。时间 O(n)，空间 O(n)，其中空间可以用滚动变量压到 O(1)。"
