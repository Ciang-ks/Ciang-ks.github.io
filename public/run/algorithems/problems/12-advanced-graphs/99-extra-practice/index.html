    1. 1631 Path With Minimum Effort¶

    LeetCode 1631 ｜ Medium

    题目：给定高度矩阵，从左上走到右下，路径的"消耗"定义为相邻格子高度差的最大值，求最小消耗。

    为什么放这里：778 Swim in Rising Water 的孪生题——同一个 Dijkstra 变体模板，只是"代价"换了定义。

    思路提示：Dijkstra，堆里存 (当前路径的最大高度差, r, c)，扩展时 new = max(cur, abs(h1 - h2))。

    方法辨析：路线代价由相邻高度差的最大值决定，与 Swim in Rising Water 的最高格子不同。起点不产生一条移动边，初始 effort 为 0；只有一格时答案也应为 0，不是它的高度。

    import heapq

class Solution:
    def minimumEffortPath(self, heights: List[List[int]]) -> int:
        ROWS, COLS = len(heights), len(heights[0])
        dist = [[float('inf')] * COLS for _ in range(ROWS)]
        dist[0][0] = 0
        heap = [(0, 0, 0)]

        while heap:
            effort, r, c = heapq.heappop(heap)
            if r == ROWS - 1 and c == COLS - 1:
                return effort
            if effort > dist[r][c]:
                continue                      # 过期条目
            for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                nr, nc = r + dr, c + dc
                if 0 <= nr < ROWS and 0 <= nc < COLS:
                    ne = max(effort, abs(heights[nr][nc] - heights[r][c]))
                    if ne < dist[nr][nc]:
                        dist[nr][nc] = ne
                        heapq.heappush(heap, (ne, nr, nc))

        return 0

    易错点：代价是 max 而不是加法；dist 数组用来剪枝（避免重复处理）。

    复杂度：时间 \(\mathcal{O}(mn \log (mn))\)，空间 \(\mathcal{O}(mn)\)。

    2. 1334 Find the City With the Smallest Number of Neighbors¶

    LeetCode 1334 ｜ Medium

    题目：给定带权无向图，对每个城市统计"距离不超过阈值"的邻居数，返回邻居数最少的城市（并列时取编号最大的）。

    为什么放这里：多源最短路问题。它和前面几题的区别是"要所有点之间的最短距离"，所以适合 Floyd-Warshall（或者对每个点跑一次 Dijkstra）。

    思路提示

    • Floyd-Warshall：\(\mathcal{O}(n^{3})\)，代码只有 5 行，适合节点较少且三重循环能满足时限的场景；
    • 对每个点跑 Dijkstra：\(\mathcal{O}(n \cdot E \log V)\)，在稀疏图上更快。

    什么时候用哪个？ 记住这个判断：

    • 只需要一个源点 → Dijkstra
    • 所有点对 + n 较小且 \(\mathcal{O}(n^{3})\) 可接受 → Floyd-Warshall（代码最短）
    • 所有点对 + n 较大 + 稀疏图 → 对每个点跑 Dijkstra

    方法辨析：要比较每个城市在阈值内可达的邻居数，所以需要所有源点的最短距离。Floyd 的中转点 k 必须在最外层，让每轮只允许新增一个中转候选；计数通常排除城市自身，平局按题目选择较大编号。

    class Solution:
    def findTheCity(self, n: int, edges: List[List[int]], distanceThreshold: int) -> int:
        INF = float('inf')
        dist = [[INF] * n for _ in range(n)]
        for i in range(n):
            dist[i][i] = 0
        for u, v, w in edges:
            dist[u][v] = dist[v][u] = min(dist[u][v], w)    # 可能有平行边

        # Floyd-Warshall：以 k 为中转点
        for k in range(n):
            for i in range(n):
                if dist[i][k] == INF:
                    continue
                for j in range(n):
                    if dist[i][k] + dist[k][j] < dist[i][j]:
                        dist[i][j] = dist[i][k] + dist[k][j]

        best_city, best_count = -1, n
        for i in range(n):
            cnt = sum(1 for j in range(n) if i != j and dist[i][j] <= distanceThreshold)
            if cnt <= best_count:            # <= 保证并列时取编号更大的
                best_count = cnt
                best_city = i

        return best_city

    易错点：Floyd-Warshall 的三重循环顺序不能变（k 必须在最外层）；dist[u][v] = min(...) 处理平行边；cnt <= best_count 用 \(\le\) 才能在并列时取到编号更大的城市。

    复杂度：时间 \(\mathcal{O}(n^{3})\)，空间 \(\mathcal{O}(n^{2})\)。

    3. 1514 Path with Maximum Probability¶

    LeetCode 1514 ｜ Medium

    题目：给定无向图和每条边的"成功概率"，求从 start 到 end 的最大成功概率路径。

    为什么放这里：Dijkstra 的第三种变形——把"最小化加法"换成"最大化乘法"。

    思路提示：用大顶堆（存概率的负数）+ 同样的松弛逻辑。乘法天然具有单调性（概率都在 [0,1] 之间，乘只会变小），所以 Dijkstra 的正确性依然保持。

    方法辨析：每条边概率在 0..1，相乘不会提高沿途成功率，且较高已有概率经同一路径延伸仍不更差。故先弹最大概率可确定最优；两条边独立成功的乘积假设是题目给定模型，不能推广到相关事件概率。

    import heapq
from collections import defaultdict

class Solution:
    def maxProbability(self, n: int, edges: List[List[int]], succProb: List[float],
                       start: int, end: int) -> float:
        graph = defaultdict(list)
        for (u, v), p in zip(edges, succProb):
            graph[u].append((v, p))
            graph[v].append((u, p))

        best = [0.0] * n
        best[start] = 1.0
        heap = [(-1.0, start)]                # 大顶堆（存负数）

        while heap:
            negp, u = heapq.heappop(heap)
            p = -negp
            if u == end:
                return p
            if p < best[u]:
                continue                      # 过期条目
            for v, edge_p in graph[u]:
                np_ = p * edge_p
                if np_ > best[v]:             # 注意是大于
                    best[v] = np_
                    heapq.heappush(heap, (-np_, v))

        return 0.0                            # 不可达

    易错点：用大顶堆（负数）；比较是 \(>\) 而不是 \(<\)；不可达返回 0。

    复杂度：时间 \(\mathcal{O}(E \log V)\)，空间 \(\mathcal{O}(V + E)\)。

    4. 1976 Number of Ways to Arrive at Destination¶

    LeetCode 1976 ｜ Medium

    题目：求从 0 到 n-1 的最短路径的条数（对 \(10^9+7\) 取模）。

    为什么放这里：Dijkstra + 计数的组合。它说明 Dijkstra 不只能求"距离"，还能顺带维护"到达方式的数量"。

    思路提示：在 Dijkstra 的松弛过程中额外维护 ways[]：

    • 如果找到更短的路径 → 更新距离，\(\mathrm{ways}[v] = \mathrm{ways}[u]\)（继承来源的数量）；
    • 如果找到等长的另一条路径 → ways[v] += ways[u]（累加）。
    • 等长更新只累加 ways，不必再次入堆；过期距离条目跳过。本题边权严格为正，最短路前驱距离都更小，因此 v 的最短距离弹出时，所有前驱的计数都已汇总。若允许零权环，路径计数语义和处理顺序需要重新定义。

    方法辨析：边权严格为正使最短路前驱距离小于当前节点，距离顺序也是计数依赖的顺序。更短路线替换旧方案数，等长路线累加，不能两者都加；过期堆条目不能再次贡献同一批 ways。

    import heapq
from collections import defaultdict

class Solution:
    def countPaths(self, n: int, roads: List[List[int]]) -> int:
        MOD = 10**9 + 7
        graph = defaultdict(list)
        for u, v, w in roads:
            graph[u].append((v, w))
            graph[v].append((u, w))

        dist = [float('inf')] * n
        ways = [0] * n
        dist[0] = 0
        ways[0] = 1
        heap = [(0, 0)]
        done = [False] * n

        while heap:
            d, u = heapq.heappop(heap)
            if done[u]:
                continue
            done[u] = True                    # 第一次弹出即最优，之后不再处理
            for v, w in graph[u]:
                nd = d + w
                if nd < dist[v]:
                    dist[v] = nd
                    ways[v] = ways[u]         # 更短 → 覆盖
                    heapq.heappush(heap, (nd, v))
                elif nd == dist[v]:
                    ways[v] = (ways[v] + ways[u]) % MOD    # 等长 → 累加

        return ways[n - 1]

    易错点：用 done 数组保证每个节点只被"结算"一次（否则等长路径会被重复累加）；取模。

    复杂度：时间 \(\mathcal{O}(E \log V)\)，空间 \(\mathcal{O}(V + E)\)。

    5. 1928 Minimum Cost to Reach Destination in Time¶

    LeetCode 1928 ｜ Hard

    题目：每条边有"耗时"和"花费"两个属性，要求在总时间不超过 maxTime 的前提下，求到达终点的最小花费。

    为什么放这里：两个约束的 DP / Dijkstra。它展示了"当最优解不由单一指标决定时，如何扩展状态"。

    思路提示：状态是 (节点, 已用时间)，值是"最小花费"。用 Dijkstra，堆里存 (花费, 节点, 已用时间)，只看花费作为优先级的键。

    方法辨析：便宜但耗时多的到达与较贵但耗时少的到达不能只按节点价格互相淘汰，因为剩余时限不同。用节点与累计时间作为状态，进入新节点时加其费用，初始起点费用也必须计入。

    import heapq
from collections import defaultdict

class Solution:
    def minCost(self, maxTime: int, edges: List[List[int]], passingFees: List[int]) -> int:
        n = len(passingFees)
        graph = defaultdict(list)
        for u, v, t in edges:
            graph[u].append((v, t))
            graph[v].append((u, t))

        # 状态是 (节点, 已用时间)，值是"到达该状态的最小花费"
        seen = {(0, 0): passingFees[0]}       # (node, time) -> 最小花费，用于剪枝
        heap = [(passingFees[0], 0, 0)]       # (总花费, 节点, 已用时间)

        while heap:
            cost, u, time_used = heapq.heappop(heap)
            if u == n - 1:
                return cost
            for v, t in graph[u]:
                nt = time_used + t
                if nt > maxTime:
                    continue
                nc = cost + passingFees[v]
                key = (v, nt)
                if key not in seen or nc < seen[key]:
                    seen[key] = nc
                    heapq.heappush(heap, (nc, v, nt))

        return -1

    易错点：堆的排序键是"花费"；状态必须包含 (节点, 时间) 两个维度；起点的时间为 0、费用为 passingFees[0]。

    复杂度：时间 \(\mathcal{O}(V \cdot maxTime \cdot \log (...))\)，空间 \(\mathcal{O}(V \cdot maxTime)\)。

    6. 2097 Valid Arrangement of Pairs¶

    LeetCode 2097 ｜ Hard

    题目：给定若干数对 [u, v]，重新排列它们，使前一对的第二个数等于后一对的第一个数。返回任意一种排列。

    为什么放这里：欧拉路径的"有向图版本"，和 332 Reconstruct Itinerary 是同一个算法，但要求确定起点并输出边而不是节点。

    思路提示

    1. 统计每个节点的出度减入度：out - in == 1 的节点是起点；
    2. 如果没有这样的节点（欧拉回路），任选一个有出边的节点作为起点；
    3. 用 Hierholzer 算法沿着边 DFS，记录边（而不是节点），最后反转。

    方法辨析：本题起点不固定，需要优先选 out-in=1 的节点；全为零时可从任一有出边节点开始。输出的是边对，可由欧拉节点序列相邻两项重建，或后序直接记录边；重复边实例仍需各消费一次。

    from collections import defaultdict, deque

class Solution:
    def validArrangement(self, pairs: List[List[int]]) -> List[List[int]]:
        graph = defaultdict(list)
        out_in = defaultdict(int)             # 出度 - 入度

        for u, v in pairs:
            graph[u].append(v)
            out_in[u] += 1
            out_in[v] -= 1

        # 找起点：出度 - 入度 = 1 的节点
        start = pairs[0][0]
        for node, diff in out_in.items():
            if diff == 1:
                start = node
                break

        result = deque()                      # 用 deque 左插，省掉最后反转

        def dfs(node: int) -> None:
            while graph[node]:
                nxt = graph[node].pop()
                dfs(nxt)
                result.appendleft([node, nxt])    # 后序 + 左插 = 反转

        dfs(start)
        return list(result)

    易错点：起点的选择（out - in == 1，没有则任选）；记录的是边 [node, nxt] 而不是节点；用 appendleft 省掉显式反转。

    复杂度：时间 \(\mathcal{O}(E)\)，空间 \(\mathcal{O}(E)\)。

    和 332 的对照：332 记录的是节点（因为要的是行程顺序），本题记录的是边（因为要的是数对的排列）。同一个 Hierholzer 算法，输出物不同而已。
