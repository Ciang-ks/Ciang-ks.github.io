    Trees · 解题手册¶

    树题几乎都能用一句话概括：把问题分解成"左子树的结果"和"右子树的结果"，再合并。写不出递归，通常不是因为不会写递归，而是因为没想清楚"函数应该返回什么"。

    一、从题面提出候选，再核对条件¶

    已学基础：11-二叉搜索树与平衡树、14-树上的算法。下面将讲义中的结构性质用于选择解法。

    把递归函数看成一个对子树的接口：向下传祖先限制，向上返回父节点需要的摘要，全局答案另存。遍历顺序由依赖决定。

    题目特征 需要验证的依据 迁移边界与反例
    高度、平衡、直径、最大路径和 后序获取两侧摘要；区分单边返回与双边候选 返回左右合计路径再接父节点会形成分叉
    根到节点的约束 用参数传当前路径信息 旁边分支的大值不能污染另一条路径
    BST 大小定位或验证 有序关系可用于剪枝；验证需保留祖先上下界 只比父子大小不够，普通二叉树也无此剪枝
    按层输出或取每层代表 BFS 固定本轮队列长度，或 DFS 明确深度及先后顺序 沿右孩子走不等于右视图

    为 None、叶子、单边树分别写出返回值。树的空间用高度 h 或宽度 w 描述，不能无条件将 h 当成 log n；链状树的递归可深至 n。

    二、两类递归：这是树题的分水岭¶

    类型 A 自顶向下（把状态往下传）¶

    函数参数里带着"从根走到当前节点积累的信息"，返回值是答案本身。

    def dfs(node, state_from_above):
    if not node:
        return
    # 用上层状态 + 当前节点，决定是否更新全局答案
    dfs(node.left, state_from_parent)
    dfs(node.right, state_from_parent)

    典型题：1448 Count Good Nodes（传路径最大值）、98 Validate BST（传上下界）、112 Path Sum（传剩余目标和）。

    类型 B 自底向上（子树把信息返回给父节点）¶

    def dfs(node):
    if not node:
        return 基线值
    left = dfs(node.left)
    right = dfs(node.right)
    # 用 left / right 更新全局答案
    return 这个子树的统计量

    典型题：104 深度、543 直径、110 平衡、124 最大路径和。

    判断技巧：如果答案需要"跨过当前节点把左右两边连起来"（直径、最大路径和），那一定是类型 B——返回值和答案不是同一个东西：返回值是"单边量"，答案是"双边合并量"。

    三、四种遍历与它们的分工¶

    遍历 顺序 典型用途
    前序 DFS 根 → 左 → 右 复制、序列化、自顶向下传状态
    中序 DFS 左 → 根 → 右 BST 升序、验证 BST、第 k 小
    后序 DFS 左 → 右 → 根 自底向上合并（高度、直径、路径和）
    层序 BFS 按层 层序输出、每层最值、最小深度

    层序 BFS 模板（务必背下来）¶

    from collections import deque

def level_order(root):
    if not root:
        return []
    res = []
    q = deque([root])
    while q:
        level = []
        for _ in range(len(q)):        # 关键：循环开始时锁定本层节点数
            node = q.popleft()
            level.append(node.val)
            if node.left:
                q.append(node.left)
            if node.right:
                q.append(node.right)
        res.append(level)
    return res

    for _ in range(len(q)) 是层序的核心：它在循环开始时固定了这一层的节点数，从而把"层"分离出来。

    四、BST 的三条性质与验证方法¶

    1. 中序遍历是严格升序；
    2. 任意节点的值都大于左子树的所有值、小于右子树的所有值；
    3. 查找/插入/删除是 \(\mathcal{O}(h)\)。

    验证 BST 的标准写法（带上下界）¶

    def is_valid_bst(root):
    def valid(node, lo, hi):
        if not node:
            return True
        if not (lo < node.val < hi):        # 必须严格在区间内
            return False
        # 往左走：上界收紧为 node.val；往右走：下界收紧为 node.val
        return valid(node.left, lo, node.val) and valid(node.right, node.val, hi)
    return valid(root, float("-inf"), float("inf"))

    为什么不能只比较父子？ 看 [5,1,4,null,null,3,6]：节点 4 大于左孩子 3、小于父节点 5，看起来没问题，但 3 处在 5 的右子树里却比 5 小。这个反例是面试必问的。

    BST 中序遍历（迭代版，用于找第 k 小）¶

    def kth_smallest(root, k):
    stack, cur = [], root
    while stack or cur:
        while cur:
            stack.append(cur)
            cur = cur.left          # 一路向左，压入"当前最小"的候选
        cur = stack.pop()           # 弹出的是当前最小未访问节点
        k -= 1
        if k == 0:
            return cur.val
        cur = cur.right
    return -1

    五、从读题到写码：四步流程¶

    1. 判断属于类型 A 还是类型 B：需不需要"把左右两边连起来"？需要 → B。
    2. 写清 dfs 的返回值语义（一句话），以及全局答案是否需要单独维护。
    3. 确定空节点的基线值：返回 0？-inf？None？这一步最容易错。
    4. 确认遍历顺序：后序（自底向上）/ 前序（自顶向下）/ 层序。

    六、逐题推演：从题面到思路¶

    1. Invert Binary Tree（226）¶

    题面信号："把每个节点的左右子树交换"。

    候选思路：递归不变式是"假设左右子树都已经翻转好了，我只需要交换两个孩子的指针"。

    走一遍示例：4(2(1,3), 7(6,9))

    先翻转左子树 2 → 变成 2(3,1)
再翻转右子树 7 → 变成 7(9,6)
最后交换根的两个孩子 → 4(7(9,6), 2(3,1))

    关键细节：后序写法最不容易出错（先用临时变量接住左右孩子再交换）；前序写法在交换之后递归的孩子已经是"原来的另一个"。

    2. Maximum Depth of Binary Tree（104）¶

    题面信号："最大深度"。

    候选思路：这是类型 B 的母题——\(\operatorname{dfs}(\mathrm{node})=1+\max(\operatorname{dfs}(\mathrm{left}),\operatorname{dfs}(\mathrm{right}))\)，空节点返回 0。

    关键细节：用 max（最大深度）；求最小深度时不能直接写 \(1 + \min (\mathrm{left}, \mathrm{right})\)，因为只有一个孩子时另一个是 0，会算错。

    3. Diameter of Binary Tree（543）¶

    题面信号："任意两节点间最长路径的边数"。

    候选思路：关键观察——任一条路径都有一个"最高点"，在这点向左下、右下各延伸一段。于是"经过 node 的最长路径 = 左高 + 右高"。

    难点在于分清两个量：

    • 递归返回值：以 node 为根的子树高度（单边量，因为高度只能沿一条路往上传）；
    • 全局答案：\(\max (左高 + 右高)\)（双边量，因为路径可以在这里拐弯）。

    走一遍示例：1(2(4,5), 3)

    dfs(4) = 1，dfs(5) = 1
dfs(2): 左高 1 + 右高 1 = 2 → 候选答案 2；返回 1 + max(1,1) = 2
dfs(3) = 1
dfs(1): 左高 2 + 右高 1 = 3 → 候选答案 3；返回 1 + max(2,1) = 3
最终答案 3（路径 4→2→1→3）

    关键细节：直径可能完全落在某个子树里（所以要在每个节点都更新答案，不能只在根处算）；答案是边数，若按节点数算应写 \(\mathrm{left} + \mathrm{right} + 1\)。

    4. Balanced Binary Tree（110）¶

    题面信号："判断每个节点的左右子树高度差是否不超过 1"。

    候选思路：朴素做法是"对每个节点求一次高度"，会重复计算（\(\mathcal{O}(n^{2})\)）。优化方式是"在求高度的同时判断平衡"，用 -1 当哨兵短路。

    为什么 -1 能短路？ 一旦某个子树返回 -1，父节点就直接返回 -1，不再计算另一半——这样每个节点只被访问一次。

    关键细节：所有用到高度的地方都要先检查 \(= -1\)，不能把它当普通高度参与 abs 计算；判断条件是 \(> 1\)。

    5. Same Tree（100）¶

    题面信号："两棵树结构和值是否都相同"。

    候选思路：同步递归。三种空节点情况必须写全：都空 → True；只有一个空 → False；都不空 → 比值 + 递归。

    关键细节：漏掉"只有一个空"这一支，结构不同的树会被误判为相同。这个模板是 572 和 101 的基础。

    6. Subtree of Another Tree（572）¶

    题面信号："subRoot 是否是 root 的子树"。

    候选思路：对 root 的每个节点调用一次 Same Tree。

    注意递归的两层含义不能混：

    isSubtree(root, sub) = isSameTree(root, sub)            # 当前节点就匹配
                     or isSubtree(root.left, sub)       # 或在左子树里
                     or isSubtree(root.right, sub)      # 或在右子树里

    关键细节：序列化 + 字符串匹配可以做到 \(\mathcal{O}(n+m)\)，但空节点必须参与序列化（否则 [1,2] 和 [1,2,null] 会生成相同结果）。

    7. Lowest Common Ancestor of a BST（235）¶

    题面信号："BST 中两个节点的最近公共祖先"。

    候选思路：利用 BST 的大小关系，不需要遍历整棵树：从根往下走，两个值都小于当前节点就向左；都大于就向右；否则当前节点就是分岔点，也就是答案。

    走一遍示例：root = [6,2,8,0,4,7,9,...]，p = 2，q = 8

    node=6: 2 < 6 但 8 > 6 → 分居两侧 → 返回 6

    关键细节：判断必须同时看两个节点（p.val < cur.val and q.val < cur.val），只看 p 是错的；"节点可以是自己的祖先"由 else 分支天然处理。

    追问准备："如果是普通二叉树？" → 236，用后序递归：左右各找到一个就返回当前节点。

    8. Binary Tree Level Order Traversal（102）¶

    题面信号："按层返回节点值"。

    候选思路：BFS + for _ in range(len(q)) 分层。

    另一种不用队列的写法：DFS 时把 depth 当参数传下去，res[depth].append(node.val)；前序遍历天然保证同层从左到右。这种写法空间从 \(\mathcal{O}(层宽)\) 降到 \(\mathcal{O}(树高)\)。

    关键细节：空树返回 [] 而不是 [[]]；用 deque 而不是 list（list.pop(0) 是 \(\mathcal{O}(n)\)）。

    9. Binary Tree Right Side View（199）¶

    题面信号："站在右侧能看到的节点" = 每层最右边。

    候选思路：层序取 level[-1]；或者 DFS 优先访问右子树，每个深度第一次到达的节点就是最右节点（depth == len(res)）。

    关键细节：DFS 版必须先右后左，否则拿到的是最左节点；DFS 版的空间是 \(\mathcal{O}(树高)\)，比 BFS 的 \(\mathcal{O}(层宽)\) 更省。

    10. Count Good Nodes in Binary Tree（1448）¶

    题面信号："路径上没有比它更大的值的节点"。

    候选思路：判断只需要"从根到它的路径上的最大值" → 类型 A 自顶向下，把 max_so_far 当参数。

    走一遍示例：3(1(3), 4(1,5))

    节点 传入的 max_so_far 是否好节点 传给孩子的 max
    3 -inf 是 3
    1（左） 3 否 3
    3（左左） 3 是（相等也算） 3
    4 3 是 4
    1（右左） 4 否 4
    5 4 是 5

    答案 4。

    关键细节：判断用 \(\ge\)（相等也是好节点）；初始值用 float("-inf")，这样根节点必然被计入。

    11. Validate Binary Search Tree（98）¶

    题面信号："判断是否合法 BST"。

    候选思路：带上下界的递归，或中序遍历必须严格递增。

    为什么不能只比较父子：见第四节的反例 [5,1,4,null,null,3,6]。面试官一定会拿这个例子问你。

    关键细节：比较必须严格（lo < val < hi）；边界用 ±inf；中序版的 prev 初值是 -inf。

    12. Kth Smallest Element in a BST（230）¶

    题面信号："BST 中第 k 小的元素"。

    候选思路：BST 的中序是升序 → 中序遍历到第 k 个就返回，不必遍历整棵树。

    关键细节：迭代中序（栈）可以在找到后立刻返回，时间 \(\mathcal{O}(h + k)\)；k 是 1-based；循环条件 while stack or cur 两个都不能少。

    13. Construct Binary Tree from Preorder and Inorder（105）¶

    题面信号："用前序 + 中序重建二叉树"。

    候选思路：前序的第一个元素是根；中序里根的左边是左子树、右边是右子树。两者结合就能递归切分。

    走一遍示例：\(\mathrm{pre} = [3,9,20,15,7]\)，\(in = [9,3,15,20,7]\)

    前序首元素 3 是根；在中序里找到 3 的下标 1
→ 左子树中序 [9]，长度 1；右子树中序 [15,20,7]，长度 3
→ 前序按长度切成 [9] 和 [20,15,7]
递归处理左右

    关键细节：用 值 → 中序下标 的哈希表把定位从 \(\mathcal{O}(n)\) 降到 \(\mathcal{O}(1)\)，总复杂度 \(\mathcal{O}(n)\)；递归顺序必须先左后右（因为前序指针只能单向前进）。

    追问准备："后序 + 中序？" → 106，根在后序的最后一个，构造顺序变成先右后左。

    14. Binary Tree Maximum Path Sum（124）¶

    题面信号："路径上节点值之和的最大值"（路径不一定要经过根）。

    候选思路：结构和 543 完全一样——返回值是单边量、答案是双边合并量，只多了"处理负数"。

    \[ \begin{aligned}\operatorname{gain}(u)&=v_u+\max\{0,\operatorname{gain}(u_L),\operatorname{gain}(u_R)\},\\\operatorname{through}(u)&=v_u+\max\{0,\operatorname{gain}(u_L)\}+\max\{0,\operatorname{gain}(u_R)\}.\end{aligned} \]

    max(0, ...) 的两个作用：① 截断负数子树（走那边只会更差）；② 把空节点统一成 0。

    走一遍示例：-10(9, 20(15,7))

    dfs(9) = 9
dfs(15) = 15，dfs(7) = 7
dfs(20): 20 + 15 + 7 = 42 → 候选答案 42；返回 20 + max(15,7) = 35
dfs(-10): 左 9、右 35 → 候选 9 + 35 - 10 = 34；返回 -10 + max(9,35) = 25
最终答案 42

    关键细节：best 必须初始化为 -inf（全负数数组时答案是负数，不能是 0）；返回值只能选一条腿，不能返回 \(\mathrm{left} + \mathrm{right}\)（否则父节点会重复用同一个节点）。

    15. Serialize and Deserialize Binary Tree（297）¶

    题面信号："把树编码成一个字符串，再原样还原"。

    候选思路：空节点必须显式记录，否则 [1,2] 和 [1,null,2] 会产生同一个序列。

    推荐编码：前序遍历 + # 表示空节点，例如 "1,2,#,#,3,4,#,#,5,#,#"。

    为什么序列化和反序列化都用前序？ 因为前序把根放在最前面，反序列化时"先消费到的就是根"，两者天然对齐。

    关键细节：反序列化用 iter(tokens) + next() 让游标隐式前进，比传下标干净；如果节点值可能包含分隔符，要改用长度前缀（271 的思路）。

    七、复杂度速查¶

    题目 递归类型 时间 空间
    Invert Binary Tree 后序 \(\mathcal{O}(n)\) \(\mathcal{O}(h)\)
    Maximum Depth 后序 \(\mathcal{O}(n)\) \(\mathcal{O}(h)\)
    Diameter 后序（单边返回值 + 全局答案） \(\mathcal{O}(n)\) \(\mathcal{O}(h)\)
    Balanced Binary Tree 后序 + 短路 \(\mathcal{O}(n)\) \(\mathcal{O}(h)\)
    Same Tree 同步递归 \(\mathcal{O}(n)\) \(\mathcal{O}(h)\)
    Subtree of Another Tree 嵌套递归 \(\mathcal{O}(n\cdot m)\) \(\mathcal{O}(h)\)
    LCA of a BST 自顶向下利用 BST \(\mathcal{O}(h)\) \(\mathcal{O}(1)\)
    Level Order Traversal BFS \(\mathcal{O}(n)\) \(\mathcal{O}(w)\)
    Right Side View BFS 或右优先 DFS \(\mathcal{O}(n)\) \(\mathcal{O}(w)\) / \(\mathcal{O}(h)\)
    Count Good Nodes 自顶向下 \(\mathcal{O}(n)\) \(\mathcal{O}(h)\)
    Validate BST 自顶向下（上下界） \(\mathcal{O}(n)\) \(\mathcal{O}(h)\)
    Kth Smallest in BST 中序（可提前停） \(\mathcal{O}(h+k)\) \(\mathcal{O}(h)\)
    Construct from Pre+In 分治 \(\mathcal{O}(n)\) \(\mathcal{O}(n)\)
    Maximum Path Sum 后序 \(\mathcal{O}(n)\) \(\mathcal{O}(h)\)
    Serialize/Deserialize 前序 + 空标记 \(\mathcal{O}(n)\) \(\mathcal{O}(n)\)

    （h 是树高，w 是最大层宽。）

    八、易错点速查¶

    1. 空节点的基线值选错（124 用 0 会把全负数答案算错）。
    2. 把"全局答案"和"递归返回值"混为一谈。
    3. 验证 BST 只比较父子。
    4. 层序遍历忘记用 len(q) 分层。
    5. 高度定义（节点数 vs 边数）没确认就写。
    6. 右视图 DFS 写成先左后右，结果变成左视图。
    7. 246 之类的对称题只比较同侧（镜像要交叉比较）。
    8. 递归深度：链状树是 \(\mathcal{O}(n)\)，Python 默认上限约 1000，必要时改迭代。

    九、面试话术¶

    "我用后序遍历。递归函数返回子树的高度；同时用全局变量记录答案，每到一个节点就用 left + right 更新它。这样每个节点只访问一次，复杂度 \(\mathcal{O}(n)\)。区分'返回值是单边量、答案是双边量'是这题的关键。"
