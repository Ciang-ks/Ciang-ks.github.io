    Heap / Priority Queue · 解题手册¶

    堆解决的是"在动态变化的数据里，随时拿到最值"。判断标准很简单：如果数据是"变化的"，就该用堆；如果数据是"给定的、一次性的"，排序或快速选择往往更好。

    一、从题面提出候选，再核对条件¶

    已学基础：10-选择与中位数、12-二叉堆与优先队列。下面将讲义中的结构性质用于选择解法。

    堆适合持续更新后反复取边界候选；它不保证数组整体有序，也不负责证明某个调度选择最优。

    题目特征 需要验证的依据 迁移边界与反例
    保留最大 k 项 小顶堆，堆顶是要淘汰的最小候选 保留最小 k 项则反用大顶堆
    静态求第 k 大 比较排序、固定堆、快速选择的修改与期望代价 快速选择平均线性不是最坏保证
    多个有序流取下一项 每条流只保留一项前沿，弹出后补同一流 无需收集全部历史数据
    流式中位数 两堆分别维护分界顺序和数量平衡 仅平衡大小或仅平衡数量都不够

    给堆元组的每个字段写出含义，并说明重复值与平局如何处理。堆不会自动删除任意过期项，窗口和离线查询常需在堆顶检查有效性。

    二、Python heapq 速查（最容易踩坑的地方）¶

    import heapq

heapq.heapify(arr)               # 原地建堆，O(n)（不是 O(n log n)）
heapq.heappush(heap, x)          # 插入，O(log n)
heapq.heappop(heap)              # 弹出最小值，O(log n)
heap[0]                          # 只看最小值，O(1)
heapq.heappushpop(heap, x)       # 先 push 再 pop（比两步快）
heapq.nlargest(k, it)            # 前 k 大，O(n log k)

    本文使用 heapq 的小顶堆接口；需要大顶堆时用负数兼容常见 Python 运行环境：

    heapq.heappush(heap, -x)
largest = -heapq.heappop(heap)

    三、四种典型用法¶

    用法 1 小顶堆维护"最大的 k 个"（Top-K 母题）¶

    import heapq

def top_k(nums, k):
    heap = []
    for x in nums:
        heapq.heappush(heap, x)
        if len(heap) > k:
            heapq.heappop(heap)      # 弹掉最小的，留下最大的 k 个
    return heap[0]                   # 堆顶就是第 k 大

    为什么必须是小顶堆？ 因为我们要淘汰的是"这 k+1 个里最小的那个"，而小顶堆的堆顶正好是最小值。

    用法 2 多路归并¶

    import heapq

def merge_k_sources(sources):
    heap = [(src[0], i, 0) for i, src in enumerate(sources) if src]
    heapq.heapify(heap)
    res = []
    while heap:
        val, si, idx = heapq.heappop(heap)
        res.append(val)
        if idx + 1 < len(sources[si]):
            heapq.heappush(heap, (sources[si][idx + 1], si, idx + 1))
    return res

    用法 3 双堆求中位数（流式数据的标准解法）¶

    import heapq

class MedianFinder:
    def __init__(self):
        self.small = []      # 大顶堆（存负数），较小的一半
        self.large = []      # 小顶堆，较大的一半

    def addNum(self, num: int) -> None:
        heapq.heappush(self.small, -num)
        heapq.heappush(self.large, -heapq.heappop(self.small))
        if len(self.large) > len(self.small):
            heapq.heappush(self.small, -heapq.heappop(self.large))

    def findMedian(self) -> float:
        if len(self.small) > len(self.large):
            return -self.small[0]
        return (-self.small[0] + self.large[0]) / 2

    平衡规则必须固定：约定"small 要么与 large 等长，要么比它多一个"。插入的三步顺序不能变。

    用法 4 元组当复合键（注意 Python 的坑）¶

    heapq.heappush(heap, (distance, counter, obj))   # counter 保证不会比较到 obj
counter += 1

    元组会依次比较各元素。如果前几个字段相等，就会去比较后面的对象——而 ListNode 之类没有定义 \(<\)，直接抛 TypeError。插入一个唯一递增计数器是标准解法（23、355 都会用到）。

    四、从读题到写码：四步流程¶

    1. 判断数据是动态还是静态：动态 → 堆；静态且只求第 k 大 → 快速选择。
    2. 确定堆里存什么语义："最大的 k 个"还是"最小的 k 个"？这决定了用大顶堆还是小顶堆。
    3. 确定堆元素的结构：单值？(优先级, 序号, 对象)？多路归并还要带"来源下标"。
    4. 处理不可比较的对象：加计数器。

    五、逐题推演：从题面到思路¶

    1. Kth Largest Element in a Stream（703）¶

    题面信号："数据流"+"第 k 大"。

    候选思路：动态 → 堆。关键观察：维护"第 k 大"只需要维护"当前最大的 k 个"，这 k 个里最小的那个就是答案，其余元素怎么变都不影响第 k 大。

    走一遍示例：初始 \(\mathrm{nums} = [4,5,8,2]\)，k = 3，随后依次 add(3)、add(5)、add(10)、add(9)、add(4)。

    初始时"最大的 3 个"是 {4, 5, 8}（2 在收缩时被弹掉）：

    操作 堆内元素（最大的 3 个） 返回值
    初始 {4, 5, 8} ——
    add(3) {4, 5, 8}（3 被弹掉） 4
    add(5) {5, 5, 8}（4 被弹掉） 5
    add(10) {5, 8, 10}（5 被弹掉） 5
    add(9) {8, 9, 10}（5 被弹掉） 8
    add(4) {8, 9, 10}（4 被弹掉） 8

    关键细节：超过 k 时弹出的是堆顶（最小值），不是把它 pop 出来看答案；答案是 heap[0]。

    2. Last Stone Weight（1046）¶

    题面信号："每次取最重的两块"。

    候选思路：反复取最大值 → 大顶堆（Python 里存负数）。

    走一遍示例：[2,7,4,1,8,1]

    取 8,7 → 差 1，放回 → [2,4,1,1,1]
取 4,2 → 差 2，放回 → [1,1,1,2] ...
最终剩 1

    关键细节：压回堆的值是 y - x（y 是较大的）；循环条件是 len(heap) > 1；最后可能剩 0 块（返回 0）。

    顺带记住：heapify 是 \(\mathcal{O}(n)\)，不是 \(\mathcal{O}(n \log n)\)——面试中主动说出来是加分项。

    3. K Closest Points to Origin（973）¶

    题面信号："最近的 k 个点"。

    候选思路：Top-K 的变体，但方向相反——要淘汰"最远的"，所以用大顶堆。

    两个关键优化：

    1. 不要开方：比较 \(x^{2} + y^{2}\) 即可，避免浮点误差；
    2. 元组写成 (-距离平方, x, y)，x、y 作为 tie-break，保证元组可比较。

    追问准备："k 接近 n 时？" → 改用快速选择（平均 \(\mathcal{O}(n)\)）或直接排序。

    4. Kth Largest Element in an Array（215）¶

    题面信号："静态数组的第 k 大"。

    候选思路：三种做法 —— 小顶堆（\(\mathcal{O}(n \log k)\)）、快速选择（平均 \(\mathcal{O}(n)\)）、排序（\(\mathcal{O}(n \log n)\)）。

    快速选择的关键：

    "第 k 大" = 升序排序后的第 n-k 个位置（别写成 k-1）
partition 之后只递归一边，所以期望复杂度是 n + n/2 + n/4 + … = O(n)
必须随机化 pivot，否则已排序数组会退化到 O(n²)

    关键细节："必须随机化 pivot"是这道题最常被追问的点；while True + 三路分支（等于目标直接返回）。

    5. Task Scheduler（621）¶

    题面信号："同类任务之间要间隔 n 个时间单位，求最短总时间"。

    候选思路：先想数学公式，因为它 \(\mathcal{O}(n)\) 且代码极短。

    推一把公式：设出现最多的任务出现 maxf 次，且有 maxcnt 种任务都出现了 maxf 次。先把这些"最重的"排成骨架：

    A _ _ A _ _ A          （maxf = 3，n = 2）

    骨架长度 = \((\mathrm{maxf} - 1) * (n + 1) + \mathrm{maxcnt}\)。为什么最后要加 maxcnt？ 因为如果多种任务并列最高频，它们会并排填在最后一批里。

    最后必须和 len(tasks) 取 max：如果任务种类足够多，能把所有间隔填满甚至溢出，就不需要任何 idle。

    走一遍示例：tasks = ["A","A","A","B","B","B"]，n = 2

    maxf = 3，maxcnt = 2（A 和 B 都是 3 次）
公式: (3-1)*(2+1) + 2 = 8
len(tasks) = 6
答案 = max(8, 6) = 8

    反例提醒：tasks = ["A","B","C","D"]，n = 1 时公式算出 2，但实际需要 4——不取 max 就会错。

    追问准备："要输出具体调度序列？" → 公式法做不到，必须用"堆 + 冷却队列"模拟。

    6. Design Twitter（355）¶

    题面信号："取自己和关注者最近的 10 条推文"。

    候选思路：每个用户的推文列表按时间递增，所以"合并多个用户取最近 10 条"就是多路归并（23 题的变形）。

    数据结构：tweets[user] = [(time, tweetId)]、follows[user] = set()、全局递增 time。

    关键细节：getNewsFeed 必须包含自己（用 follows[uid] | {uid} 一步搞定）；堆里要带 (userId, idx) 才能补下一条；unfollow 用 discard 而不是 remove。

    7. Find Median from Data Stream（295）¶

    题面信号："流式数据的中位数"。

    候选思路：每来一个数就排序是 \(\mathcal{O}(n \log n)\)；双堆可以做到 \(\mathcal{O}(\log n)\) 插入、\(\mathcal{O}(1)\) 查询。

    双堆的分工：

    small：大顶堆，存较小的一半（堆顶是这半的最大值）
large：小顶堆，存较大的一半（堆顶是这半的最小值）
中位数 = small 堆顶（奇数个） 或 两个堆顶平均（偶数个）

    插入的三步（顺序不能变）：先压 small → 把 small 的堆顶移到 large → 若 len(small) < len(large) 再挪回来。这三步保证了"small 的所有元素 不大于 large 的所有元素"。

    走一遍示例：依次加入 1、2、3

    add small（负数，大顶） large 中位数
    1 [1] [] 1
    2 [1] [2] 1.5
    3 [2,1] [3] 2

    追问准备："为什么不用两个数组？" → 插入后维持有序是 \(\mathcal{O}(n)\)；"带删除的双堆？" → 需要惰性删除（480）。

    六、复杂度速查¶

    题目 用法 时间 空间
    Kth Largest in a Stream 动态 Top-K \(\mathcal{O}(\log k)\) 每次 \(\mathcal{O}(k)\)
    Last Stone Weight 大顶堆模拟 \(\mathcal{O}(n \log n)\) \(\mathcal{O}(n)\)
    K Closest Points 大顶堆（淘汰最远） \(\mathcal{O}(n \log k)\) \(\mathcal{O}(k)\)
    Kth Largest in Array 堆 或 快速选择 \(\mathcal{O}(n \log k)\) / 平均 \(\mathcal{O}(n)\) \(\mathcal{O}(k)\) / \(\mathcal{O}(1)\)
    Task Scheduler 公式 / 堆 + 队列 \(\mathcal{O}(n)\) \(\mathcal{O}(1)\)
    Design Twitter 多路归并 \(\mathcal{O}(F+10 \log (F+1))\) 查询 \(\mathcal{O}(F)\) 查询临时堆，历史另计
    Find Median 双堆 \(\mathcal{O}(\log n)\) 插入 \(\mathcal{O}(n)\)

    七、易错点速查¶

    1. 把 heapq 当大顶堆用（本文使用的小顶堆接口应取负数模拟大顶堆）。
    2. heap[0] 是小值，Top-K 题里它就是答案但不要 pop 掉。
    3. 求 Top-K 时方向搞反：要"最大的 k 个"就得用小顶堆淘汰最小值。
    4. 元组里放不可比较对象没加计数器。
    5. 双堆平衡条件写错 / 插入三步顺序写反。
    6. heapify 复杂度记成 \(\mathcal{O}(n \log n)\)。
    7. 用 nlargest 却不解释复杂度：k 小时是 \(\mathcal{O}(n \log k)\)，k 接近 n 时会退化成排序。

    八、面试话术¶

    "我用一个小顶堆维护当前最大的 k 个元素。遍历时把元素压入堆，堆大小超过 k 就弹出堆顶（也就是这 k 个里最小的）。遍历结束后堆顶就是第 k 大的元素。时间 \(\mathcal{O}(n \log k)\)，空间 \(\mathcal{O}(k)\)。"
