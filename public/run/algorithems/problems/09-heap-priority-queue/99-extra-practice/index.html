    1. 692 Top K Frequent Words¶

    LeetCode 692 ｜ Medium

    题目：返回出现频率最高的 k 个单词，频率相同时按字典序升序。

    为什么放这里：347 的进阶版，考点是"堆里元组的方向必须与排序目标严格对应"。

    思路提示

    我们要的排序规则是：频率降序，频率相同时字典序升序。

    用堆时要注意：小顶堆按元素比较规则弹出最小项，所以比较规则要将“最差候选”排在前面。这里有一个非常容易错的细节——字典序不能简单取反（字符串不能取负）。

    若用大小为 k 的堆，应明确定义同频时较大单词更先被弹出的比较规则；普通 (freq,word) 元组会在同频时反而淘汰字典序较小者。

    最直接可靠的写法是：先全部排序，再取前 k 个（O(n log n)），或者用 Counter.most_common 配合自定义排序。面试中可以用堆版展示优化，但务必先把顺序规则讲清楚。

    方法辨析：堆中保留的是单词种类而非每个词的每次出现，先频次聚合，再比较排名。输入 a、aa 同频时必须 a 在前，这个例子能检验前缀比较；固定候选堆的最差优先规则与最终输出顺序恰好相反。

    from collections import Counter

class Solution:
    def topKFrequent(self, words: List[str], k: int) -> List[str]:
        freq = Counter(words)
        # 频率降序；频率相同时字典序升序
        ordered = sorted(freq.items(), key=lambda kv: (-kv[1], kv[0]))
        return [w for w, _ in ordered[:k]]

    堆版本（大小为 k，淘汰"当前最差"的候选）：

    大小为 k 的堆应让“最差候选”先弹出：频率越低越差；频率相等时，字典序越大越差。仅逐字符取负无法正确反转前缀关系，例如 a 与 aa；用显式比较规则更清楚。

    import heapq
from collections import Counter

class Candidate:
    def __init__(self, word, freq):
        self.word = word
        self.freq = freq

    def __lt__(self, other):
        if self.freq != other.freq:
            return self.freq < other.freq
        return self.word > other.word   # 同频时，大单词先淘汰

class Solution:
    def topKFrequent(self, words: List[str], k: int) -> List[str]:
        heap = []
        for word, freq in Counter(words).items():
            heapq.heappush(heap, Candidate(word, freq))
            if len(heap) > k:
                heapq.heappop(heap)
        ordered = sorted(heap, key=lambda item: (-item.freq, item.word))
        return [item.word for item in ordered]

    排序版更短；堆版只保留 k 个候选，但最终输出仍需按频率降序、字典序升序排列。比较字符串还可能扫描多个字符，不能把任意长单词比较都视为常数。

    易错点：频率相同必须按字典序；不要漏掉这个 tie-break，否则结果顺序会和标准答案不一致。

    复杂度：排序版 O(n log n)，堆版 O(n log k)（但需要额外的反向比较技巧）。

    2. 378 Kth Smallest Element in a Sorted Matrix¶

    LeetCode 378 ｜ Medium

    题目：给定每行、每列都升序的矩阵，求第 k 小的元素。

    为什么放这里：多路归并（堆）与二分答案两种思路都能做，是极佳的对照练习。

    思路提示

    思路 A 多路归并（堆）：把每行的第一个元素入堆（(值, 行, 列)），每次弹出一个最小的，并把该行的下一个元素补进堆。第 k 次弹出的就是答案。建堆 O(n)，随后取 k 项 O(k log(n+1))。

    思路 B 二分答案：对值域二分 mid，统计矩阵中 ≤ mid 的元素个数（用"从左下角出发的阶梯计数"，O(n)），根据计数与 k 的大小关系收缩区间。时间 O(n log(值域))。

    方法辨析：堆法只需要每行有序，各行首项构成全局前沿；值域阶梯计数还需列有序，才能一次跳过一段。重复值占多个名次，统计≤mid 的元素数而不是不同值数。

    import heapq

class Solution:
    def kthSmallest(self, matrix: List[List[int]], k: int) -> int:
        n = len(matrix)
        heap = [(matrix[i][0], i, 0) for i in range(n)]
        heapq.heapify(heap)

        for _ in range(k - 1):
            val, r, c = heapq.heappop(heap)
            if c + 1 < n:
                heapq.heappush(heap, (matrix[r][c + 1], r, c + 1))

        return heap[0][0]

    易错点：堆里必须同时存行和列，才能补上下一个元素；k == 1 时循环不执行，直接返回堆顶。

    复杂度：堆解法 O(k log n)，空间 O(n)。

    3. 767 Reorganize String¶

    LeetCode 767 ｜ Medium

    题目：重排字符串，使任意两个相邻字符都不相同；做不到则返回 ""。

    为什么放这里：大顶堆贪心的代表题——每次取"剩余次数最多的字符"，只要它和上一个字符不同。

    思路提示

    1. 统计每个字符的次数，全部压入大顶堆（存负数）；
    2. 每轮弹出次数最多的字符 c： - 如果 c 和上一个放下的字符相同，就再弹一个（次多的），把 c 留到下一轮； - 没有别的字符可选 → 无解，返回 ""；
    3. 放好之后把用掉的字符次数减 1，如果还有剩余就压回堆。

    判断无解的条件：某个字符出现次数 > (n + 1) // 2。

    方法辨析：每轮排除刚使用的字符，暂存它的剩余次数，下一轮再放回候选堆，防止连续相同。出现次数最多的字符需要足够其他字符分隔，所以 maxfreq≤ceil(n/2) 是可行性边界，不是要求所有字符次数相等。

    import heapq
from collections import Counter

class Solution:
    def reorganizeString(self, s: str) -> str:
        count = Counter(s)
        n = len(s)
        if max(count.values()) > (n + 1) // 2:      # 无解
            return ""

        heap = [(-cnt, ch) for ch, cnt in count.items()]
        heapq.heapify(heap)

        res = []
        prev = None                                  # (剩余次数, 字符)，暂存上一轮用过的
        while heap:
            neg_cnt, ch = heapq.heappop(heap)
            res.append(ch)
            cnt = -neg_cnt - 1
            if prev:
                heapq.heappush(heap, prev)           # 把上一轮的字符放回（此时它已不是"上一个字符"）
            prev = (-cnt, ch) if cnt > 0 else None

        return ''.join(res)

    易错点："暂存上一轮字符、本轮再放回"是本题的核心技巧；无解的判断 > (n+1)//2 不能漏。

    复杂度：时间 O(n log 26) = O(n)，空间 O(26)。

    4. 264 Ugly Number II¶

    LeetCode 264 ｜ Medium

    题目：丑数是只含质因子 2、3、5 的正整数。求第 n 个丑数。

    为什么放这里：多路归并 + 去重的典范——把三路"乘以 2 / 3 / 5"的序列归并起来。

    思路提示

    维护三个指针 i2, i3, i5，分别表示"下一个要乘以 2/3/5 的丑数下标"：

    next = min(dp[i2] * 2, dp[i3] * 3, dp[i5] * 5)

    取到最小值后，把所有等于该值的指针都前移一步——这一步是去重的关键（比如 6 = 2×3 = 3×2 会被两条路同时产生）。

    方法辨析：三个指针分别合并序列 2×ugly、3×ugly、5×ugly；它们各自有序。相同最小值可能由多路同时产生，必须同时推进全部命中路，而不是 if/elif 只推进一个，否则会输出重复丑数。

    class Solution:
    def nthUglyNumber(self, n: int) -> int:
        dp = [1] * n
        i2 = i3 = i5 = 0
        for i in range(1, n):
            nxt = min(dp[i2] * 2, dp[i3] * 3, dp[i5] * 5)
            dp[i] = nxt
            if nxt == dp[i2] * 2:
                i2 += 1
            if nxt == dp[i3] * 3:
                i3 += 1
            if nxt == dp[i5] * 5:
                i5 += 1
        return dp[n - 1]

    易错点：三个 if 必须并列（不能写成 elif），否则重复值不会被一起跳过；dp[0] = 1 是基础。

    复杂度：时间 O(n)，空间 O(n)。

    5. 1834 Single-Threaded CPU¶

    LeetCode 1834 ｜ Medium

    题目：单核 CPU 依次处理任务：每个任务有"到达时间"和"处理时长"。CPU 空闲时选到达时间最早的任务；有多个可选的，选处理时间最短的（再相同则选下标最小的）。返回任务的执行顺序。

    为什么放这里：堆 + 时间推进的标准模拟。它把"按时间推进"和"用堆选最优"这两个动作组合在一起。

    思路提示

    1. 把任务按到达时间排序，用一个指针表示"哪些任务已经到达"；
    2. 维护一个小顶堆，键是 (处理时长, 下标)；
    3. 每轮： - 如果堆为空（CPU 空闲），把时间直接跳到下一个任务的到达时间（不要一秒一秒地走！）； - 把所有已到达的任务压入堆； - 弹出堆顶执行，累加时间，记录下标。

    方法辨析：排序指针决定哪些任务已经到达，堆只在这些可执行任务中按时长和原下标选取。CPU 空闲时跳到下一到达时刻与逐秒等待等价；执行过程中不抢占，所以新任务不能中途改变已经选定的任务。

    import heapq

class Solution:
    def getOrder(self, tasks: List[List[int]]) -> List[int]:
        n = len(tasks)
        order = sorted(range(n), key=lambda i: tasks[i][0])   # 按到达时间排序
        heap = []
        res = []
        time = 0
        i = 0

        while len(res) < n:
            if not heap and i < n and tasks[order[i]][0] > time:
                time = tasks[order[i]][0]        # CPU 空闲，时间直接跳到下一个到达时刻
            while i < n and tasks[order[i]][0] <= time:
                idx = order[i]
                heapq.heappush(heap, (tasks[idx][1], idx))    # (处理时长, 下标)
                i += 1
            dur, idx = heapq.heappop(heap)
            time += dur
            res.append(idx)

        return res

    易错点：CPU 空闲时必须跳时间，不能逐秒推进（否则会超时）；堆的键是 (处理时长, 下标)，正好符合题目的 tie-break 规则。

    复杂度：时间 O(n log n)，空间 O(n)。

    6. 502 IPO¶

    LeetCode 502 ｜ Hard

    题目：初始资本 w，最多做 k 个项目。每个项目有"所需资本"和"利润"，做完后利润加到资本里。求最终能获得的最大资本。

    为什么放这里：排序 + 堆的贪心组合——"先按门槛排序，再用堆选当前能做的最赚钱项目"。

    思路提示

    贪心策略：每次都在"当前资本够得着的项目"里选利润最大的。

    1. 把项目按所需资本升序排序；
    2. 用一个指针维护"已经够得着的项目"，把它们全部压入大顶堆（存负数，按利润排序）；
    3. 重复 k 次：如果堆非空，弹出利润最大的项目，资本增加；如果堆空，说明没有能做的项目了，提前结束。

    为什么这个贪心是对的：资本只增不减，所以"够得着"的集合是单调扩大的；在当前可选项里选利润最大的，一定是局部最优，且不会影响未来能否够到更多项目（因为资本增加了只会让集合变大）。

    方法辨析：利润非负使资本不会减少；同一轮选更多利润，执行后可负担的后续项目集合只会更多，不会更少。项目消耗的是一次选择机会，capital 是启动门槛而非直接扣除费用；若需支付本金不返还，当前更新与贪心论证都要重写。

    import heapq

class Solution:
    def findMaximizedCapital(self, k: int, w: int, profits: List[int], capital: List[int]) -> int:
        n = len(profits)
        projects = sorted(zip(capital, profits))     # 按所需资本升序
        heap = []                                    # 大顶堆（利润的负数）
        i = 0

        for _ in range(k):
            # 把所有"现在够得着"的项目放进堆
            while i < n and projects[i][0] <= w:
                heapq.heappush(heap, -projects[i][1])
                i += 1
            if not heap:
                break                                # 没有可做的项目了
            w += -heapq.heappop(heap)                # 做利润最大的那个

        return w

    易错点：项目按资本排序而不是利润；堆按利润排序（取负数）；while 循环把"新够得着"的项目全部加进来，不能只加一个。

    复杂度：时间 O(n log n)，空间 O(n)。
