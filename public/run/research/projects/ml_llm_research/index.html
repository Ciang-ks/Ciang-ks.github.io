    项目 B：市场特征与文本的增量研究¶

    这个项目从一张月度资产表开始：每行是一只教学股票在一个决策日的市场特征、此前发布的短公告，以及未来一个月的收益标签。我们先预测未来收益，再把预测排序转成多空组合，最后回答：在相同样本、时间边界、组合规则与成本下，加入文本是否比只用市场特征更好？

    默认是 12 只教学股票、132 个月的确定性合成数据。公告只有三种模板，生成器还让市场状态和文本状态共同影响未来收益。因此，这个项目能教会你识别增量、检查信息时点和解释负结果，却不能证明现实公告或某个语言模型能赚钱。你可以在 src/data.py 看见整个生成机制，随后仍应像处理未知真实数据一样约束特征与验证。

    先沿一行数据走完整条链¶

    假设某月末，A、B、C 三只资产的预测分别是 0.02、0、-0.01，下一月收益标签分别是 3%、1%、-2%。组合做多预测最高的 A、做空最低的 C。若多头权重 +1、空头 -1，毛收益为 \(1\times3\%+(-1)\times(-2\%)=5\%\)。这里净敞口为 0，总绝对敞口为 2，意味着相对于账户资金有两倍名义头寸；5% 不能直接和满仓单一多头的收益比较风险。

    从空仓进入这组组合要交易 2 单位，单边每单位 10 基点就扣 \(2\times10\times10^{-4}=0.2\%\)，当期净收益为 4.8%。下一月若原多头变成空头，仅这只资产就交易 2 单位。这个例子把预测、排序、权重、换手和成本分开，后面的每个模型都走同一条链。

    源码 top_bottom_returns 在每个日期取预测最高和最低的三分之一资产，各自等权，总多头 +1、总空头 -1；换手使用相邻月目标权重之差，不模拟月内价格引起的权重漂移。它是一个透明的固定名义权重近似，不含借券、融资、部分成交和退市清算。project_lab.ipynb 会选一个实际生成的日期，逐资产重建这张小账本。

    数据与标签：哪些列可以进入模型¶

    字段 含义与用途
    decision_date、asset 决策日期与资产标识，共同确定一行样本
    momentum、volatility、volume_change 合成的动量、波动状态与成交量变化代理；不是从真实价格重新计算的金融量
    beta、market_return 合成的风险暴露与市场状态代理
    published_at、text 该决策日前发布的模板公告及发布时间
    future_excess_return 生成器给出的未来收益响应，用于训练与评价，决策时不可见
    synthetic_text_signal 生成机制中的潜在文本状态，只供理解生成器，禁止作为特征
    date_index 生成器的日期计数，不是经济特征

    future_excess_return 在这里是一个已设定的残余收益代理，源码没有强制每月横截面均值为零。若在真实数据中定义“减去同日市场或资产均值后的未来收益”，应单独建立标签构造与可用时间，不能仅凭列名推断已经做过该变换。对净敞口为零的组合，同日共同减去一个基准收益不会改变多空差；对单边或非零净敞口组合则会改变含义。

    默认所有文本都在决策前两天发布，所以 published_at < decision_date 成立。真实系统还需加入接收、解析完成和修订版本时间，且月末可能不是交易日；本项目的日期只是月度教学时钟。适配真实数据时，应先定义最近可交易时点、标签结束时间和实体标识，再讨论模型。

    模型为何按这个顺序增加¶

    mean 对所有资产输出训练标签均值，用来建立均方误差的最低比较。它不产生截面排序信息：给一组完全相同的分数强行排序，得到的多空收益只是同分处理的产物。阅读默认结果时，不应把 mean 的多空组合解释为模型能力；实验 Notebook 还会给出零仓位的现金比较。

    market_ridge 使用五个市场特征。岭回归（ridge regression）用平方损失加系数平方惩罚，让相互相关、噪声较大的变量不过度放大。特征减去训练均值再除以训练标准差，截距不受惩罚。源码使用小型 NumPy 实现，因此可以逐项查看矩阵，不依赖复杂训练框架。

    market_lexical_ridge 加入词典情绪、 uncertainty 计数和文本长度。词典模型并不理解否定、上下文或事件含义，例如 “lower uncertainty” 含有 uncertainty，但未必是风险恶化。这种容易解释也容易发现错误的基线，能帮助判断语义模型是否提供了额外信息。

    market_semantic_ridge 再加入可选的本地 FinBERT 分数。语义分数是文本分类输出的变换，不能解释为股价上涨概率。所有模型使用相同标签、样本、时间与组合，否则表格中的差值可能来自覆盖率，而非特征增量。

    环境与运行¶

    从仓库根目录执行：

    uv venv --python 3.13 research/.venv
uv pip install --python research/.venv/bin/python -r research/requirements-notebooks.txt -r research/projects/ml_llm_research/requirements.txt
cd research/projects/ml_llm_research
../../.venv/bin/python -m src.run --output-dir /tmp/ml-baseline
../../.venv/bin/python tests/run_tests.py
../../.venv/bin/python -m pytest -q

    已有环境可以跳过创建。交互入口是 project_lab.ipynb，选择装有这些依赖的 Python kernel；Notebook 默认将运行结果写到临时目录，正文与源码不保存执行输出。

    panel.csv 保存样本和特征，predictions.csv 保存 validation/test 两个窗口的模型预测，metrics.json 与 validation_metrics.json 分别给出测试与验证摘要，ablation.csv 汇总测试模型比较。run_manifest.json 保存配置、切分边界和产物摘要，便于把报告里的数字追溯到一次具体运行。

    src/run.py 的固定基线按决策日期做 60%/20%/20% 切分，只在训练段拟合。它没有单独建模未来标签的成熟时间；若把月末标签解释成真实未来月收益，最后一个训练月的标签会跨入验证期。Notebook 会明确计算标签结束日，剔除当时尚未成熟的训练标签，再重建严格的对照。真实扩展应把这一步纳入数据与训练接口，而不能把“按日期切开”当成已经排除所有泄漏。

    六个研究阶段：每次增加一条可以判断的证据¶

    阶段 0：把任务合同写到一行样本上¶

    [STUDENT ACTION] 选一个月末和三只资产，写出当时能看见的字段、未来标签区间、最早成交时点、基准与主指标。用开头的三资产例子手算多空毛收益、初次建仓成本和净敞口，再决定研究目标是预测误差、截面排序还是净收益。

    [AGENT ACTION] 解释 data.py 的每一列，检查潜在状态和未来标签是否误入特征，帮助画出发布时间、决策、标签结束的时间线。完成产物是一页任务合同和一份手算账本。

    阶段 1：先让市场基线成立¶

    [STUDENT ACTION] 运行固定配置，比较 mean 与 market_ridge 的预测误差，再查看 rank IC。信息系数（information coefficient，IC）在这里是每个日期预测排名与标签排名的相关，再跨日期平均；它衡量排序，不直接等于账户收益。将日期边界改为标签成熟边界后重做相同比较，解释样本数变化。

    [AGENT ACTION] 帮助逐项复算 train-only 标准化与岭回归，检查训练和评价是否共享未来信息。若结果很弱，先检查标签、样本与尺度，再讨论非线性。完成产物是带样本数和边界日期的市场基线表。

    阶段 2：让文本增量可以被反驳¶

    [STUDENT ACTION] 对同一批公告人工标注情绪和依据，至少检查每一种模板。比较 market 与 market+lexical 时保持共同样本。分别删除情绪、uncertainty 和长度字段，观察增量由哪一列带来，这叫消融实验（ablation）。

    [AGENT ACTION] 展示词典如何把一条公告转换成数值，帮助定位否定、重复和未知词错误。不能用“文本看起来合理”代替验证期的模型比较。完成产物是人工标签、词典输出和共同样本增量表。

    阶段 3：再决定是否运行语义模型¶

    [STUDENT ACTION] 先写下语义模型应修复的具体词典错误，例如能否区分风险上升与风险下降。再准备本地模型，记录模型版本、tokenizer、截断规则、设备和失败样本，用相同标签与交易规则比较结果。

    [AGENT ACTION] 检查模型是否已缓存、输出标签顺序是否正确、默认路径是否仍可离线运行。缺少模型时应显式失败，不伪造分数。完成产物是一份模型卡、人工误差对照和模型消融结果；没有增量也是可交付结论。

    阶段 4：从预测表走回交易账本¶

    [STUDENT ACTION] 选一个测试月，用真实预测重建多空权重，求和检查净敞口与总绝对敞口。对 0、10、25、50 基点成本使用同一组预测，比较净结果。再查看各月 IC、失败月份和覆盖率，防止平均值掩盖集中风险。

    [AGENT ACTION] 帮助检查换手的初始建仓、方向翻转和退出资产，区分目标权重近似与真实漂移后交易。成本提高后的逐月净收益应不升，但不能把某个 Sharpe 的变化也当成同样的单调不变量。完成产物是一个月的逐资产账本和成本压力表。

    阶段 5：用结果决定下一步¶

    [STUDENT ACTION] 在 reports/memo_template.md 中写明文本增量是否存在、在哪些月份与成本下成立，以及哪项新证据会推翻结论。真实扩展只先设计 SEC 或新闻适配器，保存文档指纹、实体、发布时间和版本；不要直接换掉合成基线。

    [AGENT ACTION] 检查报告数字能否从预测与指标重建，指出尚未实现的真实成交、标签成熟、滚动训练和重复文档处理。完成产物是一份别人能复算的研究判断，以及一项预先定义的下一步实验。

    手工练习与研究判断¶

    若市场模型 IC 为 0.04，文本模型 IC 为 0.06，但平均换手从 0.5 变成 1.2，单边成本是 20 基点，能否断言文本有交易增量？若文本模型只覆盖一半资产，又该怎样比较？

    参考答案

    不能。增加的平均成本为 \((1.2-0.5)\times20\times10^{-4}=0.14\%\) 每期；还要看毛收益改善是否超过它，以及风险、分组和不确定性。IC 的增量不直接等于收益增量。覆盖率不同时，先在共同日期与资产上比较两个模型，再单独报告扩大覆盖带来的变化；否则把样本选择和信息增量混在一起。

    若所有训练文本和测试文本只有三个相同模板，随机拆分文档会测到什么？

    参考答案

    主要测到对重复模板及其生成机制的复用能力，不能据此推断对未来新事件、新公司或新措辞的泛化。应按时间评价，额外按文档或事件分组，检查重复与覆盖。这个合成项目有意简化语言，真实语义能力需要独立、人工标注且有时间版本的数据检验。

    可选本地语义实验¶

    默认运行不加载或下载模型。需要语义层时，先安装 CPU PyTorch 并准备许可允许的本地模型缓存，再执行：

    uv pip install --python ../../.venv/bin/python torch --index-url https://download.pytorch.org/whl/cpu
HF_HOME=../../.hf_cache ../../.venv/bin/python -m src.run --semantic --output-dir /tmp/ml-semantic

    模型首次获取可能需要网络；缓存、权重和个人数据不进入仓库。结果只能相对于本次固定数据和评价规则解释。若要继续提高，优先完成真实数据时点与标签成熟接口、滚动验证和成本模型，再考虑 TF-IDF、embedding 或更复杂的预测器。
